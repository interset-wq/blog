
# WebSocket 与实时通信

## WebSocket 是什么

**WebSocket** 是一种在客户端与服务器之间建立**持久、全双工（双向）**连接的协议，实现实时通信。

### HTTP 对实时场景的问题

HTTP 需要客户端反复**轮询**服务器以获取新数据，对聊天应用、实时计分板、多人在线游戏来说缓慢且低效。

### WebSocket 握手

每个 WebSocket 连接都以一个 HTTP 请求开始：

1. 客户端请求**升级**。
2. 服务器响应 `101 Switching Protocols`。
3. 之后连接保持打开，直到任一方发送关闭信号。

### 适用场景

聊天应用、在线多玩家游戏、体育实时看板、股票行情、协作工具。

## `ws` 库

Node.js 没有内置 WebSocket 服务器，`ws` 库是常见的实现方式。

### 基础服务器

```js
const WebSocket = require("ws");
const server = new WebSocket.Server({ port: 3000 });

server.on("connection", (socket) => {
  console.log("Client connected");

  socket.on("message", (message) => {
    console.log(message.toString());
  });

  socket.on("close", () => {
    console.log("Disconnected");
  });

  socket.on("error", (error) => {
    console.error(error);
  });
});
```

### 关键 API

| API | 作用 |
| --- | --- |
| `socket.send(msg)` | 向指定客户端发送消息 |
| `readyState` | 每个连接上的属性，`WebSocket.OPEN` 表示连接活跃 |

### 向所有客户端广播

```js
server.on("connection", (socket) => {
  socket.on("message", (message) => {
    server.clients.forEach((client) => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(message.toString());
      }
    });
  });
});
```

## Pub/Sub 架构（发布/订阅）

**Pub/Sub**：一种消息模式，**发布者**向**主题（topic）**发送消息，**订阅者**从已订阅的主题接收消息。发布者与订阅者**不直接通信**。

### 相对直接通信的优势

- **解耦组件**：发布者无需知道订阅者是谁。

### Pub/Sub 与 WebSockets 的关系

- WebSockets 是**通信通道**（公路）。
- Pub/Sub 是决定谁接收哪些消息的**消息模式**（交通系统）。
