
pwsh 内置的命令是有限的。当需要更多功能时，你可以像给操作系统安装管理工具一样，给 pwsh 安装**扩展**。pwsh 存在两种类型的扩展：**模块（Module）** 和**管理单元（PSSnapin）**。

## 一、背景：MMC 管理控制台【仅 Windows 环境】

在 Windows 中，微软管理控制台（Microsoft Management Console，简称 **MMC**）是一个专门用于管理的控制台，它为 Windows 管理员提供统一的、规范的管理接口和操作平台。

MMC 本身并不执行具体的管理操作，而是作为一个**框架**，允许用户加载不同的**管理单元（snap-ins）**来进行系统和网络管理。这些管理单元是符合 MMC 编程规范的工具，例如：

- 证书管理 `certmgr.msc`
- 索引服务 `ciadv.msc`
- 可移动设备管理 `ntmsmgr.msc`
- 性能 `perfmon.msc`
- 本地安全策略 `secpol.msc`
- 服务 `services.msc`

打开方式：按 `Win + R` 输入 `mmc` 回车，或在命令行中用 `mmc path\filename.msc` 打开特定控制台文件。

> [!NOTE]
> MMC 是 Windows 平台的概念。pwsh 借鉴了这种「扩展」思路，但它本身是跨平台的；其中的「管理单元」扩展方式属于 Windows PowerShell 的历史特性（见下节）。

## 二、扩展方式一：管理单元（PSSnapin）【仅 Windows PowerShell】

### 1. 什么是 PSSnapin

管理单元在 Windows PowerShell 中的名字是 **PSSnapin**，用于区别于来自管理单元的图形化 MMC。PSSnapin 在 PowerShell v1 时期就已存在。

> [!WARNING]
> PSSnapin 是 **Windows PowerShell（5.1 及更早）** 的扩展机制，pwsh 7+ **不支持** PSSnapin。本节仅供阅读了解历史背景，在 pwsh 中请改用模块方式扩展。

一个 PSSnapin 通常包含一个或多个 DLL 文件，以及配置 XML 文件和帮助文档。PSSnapin 必须先**安装并注册**，Windows PowerShell 才能识别它的存在。

> PSSnapin 的概念正逐步被微软移除，以后会越来越少出现。微软内部的重点是提供**扩展模块**。

### 2. 查看可用的管理单元

``` powershell
# 查看已注册、但尚未加载的管理单元
Windows PowerShell> Get-PSSnapin -Registered
```

输出会列出本机已注册的可用管理单元（例如 SQL Server 相关的两个），但这些单元**尚未加载**。

```powershell
# 查看当前已加载的管理单元（包含 Windows PowerShell 核心）
PS C:\Users\d111k> Get-PSSnapin


Name        : Microsoft.PowerShell.Core
PSVersion   : 5.1.26100.9444
Description : 此 Windows PowerShell 管理单元包含用于管理 Windows PowerShell 组件的 cmdlet。
```

### 3. 加载管理单元 Add-PSSnapin

通过 `Add-PSSnapin` 并指定管理单元名称来加载：

``` powershell
Windows PowerShell> add-pssnapin sqlservercmdletsnapin100
Windows PowerShell> Get-PSSnapin
```

加载后，该管理单元的命令就可以使用了。

### 4. PSSnapin 能带来什么

PSSnapin 可以增加 cmdlet 命令、提供 PSDrive，或两者都增加。

``` powershell
# 用 Get-Command（别名 gcm）查看该管理单元新增了哪些 cmdlet
Windows PowerShell> gcm -PSSnapin sqlservercmdletsnapin100
```

再看一个既增加 cmdlet 又增加 PSDrive 的例子——加载 SQL Server Provider：

``` powershell
Windows PowerShell> Add-PSSnapin SqlServerProviderSnapin100
Windows PowerShell> Get-PSProvider
```

输出中会出现 `SqlServer` 提供程序，说明 SQL Server 的 PSDrive（`SQLSERVER`）已添加到 shell 中。

## 三、扩展方式二：模块（Module）

### 1. 什么是模块

模块是 pwsh 提供的**主要**扩展方式。它被设计得更加独立，因此更容易分发，但工作原理与 PSSnapin 类似。

> 关键区别：模块**不需要复杂的注册**。pwsh 会自动在一个特定目录下查找模块。

### 2. 模块的存放位置：PSModulePath

`PSModulePath` 这个环境变量定义了 pwsh 期望存放模块的路径：

``` pwsh
PS C:\Users\d111k> Get-Content Env:\PSModulePath
C:\Users\d111k\Documents\PowerShell\Modules;C:\Program Files\PowerShell\Modules;c:\program files\powershell\7\Modules;C:\Program Files\WindowsPowerShell\Modules;C:\Windows\system32\WindowsPowerShell\v1.0\Modules;C:\Program Files (x86)\Microsoft SQL Server\120\Tools\PowerShell\Modules\
```

> [!IMPORTANT]
> PSModulePath 不能在 pwsh 会话里直接修改，它是操作系统环境变量的一部分。可以在系统设置或配置文件中修改。如果你有位于其他位置的模块，应该把模块所在路径加入到 PSModulePath 中。

### 3. 模块的自动发现机制

通过 PSModulePath，pwsh 可以**自动发现**计算机上的所有模块，看起来就像所有模块都已加载。运行任意命令时，pwsh 会自动加载该命令相关的模块；`Update-Help` 也会用 PSModulePath 发现已有模块并更新帮助文档。

即使在模块没有显式加载到内存的情况下，pwsh 依然能自动发现模块，从而完成命令自动补全、显示帮助和运行命令。所以保持 PSModulePath 完整和最新很有必要。

### 4. 手动加载 Import-Module

如果一个模块不在 PSModulePath 引用的任何目录下，应该用 `Import-Module` 并指定模块的完整路径，例如 `C:\MyPrograms\Something\MyModule`。

> 如果在开始菜单中有某个产品 Shell 的快捷方式（如 SharePoint Server），打开快捷方式的属性，在「目标」里会包含使用 `Import-Module` 所需的模块名和路径。

模块同样可以添加 PSDrive 提供程序——运行 `Get-PSProvider` 可以确认有哪些新的提供程序。

## 四、命令冲突与移除扩展

### 1. 命名前缀防止冲突

大多数扩展都会在命令名的名词部分加一个短前缀，如 `Get-ADUser`、`Invoke-SqlCmd`。这些前缀看起来多余，但能防止命令名称冲突。

例如，假设加载的两个模块都包含 `Get-User` 这个命令，两个同名命令被同时加载。你运行 `Get-User` 时，pwsh 执行**最后一个加载模块**的命令，另一个同名命令无法再被访问。

要明确指定运行哪个，需要使用「模块名\命令名」的完整写法：

```
MyCoolPowerShellSnapin\Get-User
```

这种方式输入量大，所以微软建议添加特定产品前缀（如 AD、SQL），既能防止冲突，又让命令更容易识别和使用。

### 2. 移除扩展

如果你已对冲突不胜其烦，可以随时卸载扩展：

- `Remove-Module`：卸载模块（跨平台）
- `Remove-PSSnapin`：卸载管理单元（仅 Windows PowerShell）

## 五、实战：玩转一个新模块

目标：清除本机上的 DNS 名称解析缓存。

> [!NOTE]
> 本实战使用 Windows 的 DnsClient 模块，仅在 Windows 环境有效。核心思路（先用帮助系统搜索、再导入模块列命令、最后执行）对任意平台都适用。

### 1. 先在帮助系统中寻找线索

``` pwsh
pwsh> Get-Help *dns*
```

输出列出本机所有与 DNS 相关的命令，但没有直接看到「清空 DNS 缓存」的命令。

### 2. 手动加载模块并列出所有命令

``` pwsh
PS C:\Users\d111k> Import-Module -name DnsClient
PS C:\Users\d111k> Get-Command -Module DnsClient

CommandType     Name                                               Version    Source
-----------     ----                                               -------    ------
Function        Add-DnsClientDohServerAddress                      1.0.0.0    DnsClient
Function        Add-DnsClientNrptRule                              1.0.0.0    DnsClient
Function        Clear-DnsClientCache                               1.0.0.0    DnsClient
...
```

在 DnsClient 模块的命令列表中，可以找到 `Clear-DnsClientCache`——它就是清除 DNS 缓存的命令。

### 3. 执行命令

``` pwsh
pwsh> Clear-DnsClientCache

# 加 -Verbose 查看执行详情
PS C:\Users\d111k> Clear-DnsClientCache -Verbose
详细信息: The specified name resolution records cached on this machine will be removed.
Subsequent name resolutions may return up-to-date information.
```

> [!NOTE]
> 所有命令都有 `-Verbose` 开关参数，但并不是所有命令都实现了它。在这个例子中，我们得到一个说明发生了什么的详细信息，从而确认命令成功执行。

## 六、从 Internet 获取模块：PowerShellGet

微软引入了一个名为 **PowerShellGet** 的模块，使得从在线仓库搜索、下载、安装、升级模块变得容易。PowerShellGet 很像 Linux 管理员喜爱的包管理器（RPM、YUM、apt-get 等）。微软还维护一个在线源，称为 [PowerShell Gallery](http://powershellgallery.com)。

常用命令：

- `Register-PSRepository`：添加一个源（repository）的 URL。PowerShell Gallery 通常是默认设置，但也可以添加自用的 gallery，并用该命令指向它。
- `Find-Module`：在源中查找模块，可在名称、标签等列中使用通配符缩小搜索结果。
- `Install-Module`：下载并安装模块。
- `Update-Module`：确保本地模块副本是最新的，否则下载最新版本并安装。

## 七、核心总结

1. pwsh 有两种扩展方式：**模块（Module）**和**管理单元（PSSnapin）**。
2. **管理单元（PSSnapin）**是 Windows PowerShell 的历史机制（需注册再 `Add-PSSnapin` 加载），pwsh 7+ 不支持，正逐步被模块取代。
3. 模块通过 `PSModulePath` 环境变量被自动发现，无需复杂注册；外部模块用 `Import-Module` 手动加载。
4. 扩展会带来命令冲突，用「模块前缀 + 名词」命名规则规避；用 `Remove-Module`（或 Windows PowerShell 的 `Remove-PSSnapin`）卸载。
5. 用 PowerShellGet（`Find-Module`、`Install-Module`、`Update-Module`）从在线仓库获取模块。
