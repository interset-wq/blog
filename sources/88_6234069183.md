
通用视图的精髓在于**隐式约定**：你没写 `template_name`，Django 自己拼一个；你没写 context，Django 自己塞一组变量。本篇把这两个"魔法"完全拆开，并讲透 Mixin、分页、装饰器等进阶能力。

## 魔法之一：template_name——Django 怎么决定用哪个模板

所有通用视图最终都要渲染一个 HTML 模板，这一步由 `TemplateResponseMixin.render_to_response()` 完成，而模板路径按下面的优先级查找：

```
template_name（显式指定的类属性）        ← 最高优先级
  └─ template_name_field（从对象上取的字段）
       └─ 默认拼装：<app>/<model>_<suffix>.html
```

### 默认模板名是"拼"出来的

没有显式写 `template_name` 时，Django 从 **模型** 推断模板路径：

```python
template_name = f"{self.model._meta.app_label}/{self.model._meta.model_name}_{self.template_name_suffix}.html"
```

其中三个来源分别是：

| 片段 | 来自 | 举例（Topic） |
|---|---|---|
| `<app>` | `model._meta.app_label`（模型所在应用小写名） | `learning_logs` |
| `<model>` | `model._meta.model_name`（模型类名全小写） | `topic` |
| `<suffix>` | `template_name_suffix`（类属性，各视图默认值不同） | 见下表 |

### template_name_suffix 的默认值（各视图不同）

| 视图 | 默认 `template_name_suffix` | 默认模板 |
|---|---|---|
| `ListView` | `_list` | `<app>/<model>_list.html` |
| `DetailView` | `_detail` | `<app>/<model>_detail.html` |
| `CreateView` | `_form` | `<app>/<model>_form.html` |
| `UpdateView` | `_form` | `<app>/<model>_form.html` |
| `DeleteView` | `_confirm_delete` | `<app>/<model>_confirm_delete.html` |
| `FormView` | `_form`（无 model，须显式 `template_name`） | —— |
| `TemplateView` | 无默认（必须显式） | —— |

所以，Learning Log 里的 `TopicListView`（model=Topic，app=learning_logs）不写 `template_name` 时，Django 会自动去渲染 `learning_logs/topic_list.html`。

### 覆盖 template_name

显式指定 `template_name` 会覆盖默认拼装结果：

```python
from django.contrib.auth.mixins import LoginRequiredMixin
from django.views import generic


class MyTopicsListView(LoginRequiredMixin, generic.ListView):
    """List topics owned by the current user."""
    model = Topic
    template_name = 'learning_logs/my_topics.html'   # 显式覆盖默认 topic_list.html
    paginate_by = 10
```

也可以只改后缀、保留默认路径：

```python
class TopicListView(generic.ListView):
    model = Topic
    template_name_suffix = '_all'   # 默认模板变为 learning_logs/topic_all.html
```

模板引擎最终按 `TEMPLATES` 的 `DIRS` 与 `APP_DIRS` 找这个路径（详见模板篇 DTL）。

## 魔法之二：context——传进模板的变量从哪来

通用视图渲染模板时传入的上下文，来自 `get_context_data(**kwargs)` 的返回值。它的内容由**三部分叠加**构成：

1. **URL 捕获的 kwargs**（自动注入）
2. **视图自动生成的默认键**（每个视图类型不同）
3. **`get_context_data` 里你自己追加的键**

### URL 捕获的参数自动进入 context

URL 里用转换器捕获的参数会直接出现在模板里。例如 `path('topics/<int:pk>/', ...)` 捕获的 `pk` 会作为 `{{ pk }}` 可用。

### 默认键与命名规则

每个通用视图会往 context 里塞一组默认键，其中模型相关键的名称由 `model._meta.model_name`（全小写模型名）决定：

| 视图 | 默认注入的 context 键 | 模板里怎么用 |
|---|---|---|
| `ListView` | `object_list`、`<model>_list` | `{% for topic in topic_list %}`（`topic_list` 等价 `object_list`） |
| `DetailView` | `object`、`<model>` | `{{ topic }}`（等价 `{{ object }}`） |
| `FormView` | `form` | `{{ form.as_p }}` |
| `CreateView` | `form`、`object`、`<model>` | `{{ form }}`、`{{ topic }}` |
| `UpdateView` | `form`、`object`、`<model>` | `{{ form }}`、`{{ topic }}` |
| `DeleteView` | `object`、`<model>` | `{{ topic }}` |

举例，Learning Log 的 `TopicListView` 渲染模板时，默认注入 `topic_list`（＝`object_list`）两个等价的键；`TopicDetailView` 默认注入 `topic`（＝`object`）。

`MultipleObjectMixin` 里的默认命名逻辑是：`context_object_name` 未指定时，取 `queryset` 或 `model` 的模型名加 `_list`；`SingleObjectMixin` 同理但不加后缀。这个默认值由 `get_context_object_name()` 决定。

### context_object_name：改默认变量名

模板里不想用 `<model>_list` / `<model>` 时，用 `context_object_name` 改名：

```python
class TopicListView(generic.ListView):
    model = Topic
    context_object_name = 'all_topics'   # 模板里用 {{ all_topics }}，而不是 {{ topic_list }}
```

### 分页后多出的键

ListView 开启 `paginate_by` 后，context 额外注入 `page_obj`、`paginator`、`is_paginated`（详见本篇"分页"一节）。

### get_context_data：叠加顺序

```python
class TopicListView(generic.ListView):
    model = Topic
    paginate_by = 10

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)   # ★ 先调 super()
        context['entry_count'] = Entry.objects.count()  # 再追加自己的键
        return context
```

`super()` 调用链：`ContextMixin.get_context_data` 接收 kwargs（URL 捕获参数）→ 各 Mixin 把默认键（`object_list`、`page_obj` 等）塞进 context → 返回到你的覆盖方法里。

**铁律**：覆盖 `get_context_data` 时**必须调用 `super()`** 并把它返回的 dict 作为基础，再追加自己的键；否则默认的 `topic_list`、`object`、`page_obj`、`paginator` 全部丢失。

## Mixin 体系

### 认证与权限 Mixin（`django.contrib.auth.mixins`）

| Mixin | 作用 | 关键属性/方法 |
|---|---|---|
| `LoginRequiredMixin` | 未登录用户重定向到 `LOGIN_URL` | `login_url`、`redirect_field_name`（默认 `next`） |
| `PermissionRequiredMixin` | 用户必须拥有指定权限 | `permission_required = 'app.codename'`、`raise_exception` |
| `UserPassesTestMixin` | 自定义测试函数返回 `True` 才能过 | 覆盖 `test_func(self)`，返回 bool |
| `AccessMixin` | 上面三者的公共基类（一般不直接用） | `login_url`、`permission_denied_message`、`raise_exception` |


```python
from django.contrib.auth.mixins import PermissionRequiredMixin

class DoneEntriesListView(PermissionRequiredMixin, generic.ListView):
    """List all finished entries.
    Only visible to users with can_mark_done permission."""
    model = Entry
    permission_required = 'learning_logs.can_mark_done'
    template_name = 'learning_logs/done_entries.html'
    paginate_by = 10

    def get_queryset(self):
        return Entry.objects.filter(progress='done').order_by('-date_added')
```

权限 `learning_logs.can_mark_done` 是在 `Entry.Meta.permissions` 里声明的自定义权限。

`UserPassesTestMixin` 适合"对象归属者才能编辑"这类规则：

```python
from django.contrib.auth.mixins import UserPassesTestMixin

class EntryUpdateView(UserPassesTestMixin, UpdateView):
    model = Entry
    fields = ['text']

    def test_func(self):
        entry = self.get_object()
        return self.request.user == entry.topic.owner
```

### 通用 Mixin（`django.views.generic.base` / `.detail` / `.list` / `.edit`）

| Mixin | 提供的能力 | 关键成员 |
|---|---|---|
| `ContextMixin` | `get_context_data()` 的默认实现、`extra_context` | `get_context_data(**kwargs)` |
| `TemplateResponseMixin` | `render_to_response()`、模板查找 | `template_name`、`response_class` |
| `SingleObjectMixin` | 单对象查询：`get_object()`、`get_context_object_name()` | `model`/`queryset`、`pk_url_kwarg='pk'`、`slug_field`、`slug_url_kwarg` |
| `MultipleObjectMixin` | 列表查询与分页 | `queryset`、`paginate_by`、`paginator_class`、`page_kwarg='page'` |
| `FormMixin` | 表单处理钩子 | `form_class`、`success_url`、`form_valid()`、`form_invalid()`、`get_form_kwargs()` |
| `ModelFormMixin` | 从 `model+fields` 自动生成 ModelForm | `fields`、`get_form_class()`、`form_valid()`（保存对象） |
| `ProcessFormView` | `get`/`post` 方法本身（调用 `get_form`、`form_valid`/`form_invalid`） | 一般不直接覆盖 |

### 继承顺序规则

Python 多继承按 **MRO（从左到右）** 解析。CBV 的正确顺序是：

```python
class MyView(LoginRequiredMixin, PermissionRequiredMixin, ListView):
    #        ↑自定义/能力 Mixin 在前              ↑通用视图基类在后
```

理由：
- Mixin 通过重写 `dispatch`、`get`、`post` 等来"插入行为"；放在前面才能覆盖后面通用视图的同名方法。
- 如果写反了（`class MyView(ListView, LoginRequiredMixin)`），`LoginRequiredMixin.dispatch` 不会被调用，登录校验失效。
- 多个 Mixin 之间也是从左到右：先 `LoginRequiredMixin` 再 `PermissionRequiredMixin`。

## 常用覆盖点速查

| 覆盖点 | 在哪类视图上 | 典型用途 | 注意事项 |
|---|---|---|---|
| `get_queryset()` | ListView、DetailView、EditView | 按用户过滤、预取关联、动态排序 | 返回 QuerySet；DetailView 覆盖后 `get_object()` 基于它查 |
| `get_object(queryset=None)` | DetailView、EditView | 用 slug 而不是 pk、加权限校验、404 自定义 | 覆盖后通常 `return super().get_object(queryset)` |
| `get_context_data(**kwargs)` | 全部 | 给模板加额外变量 | **必须 `super()`** |
| `form_valid(form)` | FormView、Create/Update/DeleteView | 保存前注入外键、发消息、写日志 | 末尾 `return super().form_valid(form)` 或自己返回 HttpResponse |
| `form_invalid(form)` | FormView、Create/UpdateView | 校验失败时自定义行为（如记日志） | 一般不用覆盖 |
| `get_success_url()` | FormView、Create/Update/DeleteView | 动态跳转（如跳到刚建对象的详情） | 返回 URL 字符串 |
| `get_form_kwargs()` | FormMixin | 给 `__init__` 传额外参数（如 `request`） | 先 `kwargs = super().get_form_kwargs()` |
| `get_initial()` | FormMixin | 动态表单初始值 | 返回 dict |

## 分页

### 开启分页

ListView 上设 `paginate_by` 就自动分页，无需写任何分页代码：

```python
class TopicListView(generic.ListView):
    model = Topic
    paginate_by = 10   # 每页 10 条
```

分页后模板上下文自动多出：

| 上下文变量 | 含义 |
|---|---|
| `page_obj` | 当前页的 `Page` 对象 |
| `is_paginated` | 是否真的分页（总数 ≤ paginate_by 时为 False） |
| `paginator` | `Paginator` 实例 |
| `page_obj.object_list` | 当前页的对象列表 |

### 模板里写分页导航

```html
{% if is_paginated %}
<div class="pagination">
  {% if page_obj.has_previous %}
    <a href="?page={{ page_obj.previous_page_number }}">上一页</a>
  {% endif %}
  <span>第 {{ page_obj.number }} / {{ page_obj.paginator.num_pages }} 页</span>
  {% if page_obj.has_next %}
    <a href="?page={{ page_obj.next_page_number }}">下一页</a>
  {% endif %}
</div>
{% endif %}
```

### Paginator 类本身

在 FBV 或需要手动分页的场景，直接用 `django.core.paginator.Paginator`：

```python
from django.core.paginator import Paginator, EmptyPage, PageNotAnInteger


def topic_list(request):
    qs = Topic.objects.all()
    paginator = Paginator(qs, 10)                 # 每页 10 条
    page_number = request.GET.get('page', 1)
    try:
        page = paginator.page(page_number)
    except PageNotAnInteger:
        page = paginator.page(1)
    except EmptyPage:
        page = paginator.page(paginator.num_pages)
    return render(request, 'learning_logs/topic_list.html', {'page_obj': page})
```

`Paginator` 常用属性/方法：

| 成员 | 说明 |
|---|---|
| `Paginator(object_list, per_page)` | 构造 |
| `paginator.count` | 总条数 |
| `paginator.num_pages` | 总页数 |
| `paginator.page(N)` | 返回第 N 页（`Page` 对象） |
| `page.object_list` | 该页对象列表 |
| `page.has_next()` / `has_previous()` | 是否有下/上一页 |
| `page.next_page_number()` / `previous_page_number()` | 下/上一页页码 |
| `page.start_index()` / `end_index()` | 当前页首/末条在全表中的序号 |

## 与装饰器配合：method_decorator

函数视图用 `@login_required` 这种装饰器；CBV 是类，不能直接套，要用 `django.utils.decorators.method_decorator` 把装饰器变成方法装饰器。

### 装饰特定方法

```python
from django.contrib.auth.decorators import login_required
from django.utils.decorators import method_decorator


class MyView(View):
    @method_decorator(login_required)
    def get(self, request, *args, **kwargs):
        ...
```

### 装饰 dispatch（推荐写法）

给 `dispatch` 加装饰器等于给整个视图加：

```python
from django.utils.decorators import method_decorator
from django.views.decorators.csrf import csrf_exempt


@method_decorator(csrf_exempt, name='dispatch')
class WebhookView(View):
    def post(self, request):
        ...
```

`@method_decorator(..., name='dispatch')` 是类装饰器写法，等价于在 `dispatch` 方法上加装饰器。常见搭配：

| 装饰器 | 作用 |
|---|---|
| `login_required` | 需登录（CBV 里更推荐用 `LoginRequiredMixin`） |
| `permission_required('app.codename')` | 需权限（CBV 里更推荐 `PermissionRequiredMixin`） |
| `csrf_exempt` | 豁免 CSRF（仅 Webhook 等特殊场景） |
| `never_cache` | 禁止缓存 |
| `cache_page(60)` | 整页缓存 60 秒 |

> **约定**：能用 Mixin 就用 Mixin（`LoginRequiredMixin` 等），装饰器只在没有对应 Mixin 的时候用。

## 自定义 Mixin

把可复用的横切逻辑封装成 Mixin，供多个视图复用：

```python
class OwnerRequiredMixin:
    """要求对象的 owner 等于当前登录用户，否则 404。"""
    def get_object(self, queryset=None):
        obj = super().get_object(queryset)
        if obj.owner != self.request.user:
            raise Http404("你无权访问该对象")
        return obj


class FilterByUserMixin:
    """列表/详情查询集自动按当前用户过滤。"""
    def get_queryset(self):
        return super().get_queryset().filter(owner=self.request.user)


class TitleBreadcrumbMixin:
    """所有模板自动带上页面标题与面包屑。"""
    extra_breadcrumb = None

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['page_title'] = getattr(self, 'page_title', '')
        context['breadcrumb'] = self.extra_breadcrumb
        return context
```

使用时按"能力 Mixin 在前、通用视图在后"排列：

```python
class TopicUpdateView(OwnerRequiredMixin, LoginRequiredMixin, UpdateView):
    model = Topic
    fields = ['text']
    success_url = reverse_lazy('learning_logs:topics')
```

## 示例汇总：Learning Log 的 CBV 全景

```python
from django.views import generic
from django.views.generic.edit import CreateView, UpdateView, DeleteView
from django.urls import reverse_lazy
from django.contrib.auth.mixins import LoginRequiredMixin
from .models import Topic, Entry

# 读视图：列表 + 详情
class TopicListView(generic.ListView):
    model = Topic
    paginate_by = 10

class TopicDetailView(generic.DetailView):
    model = Topic

# 读视图：按用户过滤 + 登录保护
class MyTopicsListView(LoginRequiredMixin, generic.ListView):
    model = Topic
    template_name = 'learning_logs/my_topics.html'
    paginate_by = 10

    def get_queryset(self):
        return (Topic.objects.filter(owner=self.request.user)
                .order_by('-date_added'))

# 写视图：CRUD 三件套 + 注入外键
class TopicCreate(LoginRequiredMixin, CreateView):
    model = Topic
    fields = ['text']
    success_url = reverse_lazy('learning_logs:topics')

    def form_valid(self, form):
        form.instance.owner = self.request.user
        return super().form_valid(form)

class TopicUpdate(LoginRequiredMixin, UpdateView):
    model = Topic
    fields = ['text']

class TopicDelete(LoginRequiredMixin, DeleteView):
    model = Topic
    success_url = reverse_lazy('learning_logs:topics')
```
