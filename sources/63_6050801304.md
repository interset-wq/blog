
像 `Get-Process | Sort VM -desc | ConvertTo-HTML | Out-File process.html` 这样的单行命令非常强大——如果改用其他脚本语言实现同样功能，往往要编写多行代码，而 pwsh 只需一行。这一强大能力的根基，正是 pwsh 的**管道（pipeline）**机制。

## 一、什么是管道

pwsh 通过管道符号 `|` 连接命令。管道把**第一条命令的输出**，作为**第二条命令的输入**，让第二条命令基于第一条的结果继续运行，从而把多条命令串联成一条工作流。

``` pwsh
# 把 dir 的输出结果，作为 More 的输入（分页显示）
pwsh> Dir | More
```

上面的例子中，`dir` 列出目录内容，`More` 对结果分页显示——`dir` 的输出正是 `More` 的输入。

> 一条管道可以串联任意多条命令：`命令A | 命令B | 命令C | ...`，每个环节的输出流向下一个环节的输入。

## 二、输出结果到文件

pwsh 的输出默认显示在控制台，但可以通过多种方式保存到文件。

### 1. 重定向 `>` 与 Out-File

``` pwsh
PS C:\Users\d111k\Desktop\hello> dir > list.txt
PS C:\Users\d111k\Desktop\hello> cat .\list.txt

    目录:C:\Users\d111k\Desktop\hello

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d----          2026/10/11    22:58                routes
-a---          2026/10/12    12:49              0 list.txt
-a---          2026/10/11    22:00          29966 package-lock.json
-a---          2026/10/11    22:00            272 package.json

# 或
PS C:\Users\d111k\Desktop\hello> dir | Out-File list2.txt
PS C:\Users\d111k\Desktop\hello> cat .\list2.txt

    目录:C:\Users\d111k\Desktop\hello

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d----          2026/10/11    22:58                routes
-a---          2026/10/12    12:49            410 list.txt
-a---          2026/10/12    12:51              0 list2.txt
-a---          2026/10/11    22:00          29966 package-lock.json
-a---          2026/10/11    22:00            272 package.json
```

以上两条命令结果相同，都把 `dir` 的输出保存为 txt 文件。区别在于：

- `>` 是兼容 cmd 的写法
- `| Out-File` 是 pwsh 原生写法

> [!NOTE]
> `Out-File` 提供更多参数，例如自定义字符编码（UTF8、Unicode）、追加内容到现有文件等。默认创建的 `Out-File` 文件有 80 列宽，可能破坏原本的排版格式、降低可读性。

### 2. Out-* 系列 cmdlet

pwsh 有一批 `Out` 开头的 cmdlet，用来决定输出送到哪里：

``` pwsh
> dir
> dir | Out-Default | Out-Host
```

当你运行 `dir` 时，实际执行的相当于 `dir | Out-Default | Out-Host`——`Out-Host` 把结果显示到显示器。

> [!NOTE] 仅 Windows PowerShell
> `Out-Printer`（把结果发送到打印机，无打印机时输出 PDF）与 `Out-GridView`（在网格视图中显示结果，通过 Windows PowerShell ISE 展示）是 Windows PowerShell 独有的能力，pwsh 7+ 默认不提供。

## 三、输出为结构化数据：CSV 与 XML

### 1. CSV 表格

``` pwsh
# 把 Get-Process 的输出写入 procs.csv 并保存到当前目录
pwsh> Get-Process | Export-Csv procs.csv
```

CSV 文件的第一行是 `#TYPE System.Diagnostics.Process`，这是一个注释（`#` 用于注释），说明文件中包含的信息类型。CSV 中显示的内容比控制台更详细，因为控制台只输出比较重要的信息。

在控制台导入 CSV 查看内容：

``` pwsh
pwsh> Import-Csv procs.csv
```

### 2. XML

``` pwsh
# 导出为 XML
Get-Process | Export-Clixml reference.xml

# 导入 XML
Import-Clixml reference.xml
```

`Export-Clixml` 创建的是 clixml（generic CLI XML）文件。clixml 是 pwsh 专用的格式，但任何能解析 XML 的程序都能读取。

> [!NOTE]
> 所有以 `Import` 和 `Export` 开头的 cmdlet，都需要传入文件名参数。

## 四、对比文件差异：Compare-Object

`Compare-Object` 用于对比两组数据的差异，别名是 `Diff`，建议直接使用 `diff`。

``` pwsh
> Get-Process | Export-Clixml reference.xml

# 之后又打开了一些应用程序，再对比当前进程与刚才快照的差异
> diff -ReferenceObject (Import-Clixml .\reference.xml) -DifferenceObject (Get-Process) -Property name
```

结果中的 `SideIndicator` 列表示差异方向：

- `=>`：只存在于 `-DifferenceObject`（新的、之后出现的）内容
- `<=`：只存在于 `-ReferenceObject`（旧的、之前快照的）内容
- 两边都有的内容不会出现在输出结果中

> `()` 可以提高命令执行的优先级，被括号包裹的命令会先执行。

## 五、转换成 HTML

把结果通过管道传给 `ConvertTo-Html`，即可生成结构良好的 HTML，可在任何浏览器中打开。

``` pwsh
# 直接在控制台输出 HTML 内容（不需要文件名）
> Get-Service | ConvertTo-Html

# 输出为 HTML 文件
> Get-Service | ConvertTo-Html | Out-File services.html
```

生成的只是原始数据，若需要美观的排版，需要额外引用 CSS（Cascading Style Sheet）定制样式。

> [!NOTE]
> pwsh 还附带 `ConvertTo-Csv`、`ConvertTo-XML` 等命令。和 `ConvertTo-Html` 一样，这些命令**不会在磁盘上创建文件**，只是把结果转换成对应格式；你需要用管道连接 `Out-File` 才能存盘，效果类似 `Export-Csv` / `Export-CliXML`（后者还能同时完成转换与存储）。

## 六、用管道修改系统：终止进程、停止服务

> [!WARNING]
> 不要运行下面这个命令，否则电脑会蓝屏死机！

``` pwsh
> Get-Process | Stop-Process
```

这个命令会关闭**所有**进程，导致电脑死机。带有相同名词（本例中的 `Process`）的 cmdlet 可以互传信息，但通常情况下最好指定特定进程，而不是终止全部：

``` pwsh
# 只终止记事本进程
> Get-Process -Name Notepad | Stop-Process
```

服务也是类似的，`Get-Service` 的输出能与其他 cmdlet（`Stop-Service`、`Start-Service`、`Set-Service` 等）一起被管道传输。

### 关于安全确认：$ConfirmPreference

像 `Stop-Service`、`Stop-Process` 这类会修改系统的 cmdlet，有一个内部定义的**影响级别（impact level）**。cmdlet 的创建者已设定好这些级别，不允许修改。Shell 则有一个相应的 `$ConfirmPreference` 设置，默认是 `High`：

``` pwsh
> $ConfirmPreference
High
```

工作原理：

- 当 cmdlet 的内部影响级别 **大于等于** Shell 的 `$ConfirmPreference` 时，Shell 会自动询问是否执行该操作
- 当 cmdlet 的内部影响级别 **小于** `$ConfirmPreference` 时，不会自动弹出提示

> [!TIP]
> 在命令末尾加 `-Confirm` 参数，会对支持的修改类 cmdlet 弹出确认提示；使用 `-WhatIf` 参数则可预演命令将要执行的操作，而不会真正修改系统。

## 七、读取文件：Get-Content

`Get-Content` 用于读取文件内容，别名是 `cat`、`type`。

``` pwsh
> Get-Content .\computers.txt
```

> [!NOTE]
> `Import` 开头的 cmdlet 会关注文件中的内容、尝试解析它们，并创建比原始命令更顺眼的输出结果。例如用 `Export-CSV` 创建的文件就用 `Import-CSV` 读取，用 `Export-CliXML` 创建的文件建议用 `Import-CliXML` 读取。只有在仅需要读取文本原始内容、不需要 pwsh 解析数据时，才使用 `Get-Content`。

## 八、管道如何传输数据：参数绑定

看完上面的实战，你可能好奇：pwsh 到底是怎么把一条命令的输出，变成另一条命令的输入的？

当两条命令串联时，pwsh 必须搞清楚怎样把**第一条命令的输出**作为**第二条命令的输入**：

``` pwsh
> CommandA | CommandB
```

把第一条命令称为命令 A（产生结果），第二条命令称为命令 B（接收结果集并完成自己的工作）。

比如希望把一批计算机名称传给某条命令，让它在这些计算机上运行：

``` pwsh
pwsh> Get-Content .\computers.txt | Get-Service
```

`Get-Content` 把文本文件中的计算机名称放入管道。之后 pwsh 决定如何把数据传给 `Get-Service`——但 pwsh **一次只能使用单个参数接收传入数据**，它必须决定由 `Get-Service` 的哪个参数接收 `Get-Content` 的输出。

这个决定的过程就称为**管道参数绑定（Pipeline parameter binding）**。pwsh 使用两种方法：

1. **ByValue**：Shell 首先尝试的方法
2. **ByPropertyName**：若 ByValue 行不通，再尝试此方法

## 九、核心总结

1. **管道**用 `|` 连接命令，让前一条命令的输出成为后一条命令的输入，把多条命令串联成工作流。
2. 输出可以重定向到文件（`>` / `Out-File`）、保存为 CSV / XML（`Export-Csv` / `Export-Clixml`）、转成 HTML（`ConvertTo-Html`）。
3. `Compare-Object` 对比数据差异；`Get-Content` 读取文本文件。
4. 用管道修改系统时要谨慎（如 `Get-Process | Stop-Process` 会终止所有进程），可借助 `$ConfirmPreference`、`-Confirm`、`-WhatIf` 保证安全。
5. 管道把数据传给下一条命令时，通过**管道参数绑定**完成：先尝试 **ByValue**，不行再尝试 **ByPropertyName**。
