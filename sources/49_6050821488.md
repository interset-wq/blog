
## 压缩与解压缩

```bash
# tar + gzip
$ tar -czvf app.tar.gz dir/          # 压缩（c 创建 z gzip v 详情 f 文件）
$ tar -xzvf app.tar.gz               # 解压到当前目录
$ tar -xzvf app.tar.gz -C /opt/      # 解压到指定目录

# zip
$ sudo apt install zip unzip         # Ubuntu 安装
$ zip -r app.zip dir/                # 压缩（含目录用 -r）
$ unzip app.zip                      # 解压
$ unzip app.zip -d /opt/app          # 解压到指定目录
```

> [!WARNING]
> tar 的 `-f` 选项必须位于选项组合最后一位；解压时若目标目录存在同名文件会被覆写。

## 文件传输

```bash
# wget 下载
$ wget https://example.com/file.tar.gz
$ wget -b https://example.com/file.tar.gz   # 后台下载，日志写 wget-log
$ tail -f wget-log                           # 查看下载进度

# curl
$ curl -O https://example.com/file.tar.gz   # 下载
$ curl -I https://example.com               # 只看响应头

# rz / sz（需终端软件支持）
$ sudo apt install lrzsz
$ sz file.txt       # 下载到本地
$ rz                # 上传，弹出文件选择
```

## Python 项目部署（FastAPI / Django）

Python 后端流行框架：**FastAPI**（现代异步、自动文档）、**Django**（大而全、自带 ORM/Admin）。生产环境推荐用虚拟环境 + 进程守护 + Nginx 反向代理。

### 安装 uv 与虚拟环境

**uv** 是 Rust 编写的新一代 Python 包/环境管理器，速度快（替代 `pip`+`venv`+`requirements`），推荐作为 Python 依赖管理的统一入口。

```bash
# 安装 uv（官方脚本）
$ curl -LsSf https://astral.sh/uv/install.sh | sh
# 或 Ubuntu apt 源安装
$ sudo apt install uv

$ uv --version
# 为项目创建并激活虚拟环境（.venv）
$ cd /opt/myapi
$ uv venv
$ source .venv/bin/activate
```

依赖管理以项目内 **`pyproject.toml`** 为核心（替代 `pip install` + `requirements.txt`）：

```bash
# 添加依赖（写入 pyproject.toml 并安装）
(venv) $ uv add fastapi uvicorn[standard]
# 按 pyproject.toml 同步环境（部署/换机时）
(venv) $ uv sync
# 手动管理依赖（等价旧 pip，仍可用）
(venv) $ uv pip install flask
```

### FastAPI 部署

FastAPI 是异步框架，生产环境配 **uvicorn**（ASGI 服务器）运行，通常加 `--workers` 多进程。

```bash
# 已由 uv add 安装 fastapi + uvicorn
# 本地启动（开发，--reload 热重载）
(venv) $ uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

**systemd 守护（生产）**——`/etc/systemd/system/fastapi.service`：

```ini
[Unit]
Description=FastAPI app
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/myapi
ExecStart=/opt/myapi/venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now fastapi
$ sudo systemctl status fastapi
```

**Nginx 反向代理**——`/etc/nginx/sites-available/fastapi`：

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
$ sudo ln -s /etc/nginx/sites-available/fastapi /etc/nginx/sites-enabled/
$ sudo nginx -t && sudo systemctl reload nginx
```

### Django 部署

Django 生产环境用 **gunicorn**（WSGI 服务器）运行，并配合静态文件收集。

```bash
(venv) $ uv add gunicorn
# 收集静态文件、迁移数据库
(venv) $ python manage.py collectstatic
(venv) $ python manage.py migrate

# 启动（--workers 建议 2×CPU+1）
(venv) $ gunicorn myproject.wsgi:application --bind 127.0.0.1:8000 --workers 3
```

systemd 单元（`/etc/systemd/system/django.service`）：

```ini
[Service]
User=www-data
WorkingDirectory=/opt/mydjango
ExecStart=/opt/mydjango/venv/bin/gunicorn myproject.wsgi:application --bind 127.0.0.1:8000 --workers 3
Restart=always
```

> [!NOTE]
> Django 还需在 `settings.py` 设置 `ALLOWED_HOSTS`、`DEBUG=False`，静态文件交给 Nginx 或 CDN 托管。

## JS/TS 项目部署（Vue / React / Express）

前端主流框架 **Vue / React** 构建后产出静态文件，交给 Nginx 托管；后端 **Express**（Node.js）作为服务常驻运行。

### 环境：Node.js 与 npm

```bash
# 方式一：Ubuntu 源（版本可能旧）
$ sudo apt install nodejs npm
# 方式二：官方源安装（推荐，版本新）
$ curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
$ sudo apt install -y nodejs
$ node -v && npm -v
```

> 生产环境建议用 **nvm**（Node 版本管理器）按项目切换 Node 版本：`curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash`。

### Vue / React 前端构建部署

```bash
# 安装依赖
$ npm install
# 构建生产包（产物在 dist/ 目录）
$ npm run build
# 本地开发预览
$ npm run dev
```

构建产物 `dist/` 直接交给 Nginx 托管：

```nginx
server {
    listen 80;
    server_name app.example.com;
    root /var/www/myapp/dist;
    index index.html;

    # SPA 路由：找不到路径时回退到 index.html（解决刷新 404）
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
$ sudo cp -r dist/ /var/www/myapp/
$ sudo nginx -t && sudo systemctl reload nginx
```

### Express 后端部署

```bash
$ npm install            # 安装依赖（express 等）
$ node app.js            # 本地启动
```

**systemd 守护（生产）**——`/etc/systemd/system/express.service`：

```ini
[Service]
User=www-data
WorkingDirectory=/opt/myexpress
Environment=NODE_ENV=production
ExecStart=/usr/bin/node app.js
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now express
```

> [!NOTE]
> Node.js 进程常配合 **PM2** 进程管理器使用（内置日志、开机自启、负载均衡）：`npm install -g pm2`，`pm2 start app.js`，`pm2 save && pm2 startup`。

### 前后端分离整体架构

```text
浏览器 ──> Nginx (80/443, 静态前端 + 反向代理)
              ├── /            → Vue/React dist/ 静态文件
              └── /api         → 代理到 Express / FastAPI (127.0.0.1:8000)
```

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
}
```

## 综合示例：一键部署脚本

```bash
#!/bin/bash
set -e
APP_NAME="myapp"
DEPLOY_DIR="/opt/$APP_NAME"

echo "=== 部署 $APP_NAME ==="
mkdir -p "$DEPLOY_DIR"
cp ./app.tar.gz "$DEPLOY_DIR/"
cd "$DEPLOY_DIR"
tar -xzf app.tar.gz

cat > /etc/systemd/system/$APP_NAME.service <<EOF
[Unit]
Description=$APP_NAME
After=network.target

[Service]
ExecStart=$DEPLOY_DIR/app
Restart=always

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now $APP_NAME
systemctl status $APP_NAME
```
