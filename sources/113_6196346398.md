
上一篇《在FastAPI中实现JWT》（见[JWT 系列](post/113.html)）里，鉴权逻辑写在 `deps.py` 的**依赖**中；而 Express 的同款逻辑写在**中间件**里。这篇把两件事讲透：FastAPI 为什么用依赖注入接替了中间件的多数职责，以及支撑这一切的底层魔法——**类型注解**。

## 两种横切机制：中间件 vs 依赖注入

### 中间件：作用于每个请求的函数

FastAPI 的中间件与 Express 同名同源：在请求到达路由**之前**、响应返回客户端**之前**各有一次介入机会，对**所有请求**生效。

```python
import time
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_timing(request: Request, call_next):
    """@app.middleware("http") 注册的函数：包裹整个请求-响应周期"""
    start = time.perf_counter()
    response = await call_next(request)      # 放行：交给后面的中间件/路由
    cost_ms = (time.perf_counter() - start) * 1000
    response.headers["X-Process-Time"] = f"{cost_ms:.2f}ms"
    return response
```

- `call_next(request)` 相当于 Express 中间件里的 `next()`，调用它请求才会继续往下走
- 多个中间件形成**洋葱模型**：请求按注册顺序穿入，响应按相反顺序穿出
- 全局功能通常用 `add_middleware` 挂现成类，例如 CORS：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### 依赖注入：声明在路由参数上

依赖（dependency）是 FastAPI 的独门机制：路由函数的参数标注 `Annotated[类型, Depends(fn)]` 时，FastAPI 会在**进入路由函数前**自动调用 `fn`，把返回值作为该参数传入。JWT 系列里的鉴权链就是这么搭的：

```python
from typing import Annotated
from fastapi import Depends

# 依赖可以嵌套：reusable_oauth2 先执行拿到 token，
# get_current_user 再做黑名单检查、验签
def get_current_user(token: Annotated[str, Depends(reusable_oauth2)]) -> dict:
    ...

# 路由参数写一行，鉴权链自动执行
@app.get("/profile")
def profile(user: CurrentUser) -> dict:   # CurrentUser = Annotated[dict, Depends(get_current_user)]
    return {"user": user}
```

### 逐项对比

| 维度 | 中间件 | 依赖注入 |
| --- | --- | --- |
| 作用范围 | **所有请求**，无法按路由豁免 | **声明它的路由才执行**，精确到参数 |
| 拿得到什么 | 只有原始 `Request`（不知道将要匹配哪个路由） | 依赖函数自己也能声明依赖，可组合成树 |
| 有返回值吗 | 无（只能往 `request.state` 塞东西） | **有**——返回值直接成为路由参数 |
| 异常处理 | 自己 `try/except` | `raise HTTPException` 自动转 HTTP 响应 |
| 执行时机 | 路由匹配之前（外层） | 路由匹配之后、函数调用之前（内层） |
| 声明位置 | `main.py` 全局注册 | 路由装饰器或参数表，随业务走 |
| 典型用途 | 日志、CORS、GZip、安全头、全站计时 | 鉴权、授权、数据库会话、分页参数、公共前置逻辑 |

### 同一件事的两种写法：鉴权

中间件版——只能把结果挂在 `request.state` 上，路由函数再自己取：

```python
@app.middleware("http")
async def authenticate_all(request: Request, call_next):
    token = request.headers.get("Authorization", "")
    decoded = verify_token(token.removeprefix("Bearer ")) if token else None
    request.state.user = decoded          # 路由里要手动 if 判断
    response = await call_next(request)
    return response


@app.get("/profile")
def profile(request: Request):
    if not request.state.user:            # 每个受保护路由都要重复判断
        raise HTTPException(status_code=401, detail="Invalid token")
    return {"user": request.state.user}
```

依赖版——校验和拦截集中在一处，路由只声明"我要登录用户"：

```python
@app.get("/profile")
def profile(user: CurrentUser) -> dict:   # 到不了这里就必然已登录
    return {"user": user}
```

### 怎么选

- **全局横切**（每个请求都要、与业务无关）：日志、CORS、GZip、安全头、请求计时 → **中间件**
- **业务级前置**（部分路由需要、有返回值、可组合）：鉴权、授权、数据库会话、分页 → **依赖注入**

一个请求的完整旅程，两类机制各就各位：

```
请求 → 中间件① → 中间件② → 路由匹配 → 依赖树解析(reusable_oauth2 → get_current_user)
     → 路由函数 → 响应 → 中间件② 回程 → 中间件① 回程 → 客户端
```

## 类型注解的魔法

上一篇已经反复见过这样的参数表：

```python
def register(body: Credentials) -> dict: ...
def profile(user: CurrentUser) -> dict: ...
def list_users(page: int = 1) -> dict: ...
```

Python 的类型注解本身只是元数据，运行时**不强制**任何东西——但 FastAPI 把它们全部当作**声明式配置**来读。同一个 `:`，在不同位置触发不同机制：

| 注解位置 | 写法 | FastAPI 读出了什么 |
| --- | --- | --- |
| 路由参数（路径中有 `{id}`） | `item_id: int` | **路径参数**：从 URL 提取并转换类型 |
| 路由参数（有默认值） | `page: int = 1` | **查询参数**：`?page=2`，缺省用默认值 |
| 路由参数（Pydantic 模型） | `body: Credentials` | **请求体**：解析 JSON、字段校验，失败自动 422 |
| `Annotated[类型, Depends(fn)]` | `user: CurrentUser` | **依赖注入**：先执行 `fn`，返回值作参数 |
| `Annotated[int, Query(ge=1)]` | `page: Annotated[int, Query(ge=1)]` | **校验规则**：`ge`/`le`/`min_length` 等约束 |
| 函数返回值 | `-> dict` | **响应模型**推导 + OpenAPI 文档 |

### 路径与查询参数：自动转换和校验

```python
@app.get("/users/{user_id}")
def get_user(user_id: int, verbose: bool = False) -> dict:
    return {"user_id": user_id, "verbose": verbose}
```

- `user_id: int`：URL 里的 `"42"` 自动转成 `int`；转不动（`/users/abc`）直接 **422**，带具体错误位置——Express 里 `req.params.id` 永远是 string，要手动 `Number()` 再检查 `NaN`
- `verbose: bool`：`?verbose=1`、`?verbose=true`、`?verbose=on` 都能正确解析成布尔值
- 参数在路径里 → 路径参数；不在路径里且有默认值 → 查询参数。**没有第三个动作**，函数签名即文档

### 请求体：Pydantic 模型接管校验

```python
class Credentials(BaseModel):
    email: str
    password: str

@router.post("/register")
def register(body: Credentials) -> dict:
    ...   # body.email / body.password 已保证存在且类型正确
```

字段缺失或类型不符时，请求**到不了函数体**——FastAPI 自动返回 422 和逐字段的错误清单。对比 Express 版 register 里手动的 `if (!email || !password)` 判空，这些防御代码在 FastAPI 里不需要写（所以 FastAPI 版只剩"邮箱重复"这种业务判断）。

校验规则还可以继续加密：

```python
from pydantic import BaseModel, Field

class Credentials(BaseModel):
    email: str = Field(..., pattern=r".+@.+\..+")
    password: str = Field(..., min_length=8)
```

### Annotated：一个参数挂多个"插件"

`Annotated`（PEP 593）是这套魔法的枢纽——类型旁边可以附加任意多的元数据，FastAPI 逐个识别：

```python
# 依赖 + 校验可以叠加在同一个参数上
def list_users(
    page: Annotated[int, Query(ge=1, le=100)] = 1,
    user: CurrentUser = None,        # CurrentUser 本质是 Annotated[dict, Depends(...)]
) -> dict:
    ...
```

上一篇 `deps.py` 里的 `CurrentUser = Annotated[dict, Depends(get_current_user)]` 就是把完整声明收进类型别名：路由参数写起来像普通类型，实际背后挂着整条鉴权依赖链。

### 这一切从哪来：启动时构建，不只是运行时

FastAPI 在**应用启动时**就读遍所有路由的签名（`typing` 内省 + Pydantic 模型），构建出两样东西：

1. **依赖树**：每个路由需要执行哪些依赖、以什么顺序嵌套，提前算好
2. **JSON Schema**：每个接口收发什么数据，汇成 `/openapi.json`——`/docs` 的 Swagger 交互页面就是按它自动渲染的，JWT 系列里 `/token` 表单端点喂的 Authorize 弹窗正是其中一环

所以注解不是"运行时顺便看看"：写错的注解在启动/打开文档时就能暴露，接口文档永远和代码同步——这是"类型注解的魔法"真正的回报。

### 对应到 Express 的心智转换

| 手写在 Express 里 | FastAPI 用注解声明 |
| --- | --- |
| `Number(req.params.id)` + `NaN` 检查 | `user_id: int` |
| `req.query.page ?? 1` | `page: int = 1` |
| `if (!req.body.email) return res.status(400)...` | `body: Credentials`（422 自动） |
| `app.use(authenticate)` + `req.user` | `user: CurrentUser` |
| `authorizeRole("admin")` 中间件 | `Depends(require_role("admin"))` |
| Swagger/JSDoc 手写注释、可能过期 | `/docs` 由注解自动生成，永不落后 |

一句话总结：**Express 把请求的解析、校验、鉴权写成命令式的胶水代码；FastAPI 把它们变成参数表上的声明，剩下的交给框架在启动时算好。** 中间件因此退守全局横切，依赖注入接管业务前置——而类型注解是这一切的语法载体。
