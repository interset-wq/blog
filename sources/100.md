
# Express

## Express.js 是什么

**Express.js** 是构建在 Node.js 之上的**极简、灵活**的 Web 框架。相比原生 `http` 模块，它用更少的样板代码即可构建 Web 服务器和 API。

### 一个基础 Express 服务器

```js
const express = require("express");
const app = express();
const port = 3000;

app.get("/", (req, res) => {
  res.send("Hello World!");
});

app.listen(port, () => {
  console.log(`Example app listening on port ${port}`);
});
```

### 核心概念

| 概念 | 说明 |
| --- | --- |
| `express()` | 工厂函数，创建 Express 应用实例（`app`） |
| `app.listen(port, callback)` | 启动服务器并监听指定端口 |
| `req` | 请求对象，含 URL、headers、params、body、query |
| `res` | 响应对象，用于向客户端发送数据 |
| **中间件（Middleware）** | 在接收请求与发送响应之间运行的代码 |

---

## 路由（Routing）

**路由**定义：当客户端以特定 HTTP 方法访问特定 URL 时，应用如何响应。

### 注册处理器

`app.get/post/put/delete(path, handler)` 分别为对应 HTTP 方法注册处理器。

### 静态路由

固定 URL 模式，如 `app.get("/home", handler)`。

### 动态路由（带参数）

使用 `:paramName` 占位符，通过 `req.params` 捕获：

```js
app.get("/post/:postId", (req, res) => {
  const postId = req.params.postId;
  res.send(`Viewing post with ID: ${postId}`);
});
```

### 请求/响应常用成员

| 成员 | 作用 |
| --- | --- |
| `req.params` | 路由参数（`:id` 段） |
| `req.query` | 查询字符串参数（`?key=value`） |
| `req.body` | 请求体（需要 body 解析中间件） |
| `res.send(data)` | 发送响应（文本、HTML、JSON 或二进制） |
| `res.json(obj)` | 发送 JSON 响应，自动设置 `Content-Type: application/json` |
| `res.status(code).send(msg)` | 设置状态码并发送响应 |
| `res.redirect(url)` | 重定向客户端到另一 URL |
| `res.render(view, data)` | 渲染模板引擎视图并发送 HTML |

### 链式路由 `app.route()`

为同一路径分组多个 HTTP 方法，减少重复：

```js
app
  .route("/user")
  .get((req, res) => {
    res.send("Fetching user data");
  })
  .post((req, res) => {
    res.send("Creating a user");
  })
  .put((req, res) => {
    res.send("Updating the user");
  })
  .delete((req, res) => {
    res.send("Deleting the user");
  });
```

### `express.Router()` — 模块化迷你应用

用于将相关路由分组，实现模块化：

```js
// userRoutes.js
const express = require("express");
const router = express.Router();

router.get("/", (req, res) => {
  res.send("List of users");
});
router.get("/:id", (req, res) => {
  res.send(`User details for user with id: ${req.params.id}`);
});

module.exports = router;
```

```js
// app.js
const userRoutes = require("./userRoutes");
app.use("/users", userRoutes);
```

### 提供静态文件

- `express.static(directory)`：内置中间件，从指定目录提供文件：

```js
app.use(express.static(path.join(__dirname, "public")));
```

- 带挂载路径的多目录：`app.use("/images", express.static(path.join(__dirname, "images")));`

## Express 中间件

**中间件**：在请求生命周期中执行的函数，可访问 `req`、`res` 和 `next`。

- 调用 `next()` 将控制权交给下一个中间件；省略它则结束请求周期。
- **中间件按 `app.use()` 注册的顺序执行**。

### 中间件类型

| 类型 | 绑定方式 | 作用范围 |
| --- | --- | --- |
| 应用级 | `app.use()` | 每个进入的请求 |
| 路由级 | `router.use()` | 仅该 router 处理的路由 |
| 错误处理 | 四个参数 `(err, req, res, next)` | 放在栈底部 |

### 常用内置/第三方中间件

| 中间件 | 作用 |
| --- | --- |
| `express.json()` | 解析 JSON 负载的请求，数据放到 `req.body` |
| `express.urlencoded({ extended: true })` | 解析 URL 编码的表单数据 |
| `express.static('public')` | 从目录提供静态文件 |
| `cors` | 启用跨域资源共享。`npm install cors` 后 `app.use(cors())` |
| `morgan` | 记录 HTTP 请求日志。`app.use(morgan('tiny'))` |

## 错误处理与健康检查

### 错误处理中间件

以四个参数 `(err, req, res, next)` 识别，**始终放在中间件栈末尾**：

```js
app.use((err, req, res, next) => {
  console.error(err.message);
  res.status(500).send("Internal Server Error");
});
```

### 异步错误处理

- **Express 4**：必须手动 `try/catch` 并用 `next(err)` 转发：

```js
app.get("/user", async (req, res, next) => {
  try {
    const user = await getUserFromDatabase();
    res.send(user);
  } catch (err) {
    next(err);
  }
});
```

- **Express 5**：异步错误**自动**转发给错误处理中间件，无需手动 `next(err)`。

### 404 处理

放在所有路由之后、错误处理器之前：

```js
app.use((req, res, next) => {
  res.status(404).send("Sorry, that route does not exist.");
});
```

### 调试与日志

- **内置 debug**：设置环境变量启用。`DEBUG=express:* node index.js`
- **`morgan`**：流行的第三方 HTTP 请求日志中间件，记录方法、URL、状态码和响应时间：

```js
const morgan = require("morgan");
app.use(morgan("dev"));
```

### 健康检查

返回 `200 OK` 表示应用正在运行，供负载均衡器、容器编排器使用：

```js
app.get("/health", (req, res) => {
  res.status(200).send("OK");
});
```

### 优雅关闭（Graceful Shutdown）

处理信号，允许正在进行的请求完成：

- `SIGTERM`：进程应终止时发送的信号。
- `SIGINT`：本地开发按 Ctrl+C 时发送的信号。

```js
process.on("SIGTERM", () => {
  server.close(() => {
    console.log("Server closed. Cleaning up...");
  });
});
```

**关闭前标记为不健康**：关闭期间健康检查返回 `503`，让负载均衡器不再路由新流量：

```js
let isShuttingDown = false;

app.get("/health", (req, res) => {
  if (isShuttingDown) {
    res.status(503).send("Shutting down");
  } else {
    res.status(200).send("OK");
  }
});

process.on("SIGTERM", () => {
  isShuttingDown = true;
  server.close(() => {
    console.log("Graceful shutdown complete");
  });
});
```

## 补充实战：一个完整的 REST API 示例

把本文的中间件、路由、错误处理整合成一个可运行的服务器：

```js
const express = require("express");
const path = require("path");
const morgan = require("morgan");
const app = express();
const port = process.env.PORT || 3000;

// ---------- 全局中间件（按注册顺序执行）----------
app.use(morgan("dev"));            // 请求日志
app.use(express.json());           // 解析 JSON 请求体
app.use(express.urlencoded({ extended: true })); // 解析表单
app.use(express.static(path.join(__dirname, "public"))); // 静态文件

// ---------- 内存数据 ----------
const users = [
  { id: 1, name: "Alice" },
  { id: 2, name: "Bob" },
];

// ---------- 路由 ----------
// 获取用户列表
app.get("/api/users", (req, res) => {
  res.json(users);
});

// 获取单个用户（动态参数）
app.get("/api/users/:id", (req, res) => {
  const user = users.find((u) => u.id === Number(req.params.id));
  if (!user) return res.status(404).json({ error: "User not found" });
  res.json(user);
});

// 创建用户（读取 req.body）
app.post("/api/users", (req, res) => {
  const { name } = req.body;
  if (!name) return res.status(400).json({ error: "name is required" });
  const user = { id: users.length + 1, name };
  users.push(user);
  res.status(201).json(user); // 201 Created
});

// 更新用户
app.put("/api/users/:id", (req, res) => {
  const user = users.find((u) => u.id === Number(req.params.id));
  if (!user) return res.status(404).json({ error: "User not found" });
  user.name = req.body.name || user.name;
  res.json(user);
});

// 删除用户
app.delete("/api/users/:id", (req, res) => {
  const idx = users.findIndex((u) => u.id === Number(req.params.id));
  if (idx === -1) return res.status(404).json({ error: "User not found" });
  users.splice(idx, 1);
  res.status(204).end(); // 204 No Content
});

// 健康检查
app.get("/health", (req, res) => res.status(200).send("OK"));

// ---------- 404 兜底（在所有路由之后）----------
app.use((req, res) => res.status(404).json({ error: "Route not found" }));

// ---------- 错误处理中间件（最后注册）----------
app.use((err, req, res, next) => {
  console.error(err.message);
  res.status(500).json({ error: "Internal Server Error" });
});

// ---------- 启动 + 优雅关闭 ----------
const server = app.listen(port, () => {
  console.log(`Server listening on port ${port}`);
});

let shuttingDown = false;
function shutdown(signal) {
  if (shuttingDown) return;
  shuttingDown = true;
  console.log(`${signal} received, shutting down...`);
  server.close(() => {
    console.log("Closed, cleanup done");
    process.exit(0);
  });
}
process.on("SIGTERM", () => shutdown("SIGTERM"));
process.on("SIGINT", () => shutdown("SIGINT"));
```

### 自定义中间件的两种典型形态

```js
// 1. 请求日志中间件
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url} @ ${new Date().toISOString()}`);
  next(); // 必须调用 next() 才会进入下一个中间件/路由
});

// 2. 认证保护中间件（模拟）
function requireAuth(req, res, next) {
  if (!req.headers.authorization) {
    return res.status(401).json({ error: "Unauthorized" });
  }
  next();
}
// 只对指定路由启用
app.get("/api/admin", requireAuth, (req, res) => {
  res.json({ secret: "admin-only-data" });
});
```

### 用 express.Router() 组织模块化路由

```js
// routes/userRoutes.js
const router = require("express").Router();

router.get("/", (req, res) => res.json(users));
router.get("/:id", (req, res) => res.json({ id: req.params.id }));

module.exports = router;

// index.js 挂载
const userRoutes = require("./routes/userRoutes");
app.use("/api/users", userRoutes);
```

## REST API 与 Web 服务

### API 与 Web 服务的区别

- **API（应用程序接口）**：软件之间通信的通用机制。
- **Web 服务**：使用 Web 协议（HTTP/HTTPS）在网络上传数据的**特定类型** API。
  - **每个 Web 服务都是 API，但不是每个 API 都是 Web 服务**。

### Web 服务特征

- 运行在服务器上
- 支持机器对机器通信
- 语言无关、平台无关
- 使用标准 Web 协议

### Web 服务风格

| 风格 | 说明 |
| --- | --- |
| **REST** | Representational State Transfer，使用最广泛的 Web 服务风格。简单、灵活，天然契合 HTTP |
| **SOAP** | Simple Object Access Protocol，仅用 XML，常见于要求严格标准的企业系统 |
| **XML-RPC** | 用 XML 编码轻量请求与响应 |

## REST 架构

### 无状态性（Statelessness）

- 每个请求被独立处理，服务器**不保存**请求间的会话状态。
- 每个请求必须携带所有必要信息（例如每次调用都带认证 token）。

### 资源（Resources）

一切皆是资源，用 URL 标识：

- `/products`：资源集合
- `/products/1`：单个具体资源

### REST 中的 HTTP 方法

| 方法 | 语义 |
| --- | --- |
| `GET` | 获取 |
| `POST` | 创建 |
| `PUT` / `PATCH` | 更新 |
| `DELETE` | 删除 |

### 响应格式

- JSON 最常见，也支持 XML 和纯文本。
- 客户端通过 `Accept` 头指定格式：

```
Accept: application/json
```

## 在 Express 中实现 REST API（对应上面的完整示例）

```js
// REST 资源映射：集合 + 单项
app.get("/api/products");       // 获取集合
app.get("/api/products/:id");   // 获取单项
app.post("/api/products");      // 创建
app.put("/api/products/:id");   // 完整更新
app.patch("/api/products/:id"); // 部分更新
app.delete("/api/products/:id");// 删除
```

> 上面的「完整 REST API 示例」正是对 REST 架构的落地实现：用 URL 标识资源、用 HTTP 方法表达操作、用 `res.json()` 返回 JSON、保持无状态。

## 微服务（Microservices）

### 单体架构（Monolith）

- 一个大型代码库，UI、数据库和 API 都在一起。
- 复杂度增长后难以维护和扩展。

### 微服务架构

- 将大型应用拆分为**小型、独立**的服务，每个服务负责单一业务能力。
- 服务间通过 API 或消息队列通信。

### 优劣势

| 优势 | 劣势 |
| --- | --- |
| 独立开发、部署更快 | 调试更复杂（问题跨服务） |
| 更好的故障隔离 | 基础设施开销更高 |
| 不同服务可用不同语言/框架 | 网络通信增加 |
