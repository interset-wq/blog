
## 为什么用 CBV

函数视图（FBV）每个 URL 对应一个函数，重复的样板代码（查对象、判断方法、渲染模板）要手写一遍又一遍。CBV 把这些常见模式抽象成**可配置的类**：你只需声明"用哪个模型、哪几个字段"，Django 自动完成查询、校验、保存、跳转；需要定制时再覆盖特定方法。

CBV 的难点在于它有很多**隐式约定（魔法）**——你没写的东西 Django 替你决定了。

## as_view()：类如何变成视图

类本身不是可调用的视图函数，要通过类方法 `as_view()` 在 URLconf 里挂上：

```python
from django.urls import path
from .views import BookListView

urlpatterns = [
    path('books/', BookListView.as_view(), name='book-list'),
]
```

### 最裸的 View

```python
from django.http import HttpResponse
from django.views import View

class HelloView(View):
    def get(self, request):
        return HttpResponse("Hello, CBV!")

    def post(self, request):
        return HttpResponse("You POSTed something.")
```

FBV 里的 `if request.method == 'POST': ... else: ...` 在 CBV 里被拆成同名方法，结构更清晰。

## CBV 继承树总览

```
View
├── TemplateView                  # 渲染模板（ContextMixin + TemplateResponseMixin）
├── RedirectView                  # 重定向
├── BaseDetailView ─► DetailView            # 单对象详情（读）
├── BaseListView  ─► ListView               # 对象列表（读）
├── FormView                      # 显示并处理表单（不落库）
├── BaseCreateView ─► CreateView            # 新增对象（写）
├── BaseUpdateView ─► UpdateView            # 修改对象（写）
└── BaseDeleteView ─► DeleteView            # 删除对象（写）

Mixin：
  AccessMixin
    ├─ LoginRequiredMixin          # 必须登录
    ├─ PermissionRequiredMixin     # 必须有指定权限
    └─ UserPassesTestMixin         # 自定义 test_func 返回 True
  ContextMixin                     # get_context_data
  TemplateResponseMixin             # render_to_response / template_name
  SingleObjectMixin                # get_object / get_context_object_name
  MultipleObjectMixin              # get_queryset / paginate_by
  FormMixin                        # form_valid / form_invalid / get_success_url
  ModelFormMixin                   # 从 model+fields 生成 ModelForm
  ProcessFormView                  # get/post 处理表单
```

**关键认知**：`ListView = MultipleObjectMixin + TemplateResponseMixin + View`，`DetailView = SingleObjectMixin + TemplateResponseMixin + View`，`CreateView = SingleObjectTemplateResponseMixin + ModelFormMixin + ProcessFormView`。通用视图是"Mixin 拼装"出来的，因此可以自由组合。

## 八个通用速查（含默认值）

下表是生产中最常用的速查表。模型小写名记为 `<model>`（来自 `model._meta.model_name`，全小写），app 名为 `<app>`（来自 `model._meta.app_label`）：

| 通用视图 | 默认模板 | 默认上下文变量 | URL 参数 | 关键属性/方法 |
|---|---|---|---|---|
| `TemplateView` | 必须显式给 `template_name` | 无默认 | 无 | `template_name`、`get_context_data` |
| `RedirectView` | 无（直接 301/302） | 无 | 无 | `url`、`pattern_name`、`permanent`、`query_string` |
| `DetailView` | `<app>/<model>_detail.html` | `<model>`（即 `self.object`） | `pk`（或 `slug`） | `model`/`queryset`、`get_object()` |
| `ListView` | `<app>/<model>_list.html` | `<model>_list`（别名 `object_list`） | 无 | `model`/`queryset`、`paginate_by`、`get_queryset()` |
| `FormView` | 需显式 `template_name` | `form` | 无 | `form_class`、`success_url`、`form_valid()` |
| `CreateView` | `<app>/<model>_form.html` | `form`、`object`、`<model>` | 无 | `model`+`fields` 或 `form_class`、`success_url` |
| `UpdateView` | `<app>/<model>_form.html` | `form`、`object`、`<model>` | `pk`（或 `slug`） | 同 Create，自动绑定 `instance=obj` |
| `DeleteView` | `<app>/<model>_confirm_delete.html` | `object`、`<model>` | `pk`（或 `slug`） | `model`、`success_url`（**必填**） |

> 模板名可被 `template_name` 覆盖；上下文变量名可被 `context_object_name` 覆盖；URL 参数名默认 `pk`，想用 `slug` 需设 `slug_field` 与 `slug_url_kwarg`。这些默认值的推导细节见「CBV 的魔法与进阶」一篇。

## 模板放哪：标准目录结构是前提

`template_name`（以及通用视图自动推导的默认模板名）**要能生效，前提是采用 Django 的标准模板目录结构**：每个 app 的模板放在它自己的 `templates/` 目录下、且再套一个与 app 同名的子目录（即 `templates/<app>`）：

```
<app>/
└── templates/
    └── <app>/              # 标准结构：templates 下套一个与 app 同名的子目录
        ├── <model>_list.html
        ├── <model>_detail.html
        └── <model>_form.html
```

只有按这个结构放，`template_name = '<app>/<model>_list.html'` 才能对应到实际文件 `<app>/templates/<app>/<model>_list.html`。

为什么套一层 app 名：多个 app 都可能有 `base.html`、`index.html` 这类常见文件名，用 app 名做命名空间子目录，避免模板互相覆盖。

### 各通用视图的默认模板名

通用视图不写 `template_name` 时，默认模板名由**模型小写名 + 视图后缀**拼出（前缀 `<app>/` 是命名空间子目录）：

| 通用视图 | 默认模板名 | 说明 |
|---|---|---|
| `ListView` | `<app>/<model>_list.html` | 列表页 |
| `DetailView` | `<app>/<model>_detail.html` | 详情页 |
| `CreateView` | `<app>/<model>_form.html` | 新建表单页 |
| `UpdateView` | `<app>/<model>_form.html` | 编辑表单页（与 Create 共用） |
| `DeleteView` | `<app>/<model>_confirm_delete.html` | 删除确认页 |
| `FormView` | 无默认（须显式 `template_name`） | —— |
| `TemplateView` | 无默认（必须显式） | —— |

`<model>` 是模型类名全小写（`model._meta.model_name`），如模型 `Topic` 则 `<model>` 即 `topic`。

## 读视图：ListView 与 DetailView

### ListView 列表页

```python
class TopicListView(generic.ListView):
    """Generic class-based view for a list of topics."""
    model = Topic
    paginate_by = 10
```

自动做的事：`Topic.objects.all()` → 分页（每页 10 条）→ 渲染 `<app>/topic_list.html`，上下文提供 `topic_list` 与 `object_list`（两者等价）。

最简模板（`<app>/templates/<app>/topic_list.html`）：

```html
<!-- <app>/topic_list.html -->
<ul>
  {% for topic in topic_list %}
    <li>{{ topic.text }}</li>
  {% endfor %}
</ul>
```

`{% for topic in topic_list %}` 遍历默认注入的 `topic_list`（等价 `object_list`）。

### ListView 常用属性与方法

| 成员 | 作用 |
|---|---|
| `model` | 要列出的模型（与 `queryset` 二选一） |
| `queryset` | 自定义查询集（**优先级高于 `model`**） |
| `ordering` | 默认排序字段，如 `['-date_added']` |
| `paginate_by` | 每页条数，开启分页 |
| `allow_empty` | 列表为空时是否允许（默认 `True`；`False` 则 404） |
| `context_object_name` | 自定义列表在模板中的变量名 |
| `template_name` | 覆盖默认模板路径 |
| `get_queryset()` | 返回查询集（**最常用覆盖点**：过滤、排序、按用户隔离） |
| `get_context_data(**kwargs)` | 追加额外上下文（**必须 `super()`**） |

### 覆盖 get_queryset：按用户过滤

```python
class MyTopicsListView(LoginRequiredMixin, generic.ListView):
    """List topics owned by the current user."""
    model = Topic
    template_name = '<app>/my_topics.html'
    paginate_by = 10

    def get_queryset(self):
        return (
            Topic.objects.filter(owner=self.request.user)
            .order_by('-date_added')
        )
```

注意三点：
- `LoginRequiredMixin` 写在 `ListView` **左边**（继承顺序最左优先，Mixin 必须在前）。
- `self.request.user` 是当前登录用户，在 `get_queryset` 里可以直接用。
- `get_queryset` 返回一个 QuerySet，不要返回 list。

### 覆盖 get_context_data：追加数据

```python
class TopicListView(generic.ListView):
    model = Topic
    paginate_by = 10

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)   # ★ 必须先调 super()
        context['entry_count'] = Entry.objects.count()
        return context
```

**铁律**：覆盖 `get_context_data` 时必须调用 `super()` 并把它返回的 dict 作为基础，再追加自己的键；否则默认的 `topic_list`、`page_obj`、`paginator` 全部丢失。

### DetailView 详情页

```python
from django.views import generic
from .models import Topic

class TopicDetailView(generic.DetailView):
    """Generic class-based detail view for a topic."""
    model = Topic
```

URLconf 里必须带主键转换器：

```python
path('topics/<int:pk>/', TopicDetailView.as_view(), name='topic'),
```

`DetailView` 自动完成：

1. 从 URL 捕获的 `pk` 查 `Topic.objects.get(pk=...)`（找不到抛 404）；
2. 把对象放入 context，键名 `topic`（＝`object`，来自模型小写名）；
3. 渲染 `<app>/topic_detail.html`（默认模板拼装）。

对应的最简模板（放在 `<app>/templates/<app>/topic_detail.html`）：

```html
<!-- <app>/topic_detail.html -->
<h1>{{ topic.text }}</h1>
<p>创建于：{{ topic.date_added }}</p>
```

`{{ topic }}` 来自 DetailView 默认注入的 context 键（＝`object`）。

## 写视图：CreateView / UpdateView / DeleteView

这三件套合起来叫 **edit views**。只需声明 `model + fields`，Django 自动生成 ModelForm、处理 GET/POST、校验、保存、跳转。

### 真实示例

```python
from django.views.generic.edit import CreateView, UpdateView, DeleteView
from django.urls import reverse_lazy
from django.contrib.auth.mixins import LoginRequiredMixin
from .models import Topic

class TopicCreate(LoginRequiredMixin, CreateView):
    """Create a new topic."""
    model = Topic
    fields = ['text']
    success_url = reverse_lazy('learning_logs:topics')

    def form_valid(self, form):
        form.instance.owner = self.request.user   # 注入当前登录用户
        return super().form_valid(form)

class TopicUpdate(LoginRequiredMixin, UpdateView):
    """Update an existing topic."""
    model = Topic
    fields = ['text']

class TopicDelete(LoginRequiredMixin, DeleteView):
    """Delete a topic."""
    model = Topic
    success_url = reverse_lazy('learning_logs:topics')
```

要点：
- `fields` 是白名单；`'__all__'` 不推荐（新增字段会自动暴露）。
- `initial` 给表单字段预填初始值。
- `DeleteView` **必须**给 `success_url`（或模型定义 `get_absolute_url` 并靠 `get_success_url` 兜底）。
- 上面的 `TopicCreate.form_valid` 覆盖用来在保存前注入外键 `owner`（见下方"form_valid：保存前注入外键"）。

Create/Update 共用同一个 `_form` 模板（`<app>/templates/<app>/topic_form.html`）：

```html
<!-- <app>/topic_form.html -->
<form method="post">
  {% csrf_token %}
  {{ form.as_p }}
  <button type="submit">保存</button>
</form>
```

DeleteView 用 `_confirm_delete` 模板（`<app>/templates/<app>/topic_confirm_delete.html`），确认页里能访问 `{{ topic }}`：

```html
<!-- <app>/topic_confirm_delete.html -->
<form method="post">
  {% csrf_token %}
  <p>确定删除主题 "{{ topic.text }}" 吗？</p>
  <button type="submit">确认删除</button>
</form>
```

### 三件套对照表

| 视图 | 默认模板 | 上下文 | URL 参数 | 保存后跳转 |
|---|---|---|---|---|
| `CreateView` | `<app>/<model>_form.html` | `form`、`object`、`<model>` | 无 | `success_url`，否则模型的 `get_absolute_url()` |
| `UpdateView` | `<app>/<model>_form.html` | `form`、`object`、`<model>` | `pk`/`slug` | 同 Create |
| `DeleteView` | `<app>/<model>_confirm_delete.html` | `object`、`<model>` | `pk`/`slug` | **必须** `success_url` |

### 决定保存后去哪：success_url 的四种姿势

| 方式 | 说明 |
|---|---|
| 类属性 `success_url = reverse_lazy('learning_logs:topics')` | 固定跳转（`reverse_lazy` 在 URLconf 加载前可用，比 `reverse` 安全） |
| 模型定义 `get_absolute_url()` | 不写 `success_url` 时，Create/Update 默认跳详情页 |
| 覆盖 `get_success_url()` | 动态跳转，可根据 `self.object` 决定 |
| 覆盖 `form_valid(form)` | 保存前后插入自定义逻辑（如发邮件、写日志） |

### form_valid：保存前注入外键

这是 CBV 里最常用的覆盖点——表单里不应该出现"由系统决定的字段"（如当前用户、所属对象），要在保存前塞进 `form.instance`：

```python
class TopicCreateView(LoginRequiredMixin, CreateView):
    model = Topic
    fields = ['text']
    success_url = reverse_lazy('learning_logs:topics')

    def form_valid(self, form):
        form.instance.owner = self.request.user   # 注入当前登录用户
        return super().form_valid(form)           # 父类负责 save() 与 redirect
```

对比 FBV 里的 `new_topic.owner = request.user; new_topic.save()`，逻辑等价，只是换成了面向对象写法。

## FormView：不落库的表单处理

当表单处理**不直接对应模型 CRUD** 时用 `FormView`（例如联系我们、搜索、一次性审批）。

```python
from django.views.generic import FormView
from django.shortcuts import get_object_or_404
from django.urls import reverse
from .forms import EntryForm
from .models import Topic, Entry


class QuickEntryView(FormView):
    form_class = EntryForm
    template_name = '<app>/quick_entry.html'

    def form_valid(self, form):
        entry = form.save(commit=False)
        entry.topic = get_object_or_404(Topic, pk=self.kwargs['pk'])
        entry.save()
        return super().form_valid(form)

    def get_success_url(self):
        return reverse('learning_logs:topic', args=[self.kwargs['pk']])
```

`FormView` 只负责"展示表单 + 校验 + 调用 `form_valid`"，**不负责 save**，落库逻辑要自己写（这里手动注入外键 `topic` 并保存）。

对应的最简模板（`<app>/templates/<app>/quick_entry.html`）：

```html
<!-- <app>/quick_entry.html -->
 <form method="post">
  {% csrf_token %}
  {{ form.as_p }}
  <button type="submit">提交</button>
</form>
```

## TemplateView 与 RedirectView

### TemplateView：只渲染模板

最简单的 CBV，适合首页、关于页等静态页：

```python
from django.views.generic import TemplateView


class AboutView(TemplateView):
    template_name = 'about.html'

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['latest_posts'] = Post.objects.all()[:5]
        return context
```

最简模板（`templates/about.html`，放在 `DIRS` 指向的项目级模板目录）：

```html
<!-- about.html -->
<h1>关于本站</h1>
<p>共 {{ latest_posts|length }} 篇最新文章。</p>
```

### RedirectView：重定向

| 属性 | 作用 |
|---|---|
| `url` | 硬编码目标 URL |
| `pattern_name` | 按 URLconf name 反向解析 |
| `permanent` | `True` 发 301，`False` 发 302（默认） |
| `query_string` | 是否把原查询串透传到目标（默认 `False`） |

```python
from django.views.generic import RedirectView

path('old-about/', RedirectView.as_view(pattern_name='about', permanent=True)),
```
