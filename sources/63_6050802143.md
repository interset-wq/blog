
## 一、对象：屏幕之外还有更多数据

运行 `Get-Process`，你会看到一个多列表格。但这些信息仅仅是关于进程的**冰山一角**。进程对象还包括机器名、主窗口句柄、最大工作集大小、退出代码和时间、处理器掩码等大量信息——实际上可以找出超过 60 个与进程相关的信息。

pwsh 只展示少量信息，原因很简单：屏幕上放不下更多内容。

> [!NOTE]
> 当运行任意命令（`Get-Process`、`Get-Service` 等）时，pwsh 会在内存中**完全构造**用于容纳所有项信息的表格。例如 `Get-Process` 的表格由 67 列组成，每行对应一个运行中的进程，每列包含一部分信息（虚拟内存、CPU 利用率、进程 ID 等）。
>
> 之后 pwsh 检查你是否指定了想查看的列；若未指定，它会查看微软提供的配置文件，只显示微软认为你希望查看的列。

### 查看所有列的方式

一种方式是用 `ConvertTo-Html`：

``` pwsh
Get-Process | ConvertTo-Html | Out-File processes.html
```

该命令不过滤列，而是生成包含**所有列**的 HTML 文件。

除了列信息，表中每一行还对应一些**方法**——操作系统能以进程为目标执行的操作，例如关闭进程、杀死进程、刷新信息、等待进程退出等。

### 管道传输的是整个表

每当命令产生结果，输出在内存中以「表」的形式存放。当输出经管道传给另一条命令时，例如 `Get-Process | ConvertTo-HTML`，整个表都会通过管道传输——在传输过程中**不会过滤成一小部分列**，直到所有命令运行完后才过滤。

## 二、术语：pwsh 怎么称呼这些「表」

pwsh 并不把这些内存中的表命名为「表」，而是使用以下 4 个术语：

| 术语 | 对应 | 含义 |
|---|---|---|
| **对象（Object）** | 表行 | 代表单个事物，如单个进程或单个服务 |
| **属性（Property）** | 表列 | 代表对象的一部分信息，如进程名、进程 ID、服务状态 |
| **方法（Method）** | 行为 | 与对象关联并让对象完成某些任务，如杀死进程、启动服务 |
| **集合（Collection）** | 整张表 | 对象的集合 |

## 三、为什么 pwsh 使用对象

pwsh 用**对象**代表数据，有两个原因：

1. **Windows 本身是面向对象的操作系统**，大部分 Windows 软件也是面向对象的。以对象集合的方式组织数据非常自然，因为大多数系统都适用这种结构。
2. **让事情更简单，更强大、更灵活**。无论窗口调整成什么大小，都能美观地把结果输出到控制台。

### 对象消除了文本操作开销

对象的工作机制类似内存中的表，因此你无需告诉 pwsh 信息所在的文本位置，只需输入**列名**。无论输出结果在屏幕或文件中如何组织，pwsh 都知道去哪里获取数据——内存表总是同一个，因此你永远不需要因为移动列而重写命令。这样你能更专注于实现功能，而不是不必要的开销。

> - Linux / UNIX 是基于文本的操作系统，文本对它们意义重大。
> - Windows 不是基于文本、而是基于 API 的操作系统，重度依赖对象模型。因此 pwsh 以更原生（object-oriented）的方式与 Windows 协作。

## 四、探索对象：Get-Member

对象就像内存中巨大的表，而 pwsh 只展示其中一部分——有些你需要用的属性可能没有显示在屏幕上。

要了解更多关于对象的内容，使用命令 `Get-Member`（别名 `Gm`）。可以在任何产生输出的命令之后使用 Gm：

``` pwsh
pwsh> Get-Process | gm
```

输出会列出该对象的所有成员（属性、方法、事件、别名属性、脚本属性等）。

### 成员（Member）是什么

一个对象的属性、方法以及其他附加到对象的东西，都称为**成员**。这也是 `Get-Member` 名称的由来——它获取对象成员的列表。pwsh 的惯例是使用单数名词，所以 cmdlet 名称是 `Get-Member`。

### 管道中的对象全程可访问

当一个 cmdlet 产生对象的集合时（如 `Get-Process`），整个集合直到管道末尾之前都可以访问。在所有命令运行完之前，pwsh 不会把对象的属性过滤掉；直到最后一个命令运行完，才会创建你看到的文本输出。

在上面的例子中，Gm 可以完整访问进程对象的属性和方法，正是因为这个命令还未被过滤用于显示。Gm 会查看每一个对象，并构建包含对象属性和方法的列表。

## 五、使用对象标签：属性（Property）

查看 Gm 输出，你会注意到几种不同的属性：**脚本属性、属性、NoteProperty、别名属性**。

.NET Framework 中的对象（所有 pwsh 对象的来源）通常只包含「属性」。pwsh 会动态添加其他内容：ScriptProperty、NoteProperty、AliasProperty 等。pwsh 有一个**扩展类型系统（ETS）**负责添加这些属性，使对象具有更好的一致性——比如为原本只有 `ProcessName` 属性的对象添加 `Name` 属性（别名属性的作用）；或者暴露对象中隐藏的信息（进程对象用脚本属性完成这项工作）。

> [!NOTE]
> 在 pwsh 的世界里，这些属性的行为都会变得一致。但如果这些属性没有出现在官方文档页面中，也不必惊讶：Shell 自动添加的额外属性，通常会让你工作更轻松。

**属性总是包含一个值**。例如，进程对象的 ID 属性可能是 `1234`，Name 属性的值可能是 `Notepad`。属性用于描述对象的某方面：状态、ID、名称等。

> [!IMPORTANT]
> pwsh 中的属性通常是**只读**的——你无法通过给 Name 属性赋新值来改变服务的名称，但可以通过读取 Name 属性获取服务名称。

## 六、对象行为：方法（Method）

很多对象支持一个或多个方法，指导对象的行为。例如，进程对象包含一个 `Kill` 方法，用于终止进程。

某些方法需要一个或多个输入参数来提供额外的细节信息，这些方法与 cmdlet 可以互相替代。

例如，终止一个进程有三种办法：

``` pwsh
# 办法1：获取对象并传给 Stop-Process cmdlet
pwsh> Get-Process -Name Notepad | Stop-Process

# 办法2：用单个 cmdlet 完成
pwsh> Stop-Process -name Notepad
```

### 事件（Event）

除了属性和方法，对象还有一个**事件**。事件以对象的方式通知你某些事情发生了。例如，进程对象可以在进程结束时触发 `Exited` 事件。你可以把自己的命令附加到这些事件上——比如进程结束时发送一封邮件。

## 七、排序对象：Sort-Object

大部分 pwsh cmdlet 以确定性的方式产生对象，即每次运行都以相同顺序产生。例如服务和进程按名称字母表排序，事件日志按事件排序。我们可以改变排序方式。

假设希望按虚拟内存（Virtual Memory，VM）消耗**由高到低**显示进程列表：

``` pwsh
# 按 VM 升序排序（最大值在底部，可能不是想要的）
Get-Process | Sort-Object -property VM
```

该命令按 VM 排序，但默认是**升序**。`Sort-Object` 提供 `-descending` 参数反转排序；`-property` 是位置参数，可省略参数名；`Sort-Object` 的别名是 `Sort`：

``` pwsh
pwsh> Get-Process | Sort VM -desc
```

这里把 `-descending` 简化为 `-desc`，仍能得到想要的结果。`-property` 参数接受多个值——为了防止两个进程虚拟内存相同，还可按进程 ID 排序：

``` pwsh
Get-Process | Sort VM, ID -desc
```

和之前一样，通过以逗号分隔列表的方式，把多个值传给任意支持多个值的参数。

## 八、选择所需的属性：Select-Object

另一个有用的 cmdlet 是 `Select-Object`。它从管道接受对象，让你指定希望显示的属性。这样你可以访问任意属性、减少返回列表、只返回感兴趣的列，而不受默认配置规则控制。这对输出到 HTML 的 `ConvertTo-HTML` 尤其有用（该 cmdlet 通常创建包含所有属性的表）。

比较下面两条命令的结果：

``` pwsh
> Get-Process | ConvertTo-HTML | Out-File test1.html
> Get-Process | Select-Object -property Name, ID, VM, PM | ConvertTo-HTML | Out-File test2.html
```

`test2.html` 只显示 `Name`、`ID`、`VM`、`PM` 这几列。

`Select-Object` 的别名是 `Select`，`-property` 是位置参数，可以缩短命令：

``` pwsh
> Get-Process | select Name, Id, vm, pm | ConvertTo-Html | Out-File test3.html

# 直接在屏幕展示
> Get-Process | select Name, id, vm, pm
```

### Select-Object 的 First / Last 参数

`Select-Object` 还有 `-First` 和 `-Last` 参数，只显示列表的前几项或后几项：

``` pwsh
> Get-Process | select -First 10
```

这会保留前 10 个对象。但**不能加过滤条件**（比如选择特定进程），只能选择前（或最后）10 个。

### Select-Object 与 Where-Object 的区别

这两个命令容易搞混：

- `Select-Object`：选择所需的**属性（列）**，也可以用 `-First` / `-Last` 选择输出行的任意子集。
- `Where-Object`：基于筛选条件，从管道中**移除或过滤对象**。

## 九、命令结束之前，管道里始终是对象

pwsh 管道在最后一个命令执行之前总是传递对象。在最后一个命令执行时，pwsh 查看管道中的对象，根据配置文件决定哪些属性用于构建显示结果，并基于内部规则和配置文件确定展示为表还是列表。

在一个命令行中，管道可以包含不同类型的对象。管道之后可以换行提交代码、提高可读性——换行后命令提示符变成 `>>`：

``` pwsh
> Get-Process |
>> Sort-Object vm -Descending |
>> Out-File procs.txt
```

上面代码先运行 `Get-Process`，把进程对象放入管道；接着 `Sort-Object` 不改变管道内容，只改变对象顺序，管道仍只有进程；最后 `Out-File` 生成输出——管道中的进程对象，并按内部规则格式化后写入文件。

再看一个会**改变对象类型**的例子：

``` pwsh
> Get-Process |
>> Sort-Object vm -Descending |
>> Select-Object Name, Id, vm
```

`Get-Process` 把进程对象放入管道，`Sort-Object` 仍把同样的进程对象放入管道。但 `Select-Object` 有所不同：进程对象总是拥有相同成员，`Select-Object` 并不能通过删除不需要的属性来减少属性列表——如果那样做，结果就不再是进程对象了。实际上 `Select-Object` 会创建一个名为 **PSObject** 的自定义对象，把属性从进程对象中复制出来，结果是自定义对象被放入管道。

当 pwsh 到达命令行结尾时，它必须知道如何排版文本输出。因为管道中不再是进程对象，pwsh 不会再把默认规则和配置应用于进程对象，而是查询 PSObject 的规则和配置。由于 PSObject 用于自定义输出，微软没有为它提供任何规则或配置，pwsh 只能尽最大努力猜测并产生表格——理论上能容纳那 3 列，但表格不像正常的 `Get-Process` 输出那样美观，因为缺少让表格更美观的额外配置信息。

### 用 Gm 验证管道中的对象类型

记住，可以在任何产生输出的 cmdlet 之后使用 Gm：

``` pwsh
> Get-Process | Sort VM -descending | gm
> Get-Process | sort vm -Descending | select Name, Id, VM | gm
```

第二个例子的输出会显示对象类型名为 `Selected.System.Diagnostics.Process`，只包含 3 个指定属性（Name、ID、VM）及一些系统生成的成员——这正是 Select-Object 创建的「经过筛选」的自定义对象。

pwsh 会把管道中对象的类型名称作为 Gm 输出的一部分。即使 Gm 产生对象并将对象放入管道，运行 Gm 之后管道也不再包含进程对象或「经过筛选」的对象，而是只包含 Gm 生成的对象类型 `Microsoft.PowerShell.Commands.MemberDefinition`。可以通过对 Gm 的输出再次使用 Gm 验证：

``` pwsh
> Get-Process | gm | gm
```

流程：`Get-Process` 把进程对象放入管道 → `Gm` 分析进程对象并生成 MemberDefinition 对象 → 再次传给 `Gm` → 分析并产生 MemberDefinition 的成员列表作为输出。

## 十、核心总结

1. **对象**是 pwsh 数据的核心形态：运行命令时，pwsh 在内存中构造完整的对象集合，屏幕只显示其中一部分。
2. 对象由**属性**（描述）、**方法**（行为）、**事件**（通知）构成；pwsh 通过**扩展类型系统（ETS）**动态添加属性。
3. `Get-Member`（Gm）用于查看对象的所有成员；`Sort-Object` 排序；`Select-Object` 选择属性（`-First` / `-Last` 取子集）；`Where-Object` 过滤对象。
4. 管道在最后一个命令之前始终传递对象；`Select-Object` 会产生自定义对象 PSObject，从而改变管道中的对象类型，影响最终排版效果。
