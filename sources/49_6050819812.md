
## 系统服务

系统服务又称**守护程序（Daemon）**，常驻内存提供系统或网络功能。服务启动得越多，占用资源越多、被攻击面越大，安装后应做**服务优化**（关闭不需要的，只开需要的）。

守护程序分两类：

| 类型 | 特点 |
|---|---|
| StandAlone（独立服务） | 常驻内存持续提供服务，响应快，如 `httpd`、`sshd` |
| SuperDaemon（总管服务） | 有请求才由总管唤醒，连接结束即关闭，省资源、可做安全管控，但响应慢 |

## systemd 与 systemctl

现代主流发行版（Ubuntu、RHEL、CentOS 均）用 **systemd** 管理系统服务，`systemctl` 是控制命令。

```bash
$ systemctl start nginx       # 启动
$ systemctl stop nginx        # 停止
$ systemctl restart nginx     # 重启
$ systemctl status nginx      # 查看状态
$ systemctl enable nginx      # 开机自启
$ systemctl disable nginx     # 关闭开机自启
$ systemctl is-active nginx   # 是否运行（返回 active/inactive）
$ systemctl list-units --type=service   # 列出所有服务
```

> 旧版红帽系的 `service` / `chkconfig`：`service httpd start`、`chkconfig httpd on`。现代系统已统一到 systemctl。

## systemd 单元文件

服务定义在 unit 文件中（`/etc/systemd/system/` 或 `/lib/systemd/system/`）：

```ini
[Unit]
Description=My App
After=network.target

[Service]
ExecStart=/usr/local/bin/myapp
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
$ sudo systemctl daemon-reload      # 修改 unit 后重载
$ sudo systemctl enable myapp
$ sudo systemctl start myapp
```

## 查看日志

绝大多数系统日志由 **rsyslogd** 统一管理，日志文件位于 `/var/log/`。

```bash
$ tail -f /var/log/syslog      # Ubuntu 系统日志
$ tail -f /var/log/auth.log    # Ubuntu 认证/登录日志
$ ls /var/log/                 # 查看所有日志
```

systemd 统一日志服务 **journald**，用 `journalctl` 查询：

```bash
$ journalctl -u nginx          # 查看某服务的日志
$ journalctl -u nginx -f       # 实时跟踪
$ journalctl --since today     # 今天以来的日志
$ journalctl -p err            # 只查错误级别
$ journalctl -b                # 本次启动以来的日志
```

## rsyslog 配置

`rsyslogd` 依赖配置文件 `/etc/rsyslog.conf` 及 `/etc/rsyslog.d/`，决定各服务不同级别的日志写到哪里。

| 级别（由高到低） | 含义 |
|---|---|
| emerg / alert / crit | 严重错误 |
| err | 错误 |
| warning | 警告 |
| info | 一般信息 |
| debug | 调试信息 |

## 常见服务排查流程

1. `systemctl status 服务` 看状态与最近报错。
2. `journalctl -u 服务 -n 50` 看最近 50 条日志。
3. `tail -f /var/log/syslog` 实时观察。
4. 检查端口监听：`ss -tulnp | grep 端口`。
