
# Node.js 简介、模块系统与 npm

## 什么是 Node.js

**Node.js** 是一个开源的、跨平台的 JavaScript 运行时环境，允许你在浏览器之外运行 JavaScript 代码。它被广泛用于构建 Web 服务器、API 和后端系统。

## 客户端 JS 的局限性（为什么需要后端运行时）

客户端（浏览器）中的 JavaScript 存在诸多限制：

- **受限的文件系统访问**：浏览器 JS 无法自由读写本地文件。
- **复杂应用逻辑支持有限**：不适合承载重量级业务逻辑。
- **安全风险**：例如绝不能在客户端代码中暴露数据库凭据。

## 浏览器 vs Node.js 的全局对象

| 维度 | 浏览器 | Node.js |
| --- | --- | --- |
| 全局对象 | `window` | `global` |
| 暴露能力 | DOM 操作、Cookie、浏览器事件 | 文件、网络、操作系统交互的内置模块 |
| DOM 访问 | ✅ 提供 DOM API | ❌ 不提供 |
| 系统资源访问 | ❌ 不可访问文件系统 | ✅ 可访问几乎所有系统资源 |

## 版本控制

- 你可以**自由选择**服务器上运行的 Node 版本。
- 你**无法控制**用户运行的是哪个浏览器版本。

## 非阻塞、事件驱动架构

Node 采用**单线程 + 事件循环**模型：

- 用单线程和事件循环高效处理大量并发请求与 I/O 操作。
- **不会阻塞**，非常适合实时应用（如聊天、实时数据推送）。

### 回调（Callback）

**回调**是定义「异步操作完成后要做什么」的函数。

- 对回调的严重依赖，是 Node 异步代码较难阅读和调试的原因之一。

## Node.js 在后端的优劣势

### 优势

- **单一语言**：前后端统一使用 JavaScript。
- **非阻塞架构**：适合高并发场景。
- **庞大的 npm 生态**：海量现成包可用。
- **免费开源**。

### 劣势

- **单线程**：CPU 密集型任务（图像处理、加密、复杂数学计算）会阻塞事件循环。
- **重度依赖异步/回调代码**：可读性下降。
- **npm 包质量参差**：维护状况不一。

## NVM（Node Version Manager）

用于在同一台机器上管理、切换多个 Node.js 版本。

| 操作 | 命令 |
| --- | --- |
| 安装（macOS/Linux） | `curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh \| bash` |
| 安装 LTS 版本 | `nvm install --lts` |
| 切换版本 | `nvm use 20` |
| 列出已安装版本 | `nvm ls` |
| 设置默认版本 | `nvm alias default 22.20.0` |

> **nvm-windows**：是独立项目（非 WSL），用于 Windows 管理 Node 版本。从官方仓库下载安装器后，运行 `nvm install lts` 再 `nvm use <version>`。

## 模块系统

### CommonJS（原始模块系统）

- 同步加载模块。
- **导入**用 `require()`：

```js
const { multiply } = require("./math");
```

- **导出**用 `module.exports`：

```js
function multiply(a, b) {
  return a * b;
}
module.exports = { multiply };
```

- 默认启用条件：`package.json` 中 `"type": "commonjs"`（或无 `"type"` 字段），或文件扩展名为 `.cjs`。

### ES Modules（ESM，现代标准）

- 异步加载模块。
- **具名导出**：

```js
export function multiply(a, b) {
  return a * b;
}
```

- **默认导出**：

```js
export default function multiply(a, b) {
  return a * b;
}
```

- **导入**：

```js
import { multiply } from "./math.mjs";
```

- 启用条件：文件扩展名为 `.mjs`，或 `package.json` 包含 `"type": "module"`。

### CommonJS 与 ESM 文件混用

```js
// math.cjs —— CommonJS
function add(a, b) {
  return a + b;
}
module.exports = { add };

// main.cjs —— CommonJS 导入
const { add } = require("./math.cjs");
console.log(add(1, 2)); // 3
```

```js
// math.mjs —— ES Module
export function add(a, b) {
  return a + b;
}
export default function sub(a, b) {
  return a - b;
}

// main.mjs —— ESM 导入
import sub, { add } from "./math.mjs";
console.log(add(1, 2), sub(5, 3)); // 3 2
```

### 对比总结

| 维度 | CommonJS | ESM |
| --- | --- | --- |
| 加载方式 | 同步 | 异步 |
| 导入/导出 | `require` / `module.exports` | `import` / `export` |
| 启用条件 | `"type": "commonjs"` 或无字段、`.cjs` | `"type": "module"`、`.mjs` |

## npm 简介

npm 由三部分组成：

1. **网站** `npmjs.com`
2. **公共注册表**（Registry）：包数据库
3. **CLI 工具**：随 Node.js 安装

**用途**：安装、管理和发布可复用的 JavaScript 包。npm 是最广泛使用的包管理器。

**替代品**：Yarn、PNPM、Bun。

## `package.json` 文件

npm 的**配置清单**（manifest）。记录项目名称、版本、描述、入口点（`main`）、作者、许可证、脚本和依赖。

| 操作 | 命令 |
| --- | --- |
| 交互式创建 | `npm init` |
| 默认值创建 | `npm init -y` |

### 依赖类型

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `dependencies` | 生产环境运行所需的包 | `express`、`react` |
| `devDependencies` | 仅开发/测试需要 | `jest`、`nodemon`、`eslint` |

### `license` 许可证

定义使用条款。常见值：`MIT`、`ISC`、`GPL`。

## 语义化版本（SemVer）

**格式**：`MAJOR.MINOR.PATCH`，例如 `4.17.21`。

| 部分 | 何时递增 |
| --- | --- |
| MAJOR（主版本） | 破坏性变更 |
| MINOR（次版本） | 向后兼容的新功能 |
| PATCH（补丁） | 向后兼容的 bug 修复 |

### 版本范围前缀

| 前缀 | 含义 | 示例 |
| --- | --- | --- |
| `^`（脱字符） | 允许更新 minor 和 patch，**不**允许 major | `^4.17.21` 接受 `4.18.0`，不接受 `5.0.0` |
| `~`（波浪号） | 仅允许更新 patch | `~1.2.3` 接受 `1.2.4`，不接受 `1.3.0` |
| `*`（星号） | 匹配任意版本，仅适合测试，绝不用在生产 | — |
| 无前缀（精确） | 精确锁定版本 | `1.2.3` 仅此版本 |

### SemVer 前缀的实际效果

```bash
# 假设 package.json 中: "express": "^4.17.21"
npm install            # 会更新到 4.x.x 最新（如 4.19.2），但不会到 5.x
npm update express     # 在 ^4.17.21 允许范围内更新到最新
npm install express@latest  # 无视范围，强制安装最新（可能到 5.x）
```

## 安装与移除依赖

| 操作 | 命令 |
| --- | --- |
| 安装包 | `npm install express`（简写 `npm i express`） |
| 作为 devDependency 安装 | `npm install nodemon -D` |
| 卸载包 | `npm uninstall chalk` |
| 安装指定版本 | `npm install express@4.21.2` |
| 查看可用版本 | `npm view express versions` |
| 检查过期包 | `npm outdated` |
| 更新单个包（在允许范围内） | `npm update express` |
| 强制安装最新版 | `npm install express@latest` |

### 重要文件

- **`node_modules/`**：安装后存放实际包代码的文件夹，**不提交**到版本控制。
- **`package-lock.json`**：锁定每个已安装包（含子依赖）的精确版本，自动生成。**始终提交，不要手动编辑**。

## 发布到 npm

| 操作 | 命令 |
| --- | --- |
| 登录 | `npm login` |
| 作用域包（避免命名冲突） | `@username/package-name` |
| 发布非作用域包 | `npm publish` |
| 公开发布作用域包 | `npm publish --access public` |

- **`.npmignore`**：列出发布时排除的文件（类似 `.gitignore`）。

## npm Scripts（脚本）

**作用**：在 `package.json` 的 `"scripts"` 对象中定义自定义命令，自动化重复任务（启动服务器、测试、lint、构建）。

### 定义脚本

```json
"scripts": {
  "start": "node app.js"
}
```

### 运行脚本

| 场景 | 命令 |
| --- | --- |
| 运行自定义脚本 | `npm run start` |
| 内置脚本名简写（`start`/`test`/`stop`/`restart`） | `npm start` |

### 组合命令

```json
// 顺序执行（前者成功才执行后者）
"start": "npm run build && node server.js"

// 顺序执行（后者始终执行）
"start": "npm run build; node server.js"

// 并发执行
"dev": "npm run start:server & npm run start:client"
```

### 传递参数

用 `--` 分隔符：`npm start -- 8000`；参数可通过 `process.argv[2]` 访问。

## 补充实战：完整代码示例

### 一个典型的 `package.json`

```json
{
  "name": "my-api",
  "version": "1.2.0",
  "description": "A small REST API",
  "main": "index.js",
  "type": "module",
  "license": "MIT",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest",
    "lint": "eslint .",
    "build": "node build.js",
    "deploy": "npm run build && npm run test && npm start"
  },
  "dependencies": {
    "express": "^4.21.0"
  },
  "devDependencies": {
    "nodemon": "^3.0.0",
    "jest": "^29.0.0"
  }
}
```

### 常用 npm 命令速查

```bash
npm init -y              # 快速初始化
npm i express            # 安装生产依赖
npm i -D nodemon         # 安装开发依赖
npm run dev              # 运行 dev 脚本
npm outdated             # 查看可更新依赖
npm ls --depth=0         # 查看顶层已装依赖
npm view express versions  # 查看远程可用版本
```
