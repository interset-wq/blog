
# 网络基础：客户端-服务器模型、DNS 与 HTTP

## 客户端-服务器模型

**客户端-服务器模型**：一种分布式系统架构，组件分为客户端与服务器。

- **客户端**：发送请求的进程（如 Web 浏览器）。
- **服务器**：接收请求并返回数据/服务的计算机或软件程序。

### 服务器类型

Web 服务器（HTML/CSS/静态资源）、应用服务器（业务逻辑）、数据库服务器、邮件服务器、文件服务器、代理服务器。

---

## DNS（域名系统）

常被称为"互联网的电话簿"：将人类可读的域名（如 `freecodecamp.org`）转换为 IP 地址。

### 域名层级（从右到左）

1. **顶级域名（TLD）**：如 `.org`
2. **二级域名**：如 `freecodecamp`
3. **子域名**：如 `www`

### IP 地址

设备在网络中的唯一数字标识。

- IPv4 示例：`127.0.0.1`
- IPv6 示例：`0:0:0:0:0:0:0:1`

### DNS 解析流程

浏览器 → 递归解析器 → 根服务器 → TLD 服务器 → 权威名称服务器 → 返回 IP 地址 → 递归解析器缓存并交付给客户端。

## TCP/IP 与 HTTP

### IP（网际协议）

- 使用 IP 地址将数据包从源路由到目的。
- **无连接**，每个包独立发送。

### TCP（传输控制协议）

- 将数据拆分为编号的段，在目的地重组。
- 检查错误，必要时请求重传。
- 保证**可靠、有序**的交付。

### HTTP / HTTPS

- **HTTP**：应用层协议，定义客户端和服务器如何交换 Web 内容。
- **HTTPS**：HTTP 的安全版本，使用 SSL/TLS 加密数据。

## HTTP 请求结构

```
GET / HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
Connection: keep-alive
```

| 部分 | 说明 |
| --- | --- |
| 请求行 | HTTP 方法 + 路径/URI + HTTP 版本 |
| 请求头（Headers） | 键值对形式的元数据 |
| 请求体（Body，可选） | 用 `POST`、`PUT`、`PATCH`、`DELETE` 携带数据 |

## HTTP 响应结构

```
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 105

<!DOCTYPE html>...
```

| 部分 | 说明 |
| --- | --- |
| 状态行 | HTTP 版本 + 状态码 + 原因短语 |
| 响应头 | 关于响应的元数据（内容类型、长度、缓存指令） |
| 响应体（可选） | 请求的数据 |

## HTTP 状态码分类

| 分类 | 含义 | 示例 |
| --- | --- | --- |
| 1xx 信息 | 请求已接收，处理继续 | `101 Switching Protocols` |
| 2xx 成功 | 请求成功 | `200 OK`、`201 Created`、`204 No Content` |
| 3xx 重定向 | 需要进一步操作 | `301 Moved Permanently`、`302 Found`、`304 Not Modified` |
| 4xx 客户端错误 | 请求有误 | `400 Bad Request`、`401 Unauthorized`、`403 Forbidden`、`404 Not Found` |
| 5xx 服务器错误 | 服务器处理出错 | `500 Internal Server Error`、`502 Bad Gateway`、`503 Service Unavailable` |

## HTTP 请求-响应模型

### HTTP 方法

| 方法 | 语义 |
| --- | --- |
| `GET` | 获取资源 |
| `POST` | 创建资源 |
| `PUT` | 完整更新 |
| `PATCH` | 部分更新 |
| `DELETE` | 删除资源 |

### 请求-响应周期

客户端发送请求 → 服务器校验认证、检查方法和 URL、查询数据库 → 服务器构建响应（状态码 + 可选 body）→ 客户端处理响应。

### HTTP 响应中的资源类型（Content-Type）

| 资源 | Content-Type |
| --- | --- |
| HTML | `text/html` |
| CSS | `text/css` |
| JavaScript | `application/javascript` |
| JSON | `application/json` |
| PNG / JPEG / WebP | `image/png` / `image/jpeg` / `image/webp` |
| MP4 / MP3 | `video/mp4` / `audio/mpeg` |
| PDF | `application/pdf` |
| WOFF2 | `font/woff2` |

## HTML 表单提交

- **`action` 属性**：指定表单数据发送的 URL。
- **`method` 属性**：指定 HTTP 方法（`GET` 或 `POST`）。
  - HTML **原生不支持** `PUT`、`PATCH`、`DELETE`，需用 Fetch API 或 Express 的 `method-override` 包。
- **客户端校验**：用 `required` 和 `pattern` 属性提供即时反馈。**始终也要在服务器端校验**。
- **`GET` 表单**：数据以查询参数追加到 URL（如搜索表单）。
- **`POST` 表单**：数据放在请求体（如登录、注册表单）。

## Web 标准概览

### 标准组织

| 组织 | 负责内容 |
| --- | --- |
| **WHATWG** | 维护 HTML 和 DOM 的"living standard"，由主要浏览器引擎团队（Chromium、Gecko、WebKit）驱动决策 |
| **W3C** | 主要标准组织，负责 CSS、SVG、可访问性指南（WCAG）及众多 Web API |
| **ECMA / TC39** | 发布官方 ECMAScript 规范；TC39 通过五阶段提案流程（Stage 0 雏形 → Stage 4 完全定稿）开发语言 |
| **Khronos Group** | 图形、计算和媒体。产出 WebGL、WebGL 2（GPU 加速的 3D 渲染） |

### 创建 Web 标准的流程

1. **识别需求**：开发者/组织遇到摩擦并记录下来。
2. **提案与早期讨论**：非正式 GitHub issue 或 explainer，试探兴趣（TC39 中为 Stage 0/1）。
3. **编写规范**：覆盖每个边界情况、错误条件和安全影响的精确正式文档。
4. **评审、反对与迭代**：浏览器厂商公开评审，主要浏览器拒绝实现的功能很少成为标准。
5. **实现与测试**：厂商在功能标志后实现，共享测试套件确保各浏览器行为一致。
6. **定稿**：W3C 称 Recommendation，TC39 称 Stage 4。

### Web 标准关键原则

- **开放性**：公开制定、免版税实现。
- **可访问性**：内置于 HTML、CSS 和浏览器行为，WCAG 提供正式指南。
- **互操作性**：符合标准的页面在所有浏览器中表现一致。
- **向后兼容**：旧页面在现代浏览器中仍能工作。
- **隐私与安全**：可能暴露用户数据的新 API 受到严格审查。
- **分层**：HTML 结构、CSS 表现、JavaScript 行为，各层可独立采用。
- **渐进增强**：先保证对所有人可用，再为更强大浏览器的用户增强。
