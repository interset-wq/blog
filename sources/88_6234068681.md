
## URLconf 工作原理

Django 收到请求后，按下面的流程分发：

```
浏览器 GET /topics/5/
  │
  ▼
MIDDLEWARE 链（Security → Session → Common → Csrf → Auth → ...）
  │
  ▼
URLconf 自上而下匹配 → path('topics/<int:topic_id>/', views.topic)
  │
  ▼
调用 views.topic(request, topic_id=5)
  │
  ├─ request.user 已由 Auth 中间件注入
  ├─ Topic.objects.get(id=5) 查库
  ├─ 越权检查失败 → raise Http404
  │
  ▼
render(request, 'topic.html', context) → 模板引擎渲染 HTML
  │
  ▼
HttpResponse(HTML) → MIDDLEWARE 反向链 → 浏览器
```


每个 app 维护自己的 `urls.py`，项目级 urls.py 用 `include()` 把各 app 的路由挂进来。

```python
from django.urls import path, re_path
from . import views

app_name = 'learning_logs'
urlpatterns = [
    # 1. 特殊路由：根路由（空字符串，匹配网站首页）
    path('', views.index, name='index'),
    # 2. 函数视图 FBV（无参数）：直接传视图函数
    path('topics/', views.topics, name='topics'),
    # 3. 函数视图 FBV + 路径转换器：<int:topic_id> 抽参后作为关键字参数传入
    path('topics/<int:topic_id>/', views.topic, name='topic'),
    # 4. 类视图 CBV：用 .as_view() 把类暴露给 URLconf
    path('topics/new/', views.TopicCreateView.as_view(), name='topic_new'),
    # 5. 正则路由 re_path：命名分组 (?P<name>...) 抽参（不常用，仅复杂匹配）
    re_path(r'^entries/(?P<entry_id>\d+)/delete/$', views.entry_delete, name='entry_delete'),
]
```

| 参数 | 作用 |
|---|---|
| `route` | URL 模式串，可用 `<转换器:变量名>` 抽取参数 |
| `view` | 视图函数（FBV）或 `CBV.as_view()`，也可以是 `include()` 的结果 |
| `name` | 路由别名：模板 `{% url %}` 与代码 `reverse()` 靠它反解 URL |

> 自上而下、首个命中即停：把更具体的路径写在前面。根路由 `''` 只匹配网站根 URL，不会吞掉其它路由，放前放后皆可。

## path() 与路径转换器

`route` 里的 `<转换器:变量名>` 会从 URL 里抽出一段，作为关键字参数传给视图。Django 内置 5 种转换器：

| 转换器 | 匹配 | 示例 route |
|---|---|---|
| `str`（默认） | 非空字符串，不含 `/` | `'topics/<str:name>/'` |
| `int` | 0 或正整数 | `'topics/<int:topic_id>/'` |
| `slug` | ASCII 字母数字、连字符、下划线 | `'posts/<slug:slug>/'` |
| `uuid` | UUID 字符串（含连字符） | `'book/<uuid:pk>/'` |
| `path` | 任意字符串，**可以含 `/`** | `'files/<path:filepath>/'` |


视图函数的**关键字参数名必须和转换器变量名一致**：

```python
# path('topics/<int:topic_id>/', views.topic, name='topic')

# views.py —— route 里 <int:topic_id> 抽出的值，按同名关键字参数传给函数
def topic(request, topic_id):
    topic = Topic.objects.get(id=topic_id)
    entries = topic.entry_set.order_by('-date_added')
    context = {'topic': topic, 'entries': entries}
    return render(request, 'learning_logs/topic.html', context)
```

### 自定义转换器

内置不够用时（例如要求年份必须是 4 位数字），写一个类实现 `regex`、`to_python()`、`to_url()`，再用 `register_converter` 注册：

```python
class FourDigitYearConverter:
    regex = r'[0-9]{4}'
    def to_python(self, value): return int(value)
    def to_url(self, value): return f'{value:4d}'

from django.urls import register_converter, path
register_converter(FourDigitYearConverter, 'yyyy')

urlpatterns = [path('articles/<yyyy:year>/', views.year_archive)]
```

## include()、命名空间与 reverse

### include()：分层挂载路由

项目级 `project/urls.py` 是总入口，通常不直接写业务路由，而是用 `include()` 把各 app 的路由表挂上去：

```python
from django.conf import settings
from django.conf.urls.static import static
from django.contrib import admin
from django.urls import path, include
from django.views.generic import RedirectView

urlpatterns = [
    # 挂载：把各 app 的路由表用 include() 挂进总入口
    path('admin/', admin.site.urls),
    path('accounts/', include('accounts.urls')),          # 业务 app（内含 auth 路由）
    path('learning_logs/', include('learning_logs.urls')),  # 业务 app
    # 重定向：根路径跳到业务首页（RedirectView 可配 permanent= 301/302）
    path('', RedirectView.as_view(url='/learning_logs/', permanent=True)),
]
# 静态 / 媒体资源路由（仅 DEBUG 生效；生产期交给 Web 服务器托管）
# 注意：urlpatterns += ... 只是把返回的路由列表并入 urlpatterns，本质是 Python 列表拼接
urlpatterns += static(settings.STATIC_URL, document_root=settings.STATIC_ROOT)
urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

### app_name 命名空间

在每个 app 的 `urls.py` 顶部写 `app_name = 'xxx'`，就声明了一个**应用命名空间**。之后引用路由用 `'应用名:路由名'`：

```python
from django.urls import path, include
from . import views

app_name = 'accounts'
urlpatterns = [
    # Include default auth urls.
    path('', include('django.contrib.auth.urls')),
    # Registration page.
    path('register/', views.register, name='register'),
]
```

### reverse() 与 reverse_lazy()

| 函数 | 用在哪 | 说明 |
|---|---|---|
| `reverse('app:name', args=[1])` | 视图函数内、shell、业务代码 | 根据 name 反解出完整 URL 字符串（立即执行） |
| `reverse_lazy('app:name')` | 类属性、`success_url`、模块级常量 | **惰性反解**：URLconf 还没加载完时（如 CBV 类定义时）用它 |

```python
from django.urls import reverse, reverse_lazy

reverse('learning_logs:topic', args=[5])           # => '/topics/5/'
reverse('learning_logs:topics')                    # => '/topics/'

class TopicDelete(DeleteView):
    success_url = reverse_lazy('learning_logs:topics')   # 类属性必须用 lazy
```

## re_path()：正则路由

`path()` 解决 95% 的场景；遇到复杂模式（如旧式无分隔符、多参数正则）时用 `re_path()`：

```python
from django.urls import re_path

urlpatterns = [
    re_path(r'^book/(?P<pk>\d+)/$', views.book_detail),
    re_path(r'^year/(?P<year>[0-9]{4})/month/(?P<month>[0-9]{1,2})/$', views.month_archive),
]
```

命名分组 `(?P<name>...)` 的 name 即视图关键字参数。能用 `path()` + 转换器解决就不要用 `re_path()`——可读性差、容易漏边界。

## 函数视图 FBV 骨架

FBV 就是一个**接收 `HttpRequest`、返回 `HttpResponse` 的 Python 函数**：

绝大多数业务视图的结构是：取参数 → 查库 → 分支 GET/POST → 渲染模板或重定向。

## HttpRequest 对象

视图第一个参数 `request` 是 Django 构造的 `HttpRequest`，常用成员：

| 成员 | 说明 |
|---|---|
| `request.method` | 请求方法：`'GET'` / `'POST'` / `'PUT'` … |
| `request.GET` | 查询串参数（`?a=1&b=2`），QueryDict |
| `request.POST` | 表单 POST 数据（`multipart` 不含文件） |
| `request.body` | 原始请求体字节串（API/JSON 用） |
| `request.headers` | 请求头字典（`request.headers['User-Agent']`） |
| `request.path` / `request.path_info` | 请求路径（不含域名与查询串） |
| `request.FILES` | 上传文件（需表单 `enctype="multipart/form-data"`） |
| `request.user` | 当前登录用户（未登录是 `AnonymousUser`，由 Auth 中间件注入） |
| `request.session` | 类字典的会话对象（`request.session['k'] = v`） |
| `request.COOKIES` / `request.META` | Cookie 字典 / WSGI 环境变量（含 HTTP_* 头、REMOTE_ADDR） |
| `request.is_secure()` | 是否 HTTPS |
| `request.is_ajax()` | 是否 AJAX 请求（Django 3.1+ 移除，改用 `request.headers.get('x-requested-with')`） |

### QueryDict

`request.GET`、`request.POST`、`request.FILES` 都是 `QueryDict`——一种**同键多值**的字典：

```python
request.GET.get('page', '1')           # 取单值，缺省返回 '1'
request.GET.getlist('tag')             # 取同键所有值 → ['django', 'orm']
request.POST['title']                  # 直接下标，不存在抛 KeyError
```

POST 提交的表单字段都在 `request.POST` 里；上传的文件在 `request.FILES` 里，二者要分别传给 `Form(...)`。

## HttpResponse 对象

视图的返回值必须是一个 `HttpResponseBase` 子类实例。常用响应类型：

| 类型 | 状态码 | 说明 |
|---|---|---|
| `HttpResponse(content, content_type=, status=)` | 200 | 直接返回字符串/字节 |
| `JsonResponse(data)` | 200 | `application/json`，`safe=False` 才能传列表 |
| `HttpResponseRedirect(url)` | **302** | 临时重定向（PRG 模式主力） |
| `HttpResponsePermanentRedirect(url)` | 301 | 永久重定向（SEO 用） |
| `HttpResponseNotModified()` | 304 | 协商缓存未修改 |
| `HttpResponse(status=403)` | 403 | 自定义状态码 |
| `FileResponse(file, as_attachment=True, filename=)` | 200 | 流式返回文件下载（大文件不占内存） |
| `StreamingHttpResponse(generator)` | 200 | 流式响应（长 CSV、SSE） |

## shortcuts：少写样板代码

`django.shortcuts` 模块提供视图里最常用的工具函数：

| 函数 | 说明 |
|---|---|
| `render(request, 'tpl.html', context=, content_type=, status=)` | 渲染模板并返回 HttpResponse（最常用）；`render_to_response()` 是它的旧别名，Django 2.0 起不再推荐 |
| `render_to_string('tpl.html', context=)` | 只返回渲染后的字符串（发邮件、嵌入响应时用） |
| `redirect('view-name' or url or obj)` | 返回 302；参数可以是路由名、URL、模型（自动调 `get_absolute_url()`） |
| `get_object_or_404(Model, **lookups)` | 取单条，找不到抛 `Http404`（自动转 404 响应） |
| `get_list_or_404(Model, **lookups)` | 取列表，空列表抛 404 |


```python
from django.shortcuts import get_object_or_404, render, redirect
from django.urls import reverse
from django.contrib.auth.decorators import login_required
from .models import Topic
from .forms import TopicForm

@login_required
def edit_topic(request, topic_id):
    """Edit an existing topic."""
    topic = get_object_or_404(Topic, pk=topic_id, owner=request.user)

    if request.method != 'POST':
        form = TopicForm(instance=topic)
    else:
        form = TopicForm(instance=topic, data=request.POST)
        if form.is_valid():
            form.save()
            return redirect(reverse('learning_logs:topic', args=[topic_id]))

    context = {'form': form, 'topic': topic}
    return render(request, 'learning_logs/edit_topic.html', context)
```

## 视图装饰器

函数视图用装饰器附加横切逻辑（认证、权限、方法限制）：

| 装饰器 | 作用 |
|---|---|
| `@login_required` | 未登录跳转 `settings.LOGIN_URL`；可传 `login_url=`、`redirect_field_name=` |
| `@permission_required('app.perm', raise_exception=True)` | 检查当前用户是否有某权限；`raise_exception=True` 时抛 403 而非跳登录 |
| `@require_http_methods(['GET', 'POST'])` | 只允许指定方法，否则 405 |
| `@require_GET` / `@require_POST` / `@require_safe` | 上面的便捷版（safe = GET/HEAD） |
| `@never_cache` | 加 `Cache-Control: no-cache` 头，禁止缓存该页 |
| `@csrf_exempt` | 关闭该视图的 CSRF 校验（API 常用，业务页不要用） |
| `@require_GET` + `@cache_page(60)` | 多个装饰器可叠加，最靠近函数的先执行 |


## POST/GET 分支与 PRG 模式

"新增/编辑"类视图几乎都按同一套三步写，称为 **FBV 表单黄金模式**：

1. **GET 请求**：渲染空白（或预填）表单；
2. **POST 请求且 `form.is_valid()`**：保存数据 → `redirect()` 到结果页；
3. **POST 但校验失败 / 走到末尾**：带着表单（含错误信息）重新渲染。

提交成功后立即 `redirect()` 而不是直接渲染结果页，就是 **PRG 模式**（Post-Redirect-Get）：用户刷新页面不会重复提交表单。

```python
@login_required
def new_topic(request):
    """Add a new topic."""
    if request.method != 'POST':
        # No data submitted; create a blank form.
        form = TopicForm()
    else:
        # POST data submitted; process data.
        form = TopicForm(data=request.POST)
        if form.is_valid():
            new_topic = form.save(commit=False)
            new_topic.owner = request.user
            new_topic.save()
            return redirect('learning_logs:topics')

    # Display a blank or invalid form.
    context = {'form': form}
    return render(request, 'learning_logs/new_topic.html', context)
```

```python
from django.shortcuts import render, redirect
from django.contrib.auth import login
from django.contrib.auth.forms import UserCreationForm


def register(request):
    """Register a new user."""
    if request.method != 'POST':
        # Display blank registration form.
        form = UserCreationForm()
    else:
        # Process completed form.
        form = UserCreationForm(data=request.POST)

        if form.is_valid():
            new_user = form.save()
            # Log the user in and then redirect to home page.
            login(request, new_user)
            return redirect('learning_logs:index')

    # Display a blank or invalid form.
    context = {'form': form}
    return render(request, 'registration/register.html', context)
```

## 错误处理

| 方式 | 说明 |
|---|---|
| `raise Http404` | 在视图里主动抛 404（找不到资源、越权访问都常用它） |
| `get_object_or_404(...)` | 找不到自动抛 Http404 |
| `handler400 / handler403 / handler404 / handler500` | 在项目 urls.py 里 `handler404 = 'myapp.views.bad_request'` 自定义错误视图 |
| `DEBUG=True` | 开发期 Django 直接显示调试堆栈，自定义错误页不生效 |
| `DEBUG=False` | 生产期必须配合 `ALLOWED_HOSTS`，否则所有请求 400/500 |


```python
@login_required
def topic(request, topic_id):
    """Show a single topic and all its entries."""
    topic = Topic.objects.get(id=topic_id)
    # Make sure the topic belongs to the current user.
    if topic.owner != request.user:
        raise Http404
    ...
```
