
## Django 测试是什么

Django 测试建立在 Python 标准库 `unittest` 之上：

- 测试写在各 app 的 `tests.py`，或拆成 `tests/` 包（含 `__init__.py`，再分 `test_models.py`、`test_views.py` 等）。
- 每个测试类继承 `django.test.TestCase`（或其子类）。
- 每个测试方法以 `test_` 开头，方法体里用断言验证行为。
- 运行：`python manage.py test`。
- **Django 会自动建一个独立的测试数据库**（名字一般是 `test_<你的库名>`），跑完销毁，开发库的真实数据一根手指头都碰不到。

最小骨架：

```python
from django.test import TestCase


class MyTest(TestCase):
    def test_something(self):
        self.assertEqual(1 + 1, 2)
```

## 运行测试：发现规则与常用参数

### 发现规则

`manage.py test` 默认按 `INSTALLED_APPS` 顺序，在每个 app 下找：

- `tests.py` 文件，或
- `tests/` 包里所有 `test_*.py` 模块。

类名、方法名必须是 `CamelCase` 类、`test_xxx` 方法才会被发现。

### 按范围运行

| 命令 | 跑什么 |
|---|---|
| `python manage.py test` | 全部测试 |
| `python manage.py test learning_logs` | 只跑 learning_logs 这个 app |
| `python manage.py test learning_logs.tests` | 只跑 learning_logs 的 tests 包 |
| `python manage.py test learning_logs.tests.test_models` | 只跑某个模块 |
| `python manage.py test learning_logs.tests.test_models.TopicModelTest` | 只跑某个类 |
| `python manage.py test learning_logs.tests.test_models.TopicModelTest.test_str` | 只跑某个方法 |
| `python manage.py test learning_logs.models Topic` | 模糊匹配（按名字） |

开发时强烈建议**只跑当前改的那个类**，几十秒变两秒。

### 常用参数

| 参数 | 作用 |
|---|---|
| `--keepdb` | 保留测试数据库，下次跑不重建（省建表时间，强烈建议本地开发加） |
| `--reverse` | 反向跑测试（排查测试间互相污染时有用） |
| `--debug-mode` | 测试时按 `DEBUG=True` 跑（看错误页） |
| `--parallel=N` | 多核并行跑 |
| `--tag=xxx` | 只跑打了 `@tag('xxx')` 标记的测试 |
| `--exclude-tag=xxx` | 排除某类测试 |
| `-v 0/1/2/3`（`--verbosity`） | 控制输出详细程度；`-v 2` 能看到每个用例名 |
| `--failfast` | 第一个失败就停 |
| `--shuffle` | 打乱执行顺序（检测用例依赖） |

```powershell
python manage.py test learning_logs.tests.test_views.TopicListViewTest --keepdb -v 2
```

## 四种测试类怎么选

| 类 | 是否建/回滚数据库 | 用途 |
|---|---|---|
| `TestCase` | 每个测试方法外层包一个事务，跑完回滚 | **90% 的场景用它**：测模型、视图、表单、API |
| `SimpleTestCase` | 完全不碰数据库 | 测纯函数、URL 反查、模板渲染、字符串工具 |
| `TransactionTestCase` | 每条测试后 truncate 表（而非回滚事务） | 需要测试事务行为本身（如 `transaction.atomic`、`savepoint`）时用 |
| `LiveServerTestCase` | 起一个真的开发服务器在 `localhost:8081` | 配 Selenium/Playwright 做浏览器端到端测试 |

> 通用示例（非项目代码）：用 SimpleTestCase 测 URL 反查，不碰数据库

```python
from django.test import SimpleTestCase
from django.urls import reverse, resolve


class UrlsTest(SimpleTestCase):
    def test_topics_url_resolves(self):
        found = resolve('/learning_logs/topics/')
        self.assertEqual(found.url_name, 'topics')

    def test_reverse(self):
        self.assertEqual(reverse('learning_logs:topics'), '/learning_logs/topics/')
```

## 测试数据准备：setUpTestData / setUp / fixtures

| 钩子 | 执行时机 | 特点 |
|---|---|---|
| `setUpTestData()`（classmethod） | **整个测试类只跑一次** | 建一批"只读"基准数据，最快；数据在类内共享，不要在测试里改它 |
| `setUp()` | **每个测试方法前**都跑 | 每条用例独立，需要被修改/删除的数据放这里 |
| `tearDown()` | 每个测试方法后 | 一般不用（TestCase 自动回滚） |
| `tearDownClass()` | 整个测试类结束后 | 一般不用 |

> 示例：Learning Log 的 TopicModelTest 用 setUpTestData 建一条基准主题（learning_logs/tests.py 风格）

```python
from django.test import TestCase

from learning_logs.models import Topic


class TopicModelTest(TestCase):

    @classmethod
    def setUpTestData(cls):
        """Set up non-modified objects used by all test methods."""
        Topic.objects.create(text='Python')

    def test_text_label(self):
        topic = Topic.objects.get(id=1)
        field_label = topic._meta.get_field('text').verbose_name
        self.assertEqual(field_label, 'text')

    def test_object_name_is_text(self):
        topic = Topic.objects.get(id=1)
        self.assertEqual(str(topic), 'Python')

    def test_get_absolute_url(self):
        topic = Topic.objects.get(id=1)
        self.assertEqual(topic.get_absolute_url(), '/learning_logs/topics/1/')
```

### fixtures

如果基准数据很多（比如要 50 个用户、100 篇文章），写 Python 创建很烦，可以用 fixture：先 `python manage.py dumpdata auth.User --indent 2 > learning_logs/fixtures/users.json`，然后在测试类里挂 `fixtures = ['users.json']`，Django 会在建表后自动加载。

> 通用示例（非项目代码）

```python
class PostViewTest(TestCase):
    fixtures = ['users.json', 'posts.json']

    def test_list(self):
        resp = self.client.get('/posts/')
        self.assertEqual(resp.status_code, 200)
```

### 测试数据库

- SQLite：几乎瞬间建好。
- PostgreSQL/MySQL：CI 上要先建一个能被测试账号 `CREATE DATABASE` 的角色；名字默认是 `test_<dbname>`。
- 想复用测试库，加 `--keepdb`；想换测试库名，在 `DATABASES['default']['TEST']['NAME']` 里配。

## Test Client：模拟浏览器请求

`TestCase` 自带 `self.client`，是 `django.test.Client` 实例，不用自己构造。它能发 GET/POST、跟随重定向、带登录态、带 session。

### 基本用法

```python
resp = self.client.get('/learning_logs/topics/')
resp = self.client.get(reverse('learning_logs:topics'))   # 推荐用 reverse，不怕改 URL
resp = self.client.post('/login/', {'username': 'bob', 'password': 'secret'})
resp = self.client.post('/posts/', data, follow=True)     # 自动跟随 302
```

`resp` 是 `Response` 对象，常用属性：

| 属性 | 含义 |
|---|---|
| `resp.status_code` | HTTP 状态码 |
| `resp.content` | 响应体 bytes |
| `resp.context` | 模板上下文（dict），可查 `resp.context['topic_list']` |
| `resp.wsgi_request` | 本次请求对象 |
| `resp.redirect_chain` | 跟随重定向经过的所有 URL |

### 登录与 session

```python
from django.contrib.auth.models import User

user = User.objects.create_user(username='bob', password='secret123')

# 方式一：用密码登录（模拟真实登录流程）
self.client.login(username='bob', password='secret123')

# 方式二：强制登录（不校验密码，更快）
self.client.force_login(user)

# 登出
self.client.logout()

# 直接改 session
session = self.client.session
session['favorite_color'] = 'blue'
session.save()
```

> 示例：Learning Log 的 MyTopicsListViewTest 同时演示了未登录重定向、登录后访问、按用户过滤（learning_logs/tests.py 风格）

```python
class MyTopicsListViewTest(TestCase):

    def setUp(self):
        # Create two users
        test_user1 = User.objects.create_user(
            username='testuser1', password='1X<ISRUkw+tuK')
        test_user2 = User.objects.create_user(
            username='testuser2', password='2HJ1vRV0Z&3iD')
        test_user1.save()
        test_user2.save()
        # ... 省略给各用户建 Topic 的逻辑 ...

    def test_redirect_if_not_logged_in(self):
        response = self.client.get(reverse('learning_logs:my_topics'))
        self.assertRedirects(
            response, '/accounts/login/?next=/learning_logs/my_topics/')

    def test_logged_in_uses_correct_template(self):
        login = self.client.login(
            username='testuser1', password='1X<ISRUkw+tuK')
        response = self.client.get(reverse('learning_logs:my_topics'))
        self.assertEqual(str(response.context['user']), 'testuser1')
        self.assertEqual(response.status_code, 200)
        self.assertTemplateUsed(
            response, 'learning_logs/my_topics.html')
```

### 分页测试

> 示例：Learning Log 的 TopicListViewTest 造 13 个主题，断言每页 10 条、第二页剩 3 条（learning_logs/tests.py 风格）

```python
class TopicListViewTest(TestCase):

    @classmethod
    def setUpTestData(cls):
        # Create topics for pagination tests
        number_of_topics = 13
        for topic_id in range(number_of_topics):
            Topic.objects.create(text='Topic {0}'.format(topic_id))

    def test_view_url_accessible_by_name(self):
        response = self.client.get(reverse('learning_logs:topics'))
        self.assertEqual(response.status_code, 200)

    def test_view_uses_correct_template(self):
        response = self.client.get(reverse('learning_logs:topics'))
        self.assertEqual(response.status_code, 200)
        self.assertTemplateUsed(response, 'learning_logs/topic_list.html')

    def test_pagination_is_ten(self):
        response = self.client.get(reverse('learning_logs:topics'))
        self.assertEqual(response.status_code, 200)
        self.assertTrue('is_paginated' in response.context)
        self.assertTrue(response.context['is_paginated'] is True)
        self.assertEqual(len(response.context['topic_list']), 10)

    def test_lists_all_topics(self):
        response = self.client.get(reverse('learning_logs:topics') + '?page=2')
        self.assertEqual(response.status_code, 200)
        self.assertEqual(len(response.context['topic_list']), 3)
```

## 断言全集

### unittest 标准断言（所有测试类都有）

| 断言 | 用途 |
|---|---|
| `assertEqual(a, b)` / `assertNotEqual(a, b)` | 相等 / 不等 |
| `assertTrue(x)` / `assertFalse(x)` | 真假 |
| `assertIsNone(x)` / `assertIsNotNone(x)` | 是否为 None |
| `assertIn(a, b)` / `assertNotIn(a, b)` | a 是否在 b（字符串/列表/dict）里 |
| `assertIsInstance(obj, cls)` | 类型检查 |
| `assertRaises(SomeError, func, *args)` | 断言抛异常 |
| `assertRaisesMessage(SomeError, 'msg', func, ...)` | 断言抛异常且消息含某文本 |
| `assertAlmostEqual(a, b)` | 浮点数近似相等 |
| `assertGreater(a, b)` / `assertLess(a, b)` | 大小比较 |

### Django 专属断言（TestCase 才有）

| 断言 | 用途 |
|---|---|
| `assertContains(resp, text, status_code=200)` | 响应 HTML 里包含 text |
| `assertNotContains(resp, text)` | 响应里**不**包含 text |
| `assertRedirects(resp, expected_url, status_code=302, target_status_code=200)` | 断言重定向到某 URL，并自动再请求一次目标 URL 检查状态码 |
| `assertTemplateUsed(resp, 'app/list.html')` | 渲染用了指定模板 |
| `assertTemplateNotUsed(resp, 'x.html')` | 没用某模板 |
| `assertFormError(resp, 'field', '错误信息')` | 表单某字段上有某错误（配合 POST 校验失败的响应） |
| `assertFormsetError(...)` | 同上，针对 formset |
| `assertQuerysetEqual(qs, [values], transform=...)` | 断言查询集等于某列表 |
| `assertNumQueries(N, func)` | 断言调用 func 时数据库查了 N 次（N+1 检测利器） |
| `assertURLEqual(url1, url2)` | 忽略参数顺序比较 URL |
| `assertHTMLEqual(html1, html2)` | 比较两段 HTML 结构等价 |
| `assertJSONEqual(raw, expected)` | 比较两段 JSON 等价 |
| `assertXMLEqual(...)` | 比较 XML |
| `assertLogs(logger, level)` | 上下文管理器，断言期间打了某条日志 |
| `assertWarns(...)` | 断言抛了某警告 |

> 示例：Learning Log 的视图测试，演示了 `assertFormError` 与权限 403（learning_logs/tests.py 风格）

```python
import datetime
from django.test import TestCase
from django.contrib.auth.models import User, Permission
from learning_logs.models import Topic, Entry


class EntryViewTest(TestCase):

    def setUp(self):
        # 建两个用户，给 staff_user 授 can_mark_done 权限
        self.plain_user = User.objects.create_user(
            username='testuser1', password='1X<ISRUkw+tuK')
        self.staff_user = User.objects.create_user(
            username='testuser2', password='2HJ1vRV0Z&3iD')
        self.staff_user.user_permissions.add(
            Permission.objects.get(codename='can_mark_done'))
        topic = Topic.objects.create(text='Python')
        Entry.objects.create(topic=topic, text='learn queryset')

    def test_forbidden_if_logged_in_but_not_correct_permission(self):
        # 无权限用户访问 mark_done → 403
        self.client.login(username='testuser1', password='1X<ISRUkw+tuK')
        response = self.client.get(
            reverse('learning_logs:mark_done', kwargs={'pk': 1}))
        self.assertEqual(response.status_code, 403)

    def test_form_invalid_blank_text(self):
        # text 必填，POST 空串应报字段错误
        self.client.login(username='testuser1', password='1X<ISRUkw+tuK')
        response = self.client.post(
            reverse('learning_logs:new_entry', kwargs={'topic_id': 1}),
            {'text': ''})
        self.assertEqual(response.status_code, 200)
        self.assertFormError(
            response.context['form'], 'text',
            'This field is required.')
```

### 直接测表单（不走 HTTP）

测纯表单逻辑时，不必发请求，直接构造 Form 调用 `is_valid()` 更快。

> 示例：Learning Log 的 EntryFormTest（learning_logs/tests.py 风格）

```python
from django.test import TestCase
from learning_logs.forms import EntryForm


class EntryFormTest(TestCase):

    def test_form_invalid_blank_text(self):
        """Test form is invalid if text is blank."""
        form = EntryForm(data={'text': '', 'progress': 'todo'})
        self.assertFalse(form.is_valid())

    def test_form_valid_with_text(self):
        """Test form is valid if text is provided."""
        form = EntryForm(data={'text': 'learn queryset', 'progress': 'todo'})
        self.assertTrue(form.is_valid())

    def test_progress_field_choices(self):
        form = EntryForm()
        self.assertEqual(
            [choice[0] for choice in form.fields['progress'].choices],
            ['todo', 'doing', 'done'])
```

## 速度与覆盖率

### 提速度三板斧

1. **`--keepdb`**：测试库只建一次，本地开发必备。
2. **只跑相关 app / 类**：改哪个测哪个，别每次全量。
3. **`setUpTestData` 优先于 `setUp`**：基准数据类级建一次，比每条用例重建快一个数量级。

### 覆盖率：coverage.py

```powershell
uv add coverage
coverage run manage.py test          # 跑测试并收集
coverage report -m                   # 命令行报告，-m 显示未覆盖行
coverage html                        # 生成 htmlcov/index.html，浏览器看
```

经验值：核心业务逻辑（模型方法、权限校验、关键视图）覆盖率应到 80%+；纯 CRUD 的列表/详情视图不用死磕 100%。看覆盖率不是目的，是用它找"哪些分支没人测"。

### CI 上跑测试

GitHub Actions / GitLab CI 里典型步骤：装依赖 → `python manage.py migrate`（测试会自动再建测试库）→ `coverage run manage.py test --parallel`。测试命令前加 `DJANGO_SETTINGS_MODULE=xxx.settings.test` 可以切到测试专用 settings（关掉 DEBUG、用内存 SQLite 等）。
