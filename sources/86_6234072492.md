
## 路由：Router 自动生成 URL

DRF 的 Router 根据 ViewSet 类自动生成全套 RESTful URL，无需手写 `path()`。

### DefaultRouter 与 SimpleRouter

两种 Router 的区别：

| Router | 特点 |
|---|---|
| `SimpleRouter` | 生成基础路由，不带 API 根页面 |
| `DefaultRouter` | 在 SimpleRouter 基础上额外生成一个 API 根页面（列出所有端点），还附一个 `.json` 格式后缀视图 |

### 项目实例：api/urls.py

> 示例：项目 `backend/api/urls.py`

```python
from django.urls import include, path
from rest_framework.routers import DefaultRouter

from . import views

router = DefaultRouter()
router.register('topics', views.TopicViewSet, basename='topic')
router.register('entries', views.EntryViewSet, basename='entry')

urlpatterns = [
    path('', include(router.urls)),
    path('register/', views.RegisterView.as_view(), name='register'),
]
```

`router.register()` 把 ViewSet 注册进 router；`include(router.urls)` 一次性挂出全部端点。RegisterView 不是 ViewSet，按普通视图用 `as_view()` 挂载。

注册一个 ViewSet 后自动生成的端点（以 `topics` 为例）：

| HTTP 方法 | URL | 对应 action | 说明 |
|---|---|---|---|
| GET | `/api/topics/` | `list` | 列表 |
| POST | `/api/topics/` | `create` | 创建 |
| GET | `/api/topics/{pk}/` | `retrieve` | 详情 |
| PUT | `/api/topics/{pk}/` | `update` | 整体更新 |
| PATCH | `/api/topics/{pk}/` | `partial_update` | 部分更新 |
| DELETE | `/api/topics/{pk}/` | `destroy` | 删除 |
| GET | `/api/topics/{pk}/<action>/` | 自定义 action | `@action(detail=True)` 端点 |
| GET | `/api/topics/<action>/` | 自定义 action | `@action(detail=False)` 端点 |

`router.register()` 的第三个参数 `basename` 用于反向解析 URL 名称（如 `reverse('topic-list')`）。当 ViewSet 定义了 `queryset` 时 basename 可省略，DRF 会自动从模型名推断；建议显式写出以避免歧义。

### 挂载到项目

REST API 在项目级 URLconf（`config/urls.py`）里整体挂载：

```python
# config/urls.py
urlpatterns = [
    path('admin/', admin.site.urls),
    path('accounts/', include('accounts.urls')),
    path('', include('learning_logs.urls')),
    # REST API (DRF)
    path('api/', include('api.urls')),
]
```

## 认证

认证决定"请求者是谁"。DRF 提供多种认证类，可以组合使用（按顺序尝试）。

### 内置认证类

| 认证类 | 原理 | 适用场景 |
|---|---|---|
| `SessionAuthentication` | 基于 Django session cookie | 前后端不分离、Browsable API 调试 |
| `BasicAuthentication` | HTTP Basic Auth（用户名+密码，Base64） | 简单测试、内部工具 |
| `TokenAuthentication` | 请求头带 `Authorization: Token <token>` | 移动端 / 第三方 API |
| `JWTAuthentication` | 请求头带 `Authorization: Bearer <jwt>` | 前后端分离、生产环境 |

在全局配置或视图类上指定：

```python
# 通用示例（非项目代码）
# settings.py 全局配置
REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'rest_framework.authentication.SessionAuthentication',
        'rest_framework.authentication.TokenAuthentication',
    ],
}

# 或在单个 ViewSet 上指定
class MusicViewSet(viewsets.ModelViewSet):
    authentication_classes = [SessionAuthentication]
```

### JWT 认证（djangorestframework-simplejwt）

JWT（JSON Web Token）是前后端分离项目最常用的认证方式。`djangorestframework-simplejwt` 库提供了完整的实现。

安装后在 `settings.py` 注册 app 并把默认认证类切换为 JWT。本项目的实际配置：

```python
# config/settings.py
INSTALLED_APPS = [
    # ...
    'rest_framework_simplejwt',
]

REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': (
        'rest_framework_simplejwt.authentication.JWTAuthentication',
    ),
}
```

在 URLconf 中添加获取和刷新 token 的端点。本项目的实际配置（`config/urls.py`）：

```python
from rest_framework_simplejwt.views import (
    TokenObtainPairView,
    TokenRefreshView,
)

urlpatterns = [
    path('api/token/', TokenObtainPairView.as_view(), name='token_obtain_pair'),
    path('api/token/refresh/', TokenRefreshView.as_view(), name='token_refresh'),
]
```

调用流程：

```
POST /api/token/  {"username": "alice", "password": "xxx"}
→ {"access": "<access_token>", "refresh": "<refresh_token>"}

# 之后每个请求带：
Authorization: Bearer <access_token>

# access 过期后用 refresh 换新 access：
POST /api/token/refresh/  {"refresh": "<refresh_token>"}
→ {"access": "<new_access_token>"}
```

`SIMPLE_JWT` 配置项（settings.py）可调整 token 有效期、刷新策略等。本项目的实际配置：

```python
# config/settings.py
from datetime import timedelta

SIMPLE_JWT = {
    'ACCESS_TOKEN_LIFETIME': timedelta(minutes=60),
    'REFRESH_TOKEN_LIFETIME': timedelta(days=7),
    'ROTATE_REFRESH_TOKENS': True,
}
```

关键配置项：

| 配置 | 作用 | 示例值 |
|---|---|---|
| `ACCESS_TOKEN_LIFETIME` | access token 有效期 | `timedelta(minutes=60)` |
| `REFRESH_TOKEN_LIFETIME` | refresh token 有效期 | `timedelta(days=7)` |
| `ROTATE_REFRESH_TOKENS` | 刷新时是否轮换 refresh token | `True`（每次刷新发新 refresh） |

前后端分离项目里，前端把 access token 存内存、refresh token 存 httpOnly Cookie，access 过期后静默用 refresh 换新，用户无感续期。
