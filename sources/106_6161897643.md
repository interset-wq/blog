
`os` 描述**运行环境**（操作系统层面），`process` 描述**当前进程**（Node 运行层面）。二者都属于「环境与系统信息」。

## `os` 模块（操作系统）

**用途**：暴露 Node 所运行操作系统的信息。

| 方法 | 返回内容 |
| --- | --- |
| `os.platform()` | 系统标识，如 `'darwin'`、`'win32'`、`'linux'` |
| `os.arch()` | CPU 架构，如 `'x64'`、`'arm64'` |
| `os.type()` | 官方系统名，如 `'Darwin'` |
| `os.release()` | 内核版本字符串 |
| `os.cpus()` | 每个逻辑 CPU 核的对象数组（型号、速度、times） |
| `os.uptime()` | 系统运行时间（秒） |
| `os.totalmem()` / `os.freemem()` | 总内存 / 可用内存（字节） |
| `os.userInfo()` | 当前用户信息对象（`uid`、`gid`、`username`、`homedir`、`shell`） |
| `os.networkInterfaces()` | 网络接口对象（地址、family、MAC、CIDR） |

### 打印系统概览

```js
const os = require("os");

console.log("平台:", os.platform(), os.arch());
console.log("CPU 核数:", os.cpus().length);
console.log("总内存(GB):", (os.totalmem() / 1024 ** 3).toFixed(2));
console.log("空闲内存(GB):", (os.freemem() / 1024 ** 3).toFixed(2));
console.log("运行时长(秒):", os.uptime());
```

## `process` 模块（进程）

**用途**：暴露当前 Node.js 进程的信息与控制。它是**全局对象**，无需导入。

### `process.env` — 环境变量

包含所有环境变量的对象。按需取值：

```js
process.env.NODE_ENV
```

### dotenv：从 `.env` 文件加载环境变量（第三方库）

**dotenv** 是流行的第三方库，启动时读取项目根目录的 `.env` 文件，把其中的键值对注入 `process.env`，让配置与代码分离。

安装与使用：

```bash
npm install dotenv
```

```js
// 在程序最开头加载
require("dotenv").config();

// 之后即可从 process.env 读取 .env 中的配置
const port = process.env.PORT || 5000;
const dbUrl = process.env.DB_URL;
const apiKey = process.env.API_KEY;
```

`.env` 文件示例（项目根目录）：

```ini
# .env —— 键值对，无需引号
PORT=5000
DB_URL=mongodb://localhost:27017/mydb
API_KEY=sk-1234567890
```

> **注意**：`.env` 存放密钥等敏感配置，**必须加入 `.gitignore`**，不要提交到版本控制。

#### ESM 中使用 dotenv

```js
import "dotenv/config"; // 或在文件顶部
// 或
import dotenv from "dotenv";
dotenv.config();
```

#### 指定 `.env` 文件路径

```js
require("dotenv").config({ path: "./config/prod.env" });
```

#### 两大好处

1. **安全**：密钥（API key、数据库密码）不进入源代码。
2. **灵活**：同一代码库通过在不同环境（开发/预发布/生产）替换 `.env` 文件，即可表现不同行为。

### `process.argv` — 命令行参数

- 索引 0：Node 可执行文件
- 索引 1：脚本路径
- 索引 2+：用户传入的参数

### `process.cwd()` — 当前工作目录

返回当前工作目录。

### 进程事件

```js
process.on("exit", (code) => {
  console.log(`Process exiting with code: ${code}`);
});

process.on("uncaughtException", (err) => {
  console.error("Uncaught error:", err.message);
});
```

### `process.emitWarning(message, type)`

触发自定义警告，可被 `warning` 监听器捕获。

### 解析命令行参数

```js
// 运行: node cli.js --port 3000 --name demo
const args = process.argv.slice(2);
console.log(args); // ['--port', '3000', '--name', 'demo']

// 简单解析成对象
const opts = {};
for (let i = 0; i < args.length; i += 2) {
  opts[args[i].replace(/^--/, "")] = args[i + 1];
}
console.log(opts); // { port: '3000', name: 'demo' }
```

### 监听退出与未捕获异常

```js
process.on("exit", (code) => console.log(`退出码: ${code}`));

process.on("uncaughtException", (err) => {
  console.error("未捕获异常:", err.message);
  process.exit(1);
});

process.emitWarning("自定义警告", "CustomType");
```

## os 与 process 的关联

- 都用来说明"程序跑在哪里"：`os` 说操作系统，`process` 说进程本身。
- 结合使用很常见：如用 `process.env` 读配置、用 `os.cpus().length` 决定并发 Worker 数量。

```js
const os = require("os");
const cluster = require("cluster"); // 多进程示例

if (cluster.isPrimary) {
  // 按 CPU 核数创建 worker 进程
  const workers = os.cpus().length;
  console.log(`启动 ${workers} 个 worker`);
  for (let i = 0; i < workers; i++) cluster.fork();
} else {
  console.log(`Worker ${process.pid} 运行中`);
}
```
