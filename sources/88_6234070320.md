
## 开发服务器：runserver

Django 自带一个**仅用于开发**的轻量服务器（单进程、代码改动自动重载）。它在 `DEBUG=True` 时顺便托管静态文件，**绝不能用于生产**。

```powershell
python manage.py runserver                # 默认 127.0.0.1:8000
python manage.py runserver 8080           # 改端口
python manage.py runserver 0.0.0.0:8000   # 监听所有网卡（局域网 / 容器内调试）
python manage.py runserver --ipv6         # 监听 IPv6（::1）
```

常用选项：

| 选项 | 作用 |
|---|---|
| `0.0.0.0:PORT` | 指定监听地址与端口；只写数字则视为端口 |
| `--noreload` | 关闭代码改动自动重启（复现性能问题时用） |
| `--nothreading` | 单线程运行（复现并发问题时用） |
| `--ipv6` | 用 IPv6 替代 IPv4 |
| `--nostatic` | 关闭 runserver 自动托管静态文件（测试 collectstatic 效果） |
| `--insecure` | `DEBUG=False` 时仍让 runserver 托管静态文件（临时调试） |

> runserver 会检测代码变化并重启，但**模板改动不需要重启**（模板按需加载）；安装新包、改 `settings.py` 后需手动重启。

## manage.py 运维命令

这里讲上线与日常运维高频命令。

### check：配置体检

```powershell
python manage.py check                 # 常规检查（加载 URLconf、模板配置等）
python manage.py check --deploy        # 按生产部署规则做安全 / 配置检查
python manage.py check --tag security  # 只检查某一类 tag
```

`check --deploy` 会对照 Django 的生产部署清单逐条告警，典型检查项：

| 检查项 | 含义 |
|---|---|
| `SECURITY_KEY_WARNING` | SECRET_KEY 是否为默认示例值 / 是否硬编码 |
| `DEBUG` | DEBUG 是否为 True（生产必须 False） |
| `ALLOWED_HOSTS` | 是否限制了允许的主机 |
| `SECURE_SSL_REDIRECT` | 是否强制 HTTPS |
| `SESSION_COOKIE_SECURE` / `CSRF_COOKIE_SECURE` | 会话与 CSRF cookie 是否只走 HTTPS |
| `SECURE_HSTS_SECONDS` | 是否开启 HSTS |
| `SECURE_CONTENT_TYPE_NOSNIFF` 等 | 安全响应头是否齐全 |

> 把 `check --deploy` 当作上线前的自动化 checklist；它报的每条警告都值得读一遍官方部署文档对应条目。

### dumpdata / loaddata：数据导出导入

```powershell
python manage.py dumpdata learning_logs --indent 2 > topics.json
python manage.py dumpdata --exclude contenttypes --exclude auth.Permission --indent 2 > db.json
python manage.py loaddata topics.json
```

用途：开发数据备份、把种子数据打进 fixtures、生产库局部迁移。`--natural-foreign`、`--natural-primary` 用于导出可读的自然键。

### shell：带 Django 环境的交互终端

```powershell
python manage.py shell
python manage.py shell -c "from learning_logs.models import Topic; print(Topic.objects.count())"
```

### 其它高频命令速查

| 命令 | 作用 |
|---|---|
| `migrate` / `makemigrations` / `showmigrations` | 迁移三件套 |
| `createsuperuser` | 建管理员；`--noinput` 配合环境变量可在 CI / 容器中非交互创建 |
| `collectstatic` | 收集静态文件（见“静态文件：collectstatic 与 WhiteNoise”） |
| `test` / `test --keepdb` | 跑测试 |
| `sqlmigrate <app> <n>` | 查看某条迁移对应的 SQL |
| `diffsettings` | 列出与默认值不同的配置（部署排查好用） |

## 生产化 settings

### 必须改的三项

```python
DEBUG = False
ALLOWED_HOSTS = ['www.example.com', 'example.com', '.example.com']  # 域名白名单；.example.com 匹配所有子域
SECRET_KEY = os.environ['DJANGO_SECRET_KEY']                        # 从环境变量读，绝不入库
```

- `DEBUG=False` 后：报错返回通用 500 页面（不泄露堆栈 / 源码），runserver 不再托管静态文件，未捕获异常邮件给 `ADMINS`。
- `ALLOWED_HOSTS`：请求的 Host 头不在列表里直接 400；`'*'` 只在完全内网、前置网关已校验时考虑。
- `SECRET_KEY`：签名 session / cookie / 密码重置 token 的钥匙；泄露后所有已发 cookie 可被伪造。

> 示例：Learning Log 的生产化 settings 片段（ll_project/settings.py，Platform.sh 部署分支）——检测到运行于平台时关闭 DEBUG、补 ALLOWED_HOSTS、从平台配置取 SECRET_KEY：

```python
# Platform.sh settings.
from platformshconfig import Config

config = Config()
if config.is_valid_platform():
    ALLOWED_HOSTS.append('.platformsh.site')
    DEBUG = False

    if config.appDir:
        STATIC_ROOT = Path(config.appDir) / 'static'
    if config.projectEntropy:
        SECRET_KEY = config.projectEntropy
```

> 这是"按运行环境切换配置"的通用套路：开发默认值写在上面，部署平台 / 容器里用环境变量或平台 SDK 覆盖。

### 安全相关配置（HTTPS 站点）

```python
# 通用示例（非项目代码）：HTTPS 生产环境典型安全项
SECURE_SSL_REDIRECT = True            # HTTP 自动 301 到 HTTPS
SESSION_COOKIE_SECURE = True          # 会话 cookie 只通过 HTTPS 发送
CSRF_COOKIE_SECURE = True             # CSRF cookie 只通过 HTTPS 发送
SECURE_HSTS_SECONDS = 31536000       # HSTS：一年
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SECURE_CONTENT_TYPE_NOSNIFF = True    # X-Content-Type-Options: nosniff
SECURE_REFERRER_POLICY = 'same-origin'
SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')  # 反代后识别原始协议
```

> 顺序注意：站点先在 HTTPS 下稳定运行一段时间，再开 `SECURE_HSTS_SECONDS`（HSTS 一旦下发，浏览器会硬记一年 HTTPS，想回滚要等过期）。

## 静态文件：collectstatic 与 WhiteNoise

`DEBUG=True` 时 Django 在每个 app 的 `static/` 里找文件并直接服务；`DEBUG=False` 后这一切停止，必须自己收集并托管静态文件。

```python
# 通用示例（非项目代码）
STATIC_URL = 'static/'                     # 浏览器访问前缀
STATIC_ROOT = BASE_DIR / 'staticfiles'    # collectstatic 收集目标目录
STATICFILES_DIRS = [BASE_DIR / 'static']  # 项目级额外静态目录（可选）
```

```powershell
python manage.py collectstatic                    # 汇总所有 app 的 static/ 到 STATIC_ROOT
python manage.py collectstatic --noinput --clear  # 部署脚本里非交互、先清空
```

托管方式两派：

| 方案 | 做法 | 适用 |
|---|---|---|
| 反向代理托管 | Nginx / Caddy 直接把 `/static/` 映射到 `STATIC_ROOT` | 自有服务器、流量大 |
| WhiteNoise | 把静态文件交给 Django 进程自己发（WSGI 中间件） | PaaS（Render / Railway / Fly）、不想配 Nginx |

WhiteNoise 最简接入：

```python
# 通用示例（非项目代码）
# uv add whitenoise
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'whitenoise.middleware.WhiteNoiseMiddleware',   # 紧跟 SecurityMiddleware 之后
    # ... 其余中间件
]
STORAGES = {
    'staticfiles': {
        'BACKEND': 'whitenoise.storage.CompressedManifestStaticFilesStorage',
    },
}
```

> 示例：Learning Log 的 Platform.sh 部署配置（.platform.app.yaml）——构建钩子里跑 collectstatic，部署钩子里跑 migrate：

```yaml
hooks:
    build: |
        uv sync --frozen
        python manage.py collectstatic
    deploy: |
        python manage.py migrate
```

同文件中，平台层直接把 `/static` 路径指向收集目录，不经过 Django 进程：

```yaml
web:
    upstream:
        socket_family: unix
    locations:
        "/static":
            root: "static"
            expires: 1h
            allow: true
```

## 生产数据库：切换到 PostgreSQL

SQLite 适合开发；生产并发写入请用 PostgreSQL / MySQL。以 PostgreSQL 为例：

```python
# 通用示例（非项目代码）
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': os.environ.get('DB_NAME', 'mydb'),
        'USER': os.environ.get('DB_USER', 'myuser'),
        'PASSWORD': os.environ.get('DB_PASSWORD', ''),
        'HOST': os.environ.get('DB_HOST', 'localhost'),
        'PORT': os.environ.get('DB_PORT', '5432'),
        'CONN_MAX_AGE': 60,                # 长连接秒数；0 为每个请求新建
    }
}
```

```powershell
uv add "psycopg[binary]"    # PostgreSQL 驱动（psycopg3）；旧项目用 psycopg2-binary
python manage.py migrate
```

> 示例：Learning Log 在 Platform.sh 上从"平台关系服务"读 PostgreSQL 凭证（ll_project/settings.py 尾部）：

```python
    if not config.in_build():
        db_settings = config.credentials('database')
        DATABASES = {
            'default': {
                'ENGINE': 'django.db.backends.postgresql',
                'NAME': db_settings['path'],
                'USER': db_settings['username'],
                'PASSWORD': db_settings['password'],
                'HOST': db_settings['host'],
                'PORT': db_settings['port'],
            },
        }
```

> 迁数据的策略：开发库 `dumpdata` → 建生产库 → `migrate` → `loaddata`；重要站点用维护期切换或双写，不要在流量高峰直接搬表。

## 运行方式：WSGI 与 ASGI

`runserver` 是开发服务器；生产要把 Django 交给独立的应用服务器。

| | WSGI（同步） | ASGI（异步） |
|---|---|---|
| 协议 | Web Server Gateway Interface | Asynchronous Server Gateway Interface |
| 常用服务器 | **gunicorn**、uWSGI | **uvicorn**、daphne |
| 入口模块 | `项目名.wsgi:application` | `项目名.asgi:application` |
| 适用 | 传统同步视图、同步 ORM | 异步视图（`async def` view）、WebSocket（Channels）、SSE / 长连接 |

```powershell
# WSGI：gunicorn（最常见）
gunicorn mysite.wsgi:application --workers 4 --bind 0.0.0.0:8000

# ASGI：uvicorn
uvicorn mysite.asgi:application --host 0.0.0.0 --port 8000 --workers 4
```

> workers 数量经验公式：`2 × CPU 核数 + 1`；IO 密集可适当加。容器 / 平台通常用 unix socket 而非 TCP。

> 示例：Learning Log 的 Platform.sh 启动命令（.platform.app.yaml）——4 个 worker、监听 unix socket：

```yaml
web:
    upstream:
        socket_family: unix
    commands:
        start: "gunicorn -w 4 -b unix:$SOCKET ll_project.wsgi:application"
```

前面再放一层 Nginx / Caddy 做：TLS 终止、`/static/` 直出、负载均衡、请求头清洗（把 `X-Forwarded-Proto` 传给后端，配合 `SECURE_PROXY_SSL_HEADER`）。

### 进程管理

服务器长期运行时，用系统级守护进程托管 gunicorn：

```ini
# 通用示例（非项目代码）：/etc/systemd/system/mysite.service 片段
[Unit]
Description=Django gunicorn
After=network.target

[Service]
WorkingDirectory=/app/mysite
ExecStart=/app/mysite/.venv/bin/gunicorn mysite.wsgi:application -w 4 -b 127.0.0.1:8000
Restart=always

[Install]
WantedBy=multi-user.target
```

- **systemd**（Linux 发行版自带）：上面这种 `.service` 文件，`Restart=always` 自动拉起，开机自启。
- **supervisor**：`command=gunicorn ...`、`autostart=true`、日志落盘。
- 容器 / PaaS 内通常不需要——平台进程管理器直接前台跑 gunicorn 即可（见上面 `start:` 命令）。

## 部署平台概览

| 平台 | 特点 | 适合 |
|---|---|---|
| PythonAnywhere | 免运维、配 WSGI 文件即用、支持定时任务 | 个人小站、教学项目 |
| Render / Railway | Git push 自动部署、环境变量面板、自带 PostgreSQL | 中小型项目，最省心 |
| Fly.io | 容器发到离用户近的边缘节点、可跑长期连接 | 需低延迟 / 多区域 |
| 云服务器（Nginx + Gunicorn + systemd） | 完全可控、成本低 | 有运维能力、需要定制 |
| Docker（Dockerfile + Compose） | 环境可复现、任意云都能跑 | 团队协作、CI/CD |
| Platform.sh / Heroku 风格 | 配置即代码（如上面 `.platform.app.yaml`） | 企业级流水线 |

选择逻辑：个人练手 → PythonAnywhere / Render；想完全掌控 → 云服务器 + Docker；要 WebSocket / 异步 → 选支持 ASGI 的平台。

## 环境变量与 .env

密钥、数据库口令等**不写进代码库**，运行时从环境变量读。本地开发用 `.env` 文件模拟：

```powershell
uv add django-environ     # 或 python-decouple，二选一
```

```python
# 通用示例（非项目代码）：django-environ 写法
import environ

env = environ.Env(DEBUG=(bool, False))
environ.Env.read_env(BASE_DIR / '.env')     # 本地开发读 .env；生产读真实环境变量

SECRET_KEY = env('SECRET_KEY')
DEBUG = env('DEBUG')
ALLOWED_HOSTS = env.list('ALLOWED_HOSTS')
DATABASES = {'default': env.db()}
```

```ini
# .env（加入 .gitignore，绝不提交）
SECRET_KEY=replace-with-a-long-random-string
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1
DATABASE_URL=sqlite:///db.sqlite3
```

> `.env`、`db.sqlite3`、`.venv/`、`staticfiles/`、`__pycache__/` 都应进 `.gitignore`。

## LOGGING 日志简述

生产环境用 `LOGGING` 配置结构化日志，替代 `print`：

```python
# 通用示例（非项目代码）
LOGGING = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'simple': {'format': '{asctime} {levelname} {name} {message}', 'style': '{'},
    },
    'handlers': {
        'console': {'class': 'logging.StreamHandler', 'formatter': 'simple'},
    },
    'root': {'handlers': ['console'], 'level': 'INFO'},
    'loggers': {
        'django': {'level': 'INFO'},
        'myapp': {'level': 'DEBUG'},
    },
}
```

代码里：`import logging; logger = logging.getLogger(__name__); logger.info('user %s logged in', user)`。PaaS 平台一般直接收集 stdout，配 `console` handler 即可；自有服务器再配 RotatingFileHandler 或投递到 ELK / Loki。
