
Git 是分布式版本控制系统。核心思路：在**分支**上工作 → 修改 → 追踪（add/commit）→ 合并（merge）→ 清理分支。

## 一、核心概念

| 概念 | 说明 |
|---|---|
| 仓库（repository） | `git init` 初始化，创建隐藏目录 `.git` |
| 提交（commit） | 一次保存的版本快照，有唯一哈希 |
| 分支（branch） | 一条独立的提交线；新建分支继承当前分支全部提交 |
| 暂存区（staging area） | `add` 后、`commit` 前的中间区域 |
| HEAD | 指向当前所在分支最新提交的指针 |

> 约定：`$` 开头为普通用户执行的命令；默认分支 `master` 现多用 `main`。

## 二、分支

分支是 Git 的核心。**新建的分支继承当前分支的全部提交记录**。一般不在 `main` 上直接改，而是新建分支 → 修改 → 合并回 `main` → 删除该分支。

### 2.1 分支常用命令

| 操作 | 命令 | 说明 |
|---|---|---|
| 新建并切换 | `git checkout -b new_branch` | `b` = branch |
| 只新建 | `git branch new_branch` | 不切换 |
| 切换 | `git checkout branch_name` | — |
| 查看 | `git branch` | 当前分支用 `*` 标出 |
| 合并 | `git merge branch_name` | 一般在 `main` 执行 |
| 删除 | `git branch -d branch_name` | 合并后删除 |

**分支命名规范**：不能有空格；用 `feat/`、`fix/` 开头，如 `git branch feat/add-create-table-reference`。`main` 存可上生产的代码，其他分支放新特性 `feat` 或修复 `fix`。

## 三、提交代码

正确的提交流程：

1. 新建分支
2. 做出更改
3. 追踪文件：`git add` → `git commit`
4. 合并到 `main`
5. 删除分支

| 操作 | 命令 | 说明 |
|---|---|---|
| 添加指定文件 | `git add file_name` | 进暂存区 |
| 添加所有文件 | `git add .` | — |
| 提交 | `git commit -m "msg"` | `m` = message |
| 查看状态 | `git status` | 哪些文件被修改/暂存 |

> 提交信息一般以 `feat:` 或 `fix:` 开头，便于理解此次 commit 做了什么。

## 四、历史与修改

### 4.1 查看提交记录

```bash
$ git log              # 详细记录
$ git log --oneline    # 简短信息
$ git log -1           # 最近一条的详细信息
$ git log -n --oneline # 最近 n 条
```

### 4.2 查看未提交的修改

```bash
$ git diff
```

已追踪文件在修改后（`add` 之前）用此命令查看改动。`+` 开头是新增行，`-` 开头是被删除行。

### 4.3 查看提交信息

```bash
$ git show          # 最近一个 commit 的详情（不含 revert 撤销的）
$ git show HEAD~1   # 含 revert 撤销的
```

## 五、同步分支（rebase）

```bash
$ git rebase main
```

**场景**：在 `feat` 分支加了内容并提交后，发现 `feat` 原有内容有语法错误（`main` 和 `feat` 中都有）。于是回 `main` 建 `fix` 分支修正、合并、删除；再回 `feat` 继续开发时，用 `rebase` 把 `main` 的新提交「插队」到 `feat` 提交之前。

> [!NOTE]
> `rebase` 会**重写提交历史**（改变哈希值），适合整理本地、未推送的分支。多人协作的共享分支慎用。

### 5.1 解决冲突

两个分支在同一行加了内容时合并会冲突，Git 用标记标出：

```text
<<<<<<< HEAD
=======
>>>>>>> b212535
```

在文件中编辑并删除标记即可解决。然后：

```bash
$ git add <file>         # 加入暂存区（此时 rebase 未结束）
$ git rebase --continue  # 打开 vi，直接 ZZ 退出，rebase 结束
```

### 5.2 交互式修改历史

`git rebase --interactive`（可简写 `-i`）打开 vi 编辑提交记录：

| 场景 | 命令 | 操作 |
|---|---|---|
| 删除提交 | `git rebase -i HEAD~2` | 前两行 `pick` 改 `d` |
| 合并提交 | `git rebase -i HEAD~5` | 除首个外 `pick` 改 `s`（squash）；再次打开 vi 保存即可 |
| 改提交备注 | `git rebase -i --root` | `pick` 改 `r`；新 vi 窗口编辑备注 |

> [!WARNING]
> 交互式修改会改变提交哈希，可能造成后续合并冲突，需 `git rebase main` 同步。

## 六、临时暂存（git stash）

想临时放下手头未提交的修改去处理别的事时使用。

| 操作 | 命令 | 说明 |
|---|---|---|
| 剪切未提交修改 | `git stash` | 暂存到剪贴板 |
| 查看列表 | `git stash list` | 编号 `stash@{0}` 最新，从新到旧 |
| 取出并移除 | `git stash pop` | 类似剪切粘贴；之后 list 为空 |
| 取出但保留 | `git stash apply` | 类似复制粘贴；list 仍有内容 |
| 查看简短信息 | `git stash show` | `-p` 看详细信息 |
| 查看指定项 | `git stash show stash@{0}` | `-p stash@{1}` 详细信息 |
| 删除 | `git stash drop` | 指定项加 `stash_name` |

## 七、撤销 commit

| 命令 | 行为 | 提交记录 |
|---|---|---|
| `git reset HEAD~1` | 撤销最近一次 commit 回到 add 之前 | **删除**记录 |
| `git reset --hard HEAD~1` | 丢弃修改，回到 add 之前 | 删除 |
| `git reset --soft HEAD~1` | 回到 add 之后、commit 之前（保留在暂存区） | 删除 |
| `git revert HEAD` | 生成一次反向提交回到修改之前 | **保留**记录 |

```bash
$ git reset HEAD~1    # 按 HEAD 指向撤销；HEAD~1 撤销最近一次
$ git revert HEAD     # 自动打开默认编辑器，直接退出即可
```

> [!IMPORTANT]
> `reset` 会删除提交记录，`revert` 保留记录并以反向提交回退。已推送到远程的分支回退优先用 `revert`。

## 八、.gitignore 忽略文件

```bash
$ git checkout -b feat/add-gitignore
$ touch .env
$ touch .gitignore
```

`.env` 存放环境变量，一般放入 `.gitignore` 防止被追踪。但环境变量信息其他人可能用得上，所以通常再建一个 `sample.env` 存放示例。

```bash
$ git add .gitignore
$ git commit -m "feat: add .gitignore"
```

## 核心总结

1. **工作流**：建分支 → 修改 → add/commit → merge → 删分支。
2. **分支**：`checkout -b` 新建并切换；`branch` 查看/新建；`merge` 合并；`branch -d` 删除。
3. **提交**：`add` 进暂存区，`commit -m` 提交，信息用 `feat:`/`fix:` 前缀。
4. **历史**：`log` 看记录、`diff` 看修改、`show` 看提交详情。
5. **rebase**：同步分支提交；`-i` 可删除/合并/改备注；会重写历史。
6. **stash**：临时暂存未提交修改，`pop` 取出、`apply` 复制、`drop` 删除。
7. **撤销**：`reset` 删记录回退，`revert` 保留记录反向提交。
8. **冲突**：删除 `<<<<<<<`/`=======`/`>>>>>>>` 标记后 add + `rebase --continue`。
