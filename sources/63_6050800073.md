
pwsh 的核心设计思想之一：**用同一套命令，去访问不同类型的数据存储**。实现这个能力的组件就叫 **PSProvider（提供程序）**。

## 一、什么是 PSProvider（提供程序）

PSProvider 本质上是一个**数据适配器**。它把各种底层异构数据（文件系统、注册表、环境变量、证书等）统一包装成 pwsh 中一致的「层次化项（Item）」模型。

> 简单理解：提供程序负责把各式各样的数据，伪装成类似「文件和文件夹」的结构，让你不必学习多套独立命令，用同一组 Item 系列 cmdlet 就能操作它们。

不同提供程序对应不同数据源：

| 提供程序 | 数据源 | 适用平台 |
|---|---|---|
| FileSystem | 本地文件、文件夹 | 跨平台 |
| Registry | Windows 注册表（HKCU、HKLM） | 仅 Windows 环境 |
| Env | 系统环境变量 | 跨平台 |
| Alias | pwsh 命令别名 | 跨平台 |
| Variable | pwsh 变量 | 跨平台 |
| Certificate | Windows 证书存储 | 仅 Windows 环境 |

### 提供程序的能力标记（Capabilities）

执行 `Get-PSProvider` 可以查看当前 shell 已加载的所有提供程序，输出里的 `Capabilities` 表示它支持的特性：

``` powershell
PowerShell 7.6.6
PS C:\Users\d111k> Get-PSProvider

Name                 Capabilities                                                                   Drives
----                 ------------                                                                   ------
Registry             ShouldProcess                                                                  {HKLM, HKCU}
Alias                ShouldProcess                                                                  {Alias}
Environment          ShouldProcess                                                                  {Env}
FileSystem           Filter, ShouldProcess, Credentials                                             {C, D, E, Temp…}
Function             ShouldProcess                                                                  {Function}
Variable             ShouldProcess                                                                  {Variable}
```

常见的能力标记：

- **ShouldProcess**：支持 `-WhatIf`、`-Confirm` 参数，可以**预演脚本**，不会直接修改真实数据，适合高危操作。
- **Filter**：操作时支持 `-Filter` 参数，高效筛选数据。
- **Credentials**：支持 `-Credential` 参数，可以用其他账号身份访问数据源。
- **Transactions**：支持事务，可批量操作并支持回滚。

## 二、PSDrive：提供程序映射出来的逻辑驱动器

**PSDrive（pwsh 驱动器）** 是由 PSProvider 创建的逻辑映射。PSProvider 是底层适配器，PSDrive 是访问这个数据源的入口——它把数据源挂载成一个驱动器，就像资源管理器里的 C 盘、D 盘。

> [!IMPORTANT]
> PSDrive 不一定是真实硬盘：`HKCU:`、`Env:`、`Alias:` 都是 PSDrive，但它们不是磁盘，只是注册表、环境变量等数据的访问入口。

``` pwsh
# 查看当前所有挂载的 PSDrive
PS C:\Users\d111k> Get-PSDrive

Cert                                   Certificate   \
D                 121.16        178.84 FileSystem    D:\
E                  55.67        245.33 FileSystem    E:\
```

输出中常见驱动器：

- `C、D、E`：FileSystem 提供程序映射的物理磁盘
- `HKCU、HKLM`：Registry 提供程序映射的注册表根项（仅 Windows 环境）
- `Env`：Environment 提供程序映射的环境变量
- `Alias、Variable`：分别对应别名、变量的存储

> 关系总结：**PSProvider（适配器）→ 创建 → PSDrive（逻辑驱动器入口）→ 承载多层 Item（项）**

## 三、统一操作模型：Item 系列命令

因为 PSProvider 把所有数据统一抽象为「项（Item）」，pwsh 就提供了一套通用 cmdlet——**不管是文件、注册表项，都能用这套命令操作**。

名词分为三类：

1. **Item**：单个对象（文件、文件夹、注册表项），统称为「项」
2. **ItemProperty**：项上面的属性（文件只读标记、注册表键值）
3. **ChildItem**：一个项下面包含的子项（文件夹里的文件、注册表项下的子键）

``` pwsh
# 查看所有名词为 *item* 的命令
pwsh> Get-Command -Noun *item*
```

常用 Item 命令：

| 命令 | 别名 | 作用 |
|---|---|---|
| `Set-Location` | `cd` | 切换当前位置（进入目录 / 注册表项） |
| `New-Item` | `mkdir` | 创建项（文件、文件夹、注册表项） |
| `Get-Item` | - | 获取单个项 |
| `Get-ChildItem` | `dir` | 获取一个项下面所有子项 |
| `Copy-Item` | `copy` | 复制项 |
| `Move-Item` | `move` | 移动项 |
| `Rename-Item` | `ren` | 重命名项 |
| `Remove-Item` | `del` | 删除项 |
| `Set-ItemProperty` | - | 修改项属性 |
| `Get-ItemProperty` | - | 读取项属性 |

> [!NOTE]
> 并不是所有提供程序都完整支持全部能力：
> - FileSystem 下的命令不支持事务参数 `-UseTransaction`
> - Registry 下的命令不支持 `-Filter`
> - Env（环境变量）**不支持项属性**——执行 `Get-ItemProperty Env:\PSModulePath` 会直接报错（因为它不实现 `IPropertyCmdletProvider` 接口）

## 四、路径、通配符与 LiteralPath

Item 类命令都有路径参数：

- `-Path`：默认参数，**支持通配符**
- `-LiteralPath`：字面路径，**不解析通配符**，路径里的 `*`、`?` 当作普通文本

通配符规则：

- `*`：匹配任意 0 个或多个字符
- `?`：匹配任意单个字符

> [!NOTE]
> Windows 文件系统的文件名**不能包含 `*` 和 `?`**；但注册表等其他提供程序，项名称可以正常使用 `*`、`?`。

## 五、实战 1：使用 FileSystem 文件系统提供程序

文件系统是最容易理解的提供程序，可以作为理解 PSProvider 的模板。

文件系统里的对象分三层：

1. **磁盘驱动器**（PSDrive）
2. **文件夹**（容器项，可以包含子项）
3. **文件**（非容器项，位于层级末端）

### 1. 切换位置 Set-Location

``` pwsh
# cd 是 Set-Location 的别名
pwsh> cd /tmp
pwsh> Set-Location -Path /home/user
```

### 2. 创建项 New-Item

``` pwsh
# 创建文件夹（容器项）
pwsh> New-Item testdir -ItemType Directory
pwsh> mkdir testdir2

# 不指定 -ItemType 时，默认创建文件
pwsh> New-Item test.txt
```

### 3. 列出子项 Get-ChildItem

``` pwsh
# 列出当前目录下所有 exe 程序，dir 是别名
pwsh> Get-ChildItem *.exe
pwsh> dir *.exe
```

## 六、实战 2：使用 Registry 注册表提供程序【仅 Windows 环境】

> [!NOTE]
> 注册表是 Windows 独有的数据存储，本节示例仅在 Windows 环境下运行 pwsh 时有效；Linux / macOS 上没有注册表提供程序。

注册表和文件系统的结构非常相似，都是分层树形结构：

- 注册表项（Key）≈ 文件夹（容器）
- 注册表键值（Property）≈ 文件的属性

`HKCU:` 和 `HKLM:` 是注册表提供程序自动挂载的 PSDrive，`HKCU:` 对应 HKEY_CURRENT_USER。

``` pwsh
# 切换到 HKCU 驱动器
pwsh> Set-Location HKCU:

# 逐层进入注册表路径
pwsh> Set-Location software\microsoft\Windows

# 查看当前注册表项下所有子项
pwsh> Get-ChildItem

# 修改 DWM 项下 EnableWindowColorization 属性值为 0
pwsh> Set-ItemProperty -Path .\DWM\ -Name EnableWindowColorization -Value 0
```

## 七、核心总结

1. **PSProvider（提供程序）**：数据适配器。把异构数据统一抽象为「项」模型，让一套命令操作多种数据源。
2. **PSDrive**：提供程序挂载出来的逻辑驱动器，是访问数据源的入口，不一定是真实磁盘。
3. **Item 模型**：Item 是单个对象，ItemProperty 是对象属性，ChildItem 是对象的子对象。
4. FileSystem 提供程序最直观，注册表、环境变量等提供程序复用这套模型，但每个提供程序能力不同，部分命令 / 参数不支持。
5. `-Path` 支持通配符；`-LiteralPath` 使用字面路径，不解析通配符。
