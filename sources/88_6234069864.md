
## 启用与登录

Admin 是 `django.contrib.admin` 提供的内置应用，三步走即可用：

1. `INSTALLED_APPS` 里有 `django.contrib.admin`（`startproject` 默认带）；
2. 项目 `urls.py` 挂路由：`path('admin/', admin.site.urls)`；
3. 创建超级用户并启动：

```powershell
python manage.py migrate          # 先建表（auth、contenttypes、sessions、admin 都要迁移）
python manage.py createsuperuser  # 交互式输入用户名/邮箱/密码
python manage.py runserver
```

浏览器访问 `http://127.0.0.1:8000/admin/`。能登录后台的硬性条件是用户的 **`is_staff = True`**——超级用户默认带这个标志；普通用户即使密码对也会被拒之门外。

## 三种注册方式

每个 app 的 `admin.py` 负责把模型挂到后台。三种写法等价：

```python
from django.contrib import admin
from .models import Topic

# 写法一：裸注册（不定制）
admin.site.register(Topic)

# 写法二：注册时带上 ModelAdmin 类
class TopicAdmin(admin.ModelAdmin):
    list_display = ('text', 'owner')
admin.site.register(Topic, TopicAdmin)

# 写法三：装饰器（最常用，省去最后一行 register）
@admin.register(Topic)
class TopicAdmin(admin.ModelAdmin):
    list_display = ('text', 'owner')
```

裸注册足够应付小项目；一旦要调列、加过滤、改表单，就需要 `ModelAdmin` 配置类。

## ModelAdmin 属性全集

`ModelAdmin` 上有几十个类属性，按"列表页 / 编辑页 / 关联字段 / 行为"四类整理如下。

### 列表页属性（列表长什么样）

| 属性 | 类型 | 作用 |
|---|---|---|
| `list_display` | tuple/list | 列表页显示哪些列；可以放模型字段名、`__str__`、ModelAdmin 上的方法名、模型上的方法名 |
| `list_display_links` | tuple/list | 哪些列**同时是可点击链接**跳到编辑页；默认第一列是链接 |
| `list_filter` | tuple/list | 右侧边栏过滤器，按字段值筛选；常用 BooleanField、ForeignKey、DateField、choices 字段 |
| `search_fields` | tuple/list | 顶部搜索框，按这些字段做 `icontains` 模糊匹配；ForeignKey 用 `'author__name'` 跨表 |
| `list_editable` | tuple/list | 列表页里**直接可改**的字段（回车保存）；这些字段必须同时出现在 `list_display`，且第一个 `list_display_links` 列不能被编辑 |
| `list_per_page` | int | 每页条数，默认 100 |
| `list_max_show_all` | int | 数据少于多少条时显示"全部"按钮，默认 200 |
| `ordering` | tuple/list | 默认排序；与模型 `Meta.ordering` 类似，加 `-` 前缀降序 |
| `date_hierarchy` | str | 顶部按日期分层导航（年→月→日），填一个 DateField/DateTimeField 名 |
| `prepopulated_fields` | dict | 新增页里某字段自动从另一个字段生成（如 slug 从 title 生成），`{'slug': ('title',)}` |
| `actions_on_top` / `actions_on_bottom` | bool | 批量操作栏放顶部还是底部 |
| `actions_selection_counter` | bool | 是否显示已选条数 |

```python
@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    list_display = ('title', 'author', 'status', 'created_at')
    list_display_links = ('title',)
    list_filter = ('status', 'created_at', 'author')
    search_fields = ('title', 'body')
    list_editable = ('status',)
    list_per_page = 20
    ordering = ('-created_at',)
    date_hierarchy = 'created_at'
    prepopulated_fields = {'slug': ('title',)}
```

### 编辑页属性（单条记录怎么改）

| 属性 | 类型 | 作用 |
|---|---|---|
| `fields` | tuple/list | 编辑页显示哪些字段及顺序；元素可以是字符串，也可以是元组（同一行并排显示） |
| `fieldsets` | tuple | 编辑页分区；每段是 `(名称, {'fields': (...), 'classes': (...), 'description': '...'})`；与 `fields` 二选一 |
| `exclude` | tuple/list | 排除哪些字段（与 `fields` 二选一） |
| `readonly_fields` | tuple/list | 只读字段；可放方法名（配合方法返回值展示计算结果） |
| `autocomplete_fields` | tuple/list | ForeignKey/ManyToMany 改成搜索框（对方模型必须开 `search_fields`） |
| `raw_id_fields` | tuple/list | ForeignKey 改成下拉 ID 输入框（关联表很大时用，避免渲染几千个选项） |
| `radio_fields` | dict | ForeignKey/choices 字段改成单选按钮组，`{'gender': admin.HORIZONTAL}` |
| `filter_horizontal` | tuple/list | ManyToMany 字段改成左右穿梭框（横排） |
| `filter_vertical` | tuple/list | 同上，竖排 |
| `form` | ModelForm 类 | 自定义表单（见“自定义表单”） |
| `formfield_overrides` | dict | 批量覆盖某字段类型的表单控件（见“自定义表单”） |
| `save_as` | bool | 编辑页出现"另存为新条目"按钮 |
| `save_on_top` | bool | 保存按钮同时显示在顶部 |
| `view_on_site` | bool/方法 | 列表页显示"在网站上查看"的外链（需要模型有 `get_absolute_url`） |

> 示例：Learning Log 的 EntryAdmin 用 fieldsets 把编辑页分成两段

```python
@admin.register(Entry)
class EntryAdmin(admin.ModelAdmin):
    list_display = ('topic', 'progress', 'date_added', 'id')
    list_filter = ('progress', 'date_added')

    fieldsets = (
        (None, {
            'fields': ('topic', 'text', 'id')
        }),
        ('状态', {
            'fields': ('progress', 'date_added')
        }),
    )
```

> 示例：Learning Log 的 TopicAdmin 用 `fields` 元组让两列字段并排

```python
@admin.register(Topic)
class TopicAdmin(admin.ModelAdmin):
    list_display = ('text', 'owner', 'date_added')
    fields = ['text', ('owner', 'date_added')]
    inlines = [EntriesInline]
```

### list_display 里放方法

`list_display` 可以放模型方法或 ModelAdmin 方法，用来展示计算出来的列。列标题用 `short_description` 装饰。

> 示例：Learning Log 的 Topic 模型自带 `entry_count` 方法，统计关联的 Entry 数量，TopicAdmin 直接引用它

```python
# learning_logs/models.py
def entry_count(self):
    """Returns the number of entries under this topic."""
    return self.entry_set.count()

entry_count.short_description = 'Entries'
```

```python
# learning_logs/admin.py
class TopicAdmin(admin.ModelAdmin):
    list_display = ('text', 'owner', 'entry_count')
    inlines = [EntriesInline]


admin.site.register(Topic, TopicAdmin)
```

在 ModelAdmin 上自定义方法同理，方法签名是 `(self, obj)`：

```python
@admin.register(Order)
class OrderAdmin(admin.ModelAdmin):
    list_display = ('id', 'customer', 'total_amount', 'is_overdue')

    @admin.display(boolean=True, description='是否逾期', ordering='due_date')
    def is_overdue(self, obj):
        return obj.due_date and obj.due_date < timezone.now().date()
```

`@admin.display` 装饰器（Django 3.2+）可以同时设置 `description`、`boolean`（渲染成勾/叉图标）、`ordering`（让这一列可排序）、`empty_value`。

## Inline：在一页编辑关联对象

在"父对象"的编辑页里直接编辑它的"子对象"（一对多），省得两边跳。

| 属性 | 作用 |
|---|---|
| 基类 | `admin.TabularInline`（表格横排，紧凑）/ `admin.StackedInline`（字段竖排，适合字段多） |
| `model` | 内联哪个子模型（必填） |
| `extra` | 默认显示几个空表单行，默认 3；设 0 表示不预填空行 |
| `max_num` | 最多允许几个内联行 |
| `min_num` | 最少必须有几个 |
| `can_delete` | 是否允许删除，默认 True |
| `fk_name` | 当子模型有多个外键指向同一父模型时指定用哪个 |
| `verbose_name` / `verbose_name_plural` | 自定义标题 |

> 示例：Learning Log 在 Topic 页内联 Entry（learning_logs/admin.py）

```python
class EntriesInline(admin.TabularInline):
    """Defines format of inline entry insertion (used in TopicAdmin)"""
    model = Entry


class QuickTopicsInline(admin.TabularInline):
    """Defines format of inline topic insertion (used in UserAdmin)"""
    model = Topic
```

内联类在对应 ModelAdmin 里通过 `inlines = [...]` 挂上去，例如 `TopicAdmin.inlines = [EntriesInline]`。

## 自定义 Action：批量操作

列表页顶部有个"动作"下拉框（默认是"删除所选的 …"）。可以加自己的批量动作，比如"把选中的订单标记为已发货"。

函数签名固定为 `(modeladmin, request, queryset)`：

```python
@admin.action(description='标记为已发货')
def mark_shipped(modeladmin, request, queryset):
    queryset.update(status='shipped')


@admin.register(Order)
class OrderAdmin(admin.ModelAdmin):
    list_display = ('id', 'customer', 'status', 'shipped_at')
    actions = [mark_shipped]
```

要点：

- `@admin.action(description='...')` 设置动作在下拉框里显示的文字；旧写法是函数后接 `mark_shipped.short_description = '...'`，二者等价。
- 函数拿到 `queryset`（用户勾选的那些行），直接 `update()` 或循环处理即可，**不要在循环里 save**，能批量就批量。
- 把动作列到 `ModelAdmin.actions` 里才会出现在下拉框；也可以用 `actions = None` 关闭全部动作。
- 想在动作里加中间页（如确认页），给动作函数返回一个 `HttpResponse` 即可。

## 自定义表单

默认情况下 ModelAdmin 自动生成的表单就是模型表单。要加校验、改控件、加自定义字段，用 `form` 属性挂一个 ModelForm：

```python
from django import forms
from django.contrib import admin
from .models import Article


class ArticleAdminForm(forms.ModelForm):
    class Meta:
        model = Article
        fields = '__all__'

    def clean_title(self):
        title = self.cleaned_data['title']
        if '垃圾' in title:
            raise forms.ValidationError('标题不允许包含敏感词')
        return title


@admin.register(Article)
class ArticleAdmin(admin.ModelAdmin):
    form = ArticleAdminForm
```

如果只是想批量改某类字段的控件，不用写整个表单，用 `formfield_overrides`：

```python
@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    formfield_overrides = {
        models.TextField: {'widget': forms.Textarea(attrs={'rows': 20, 'cols': 80})},
    }
```

这会让所有 TextField 在后台编辑页变成 20 行高的大文本框。

## 站点定制：标题、页脚、登录页

整个后台站点是一个 `AdminSite` 单例（`django.contrib.admin.site`）。它的几个属性改完，所有页面的文字都会变：

> 通用示例（非项目代码）：放在项目的某个 `admin.py`（如 `ll_project/admin.py`）或 `urls.py` 顶部

```python
from django.contrib import admin

admin.site.site_header = '我的网站管理后台'   # 登录页大标题、每个页面顶部
admin.site.site_title = '后台管理'            # 浏览器标签页标题
admin.site.index_title = '欢迎使用本站管理'    # 首页大标题
admin.site.site_url = '/'                    # "查看网站"按钮指向，默认 '/'
```

如果一个项目要挂两套后台（比如前台用户后台 vs 运营后台），可以自己 `AdminSite(name='ops')` 建实例，再把 URL 挂成 `path('ops/', ops_site.urls)`。

登录门槛：除了 `is_staff=True`，还可以用 `AdminSite.has_permission()` 方法做更细的拦截；默认实现就是检查 `request.user.is_active and request.user.is_staff`。

## 完整示例串起来

把前面的片段拼起来，Learning Log 的 `learning_logs/admin.py` 就是一个"全功能"模板：`@admin.register` 一个带定制的模型（Topic）、`admin.site.register(Entry, EntryAdmin)` 另一种写法、一个 TabularInline、一个计算列。

> 示例：Learning Log 的完整 learning_logs/admin.py

```python
from django.contrib import admin

from .models import Topic, Entry


class EntriesInline(admin.TabularInline):
    """Defines format of inline entry insertion (used in TopicAdmin)"""
    model = Entry


@admin.register(Topic)
class TopicAdmin(admin.ModelAdmin):
    list_display = ('text', 'owner', 'entry_count', 'date_added')
    fields = ['text', ('owner', 'date_added')]
    inlines = [EntriesInline]

    @admin.display(description='条目数', ordering='id')
    def entry_count(self, obj):
        return obj.entry_set.count()


admin.site.register(Entry, EntryAdmin)
class EntryAdmin(admin.ModelAdmin):
    list_display = ('topic', 'progress', 'date_added', 'id')
    list_filter = ('progress', 'date_added')

    fieldsets = (
        (None, {
            'fields': ('topic', 'text', 'id')
        }),
        ('状态', {
            'fields': ('progress', 'date_added')
        }),
    )
```

## 权限与安全

| 要点 | 说明 |
|---|---|
| `is_staff` | 能否进后台的总开关；超级用户自动 True，普通用户要在后台"用户"页手动勾 |
| 模型级权限 | Django 自动为每个模型生成 `add_xxx / change_xxx / delete_xxx / view_xxx` 四个权限；在组里分配即可控制谁能改哪个模型 |
| 字段级权限 | 需要第三方包（如 `django-admin-rangefilter`、`django-guardian`），原生不支持 |
| 生产部署 | `DEBUG=False`、`ALLOWED_HOSTS` 配好、`/admin/` 路径可以改成不易猜的名字（但**别把它当安全手段**，真正的防线是 HTTPS + 强密码 + `is_staff` 严控） |
| 登录失败次数 | 内置后台不做限流，建议前面挂 Nginx 限流或用 `django-axes` 这类包 |
