
## Model 是什么

Django 的 **Model 是 Python 类 ↔ 数据库表的映射**（ORM，对象关系映射）：

- 一个继承 `models.Model` 的类 = 一张数据库表；
- 一个类属性（Field 实例）= 一列；
- 一个类的实例 = 一行记录；
- 每个模型自动获得一个 `objects` 管理器（`Manager`），所有查询都从它出发。

你不需要写 SQL：定义好模型后，Django 自动建表、生成查询 API、提供后台管理界面。

```python
# app/models.py
from django.db import models
from django.contrib.auth.models import User

class Topic(models.Model):
    """A topic the user is learning about."""
    text = models.CharField(max_length=200)
    date_added = models.DateTimeField(auto_now_add=True)
    owner = models.ForeignKey(User, on_delete=models.CASCADE)
    def __str__(self):
        return self.text

class Entry(models.Model):
    """Something specific learned about a topic."""
    topic = models.ForeignKey(Topic, on_delete=models.CASCADE)
    text = models.TextField()
    date_added = models.DateTimeField(auto_now_add=True)
    class Meta:
        verbose_name_plural = 'entries'
    def __str__(self):
        return f"{self.text[:50]}..."
```

## 字段通用选项

所有 Field 都接受以下通用参数（与字段类型无关）：

| 选项 | 作用 | 典型用法 |
|---|---|---|
| `max_length` | 最大长度（`CharField` 等字符串字段必填） | `CharField(max_length=200)` |
| `null=True` | 数据库列允许 `NULL` | `DateField(null=True)` |
| `blank=True` | 表单校验允许留空 | `CharField(blank=True)` |
| `default=` | 默认值（常量或可调用对象） | `default='d'`、`default=list` |
| `unique=True` | 全表唯一约束 | `title = CharField(unique=True)` |
| `primary_key=True` | 设为主键（默认自动生成 `id`） | 自定义 UUID 主键 |
| `choices=` | 枚举取值（二元元组列表） | 见"其他常用字段"的 Entry 示例 |
| `db_index=True` | 为该列建索引 | 高频查询列 |
| `db_column='xxx'` | 指定数据库列名（默认与属性同名） | 对接老库 |
| `verbose_name='xxx'` | 人类可读名（Admin/表单显示） | 位置参数或关键字 |
| `help_text='...'` | 表单/Admin 帮助提示 | 同 `verbose_name` |
| `editable=False` | 不在表单中显示 | 自动维护字段 |
| `error_messages={}` | 覆盖默认错误信息 | 定制提示 |
| `unique_for_date='pub_date'` | 某日期范围内唯一 | 博客标题按天唯一 |
| `unique_for_year/month` | 同上，按年/月唯一 | —— |

### `null` vs `blank`

| 选项 | 数据库层面 | 表单层面 |
|---|---|---|
| `null=True` | 该列**允许 NULL** | 无影响 |
| `blank=True` | 无影响 | 表单**允许留空**，校验不报错 |

经验法则：

- 字符串字段尽量用 `blank=True`（空串 `''` 即可），不要混用 `null=True`，否则会出现"空值有两种表示"；
- 非字符串（Date、Integer、FK）可空时用 `null=True`；
- 外键"可选关联"必须 `null=True` + `on_delete=SET_NULL`。

### `auto_now` 与 `auto_now_add`

| 参数 | 写入时机 | 用途 |
|---|---|---|
| `auto_now_add=True` | 行**第一次创建**时写入，之后永不改 | 创建时间 |
| `auto_now=True` | 每次 `save()` 都刷新为当前时间 | 最后修改时间 |

二者都隐含 `editable=False`，且不需要 `default`。

## 全部 Field 类型

### 数据库类型

| 字段 | PostgreSQL 类型 | 说明 |
|---|---|---|
| `CharField(max_length=N)` | `VARCHAR(N)` | 短字符串，必须给 `max_length`；表单渲染为 `<input type="text">` |
| `TextField()` | `TEXT` | 长文本，不限长度；表单渲染为 `<textarea>` |
| `BooleanField()` | `BOOLEAN` | `True/False`；表单渲染为复选框 |
| `IntegerField()` | `INTEGER` | 整数（32 位） |
| `BigIntegerField()` | `BIGINT` | 大整数；`DEFAULT_AUTO_FIELD` 默认主键就是它 |
| `DateTimeField()` | `TIMESTAMP WITH TIME ZONE` | 日期时间；配合 `USE_TZ=True` 存 UTC |
| `DateField()` | `DATE` | 日期 |
| `DecimalField(max_digits, decimal_places)` | `NUMERIC(m, d)` | 定点小数，**金额必用**，避免浮点误差 |

> `DecimalField` 两参必填：`max_digits` 总位数、`decimal_places` 小数位。如 `DecimalField(max_digits=6, decimal_places=2)` → `NUMERIC(6,2)`，最大 9999.99。

### 基于 VARCHAR 的扩展（CharField 子类）

底层仍是 `VARCHAR`，只是叠加了一层格式校验/语义：

| 字段 | PostgreSQL 类型 | 说明 |
|---|---|---|
| `EmailField(max_length=254)` | `VARCHAR(254)` | 带邮箱格式校验 |
| `URLField(max_length=200)` | `VARCHAR(200)` | 带 URL 格式校验 |
| `SlugField(max_length=50)` | `VARCHAR(50)` | URL 友好的短标签（字母数字 `-` `_`），自带 `db_index` 倾向 |
| `FileField(upload_to='dir/')` | `VARCHAR(100)` | 文件上传；`upload_to` 是 MEDIA_ROOT 下的相对路径（可填 callable），存的是**路径字符串**而非文件内容 |

### 其他类型

> 关系字段 `ForeignKey` / `OneToOneField`、`ManyToManyField` 本质是**数据库关系**而非数据库类型，使用频率极高。其中 `ManyToManyField` 会在数据库层生成一张中间表，是最常见的高频关系，此处不再重复列出。

| 字段 | 说明 |
|---|---|
| `UUIDField(primary_key=True, default=uuid.uuid4)` | UUID 主键，分布式系统常用 |
| `JSONField()` | 存 JSON 对象（PostgreSQL 原生 JSONB，其他库序列化为文本） |
| `FloatField()` | Python float（双精度） |
| `ForeignKey` / `OneToOneField` | 一对多 / 一对一（外键列，类型取决于关联主键） |
| `SmallIntegerField` / `PositiveIntegerField` / `PositiveSmallIntegerField` | 窄整数、非负整数 |
| `TimeField()` | 纯时间 |
| `DurationField()` | 时间段（`timedelta`） |
| `ImageField(upload_to=)` | 图片（`FileField` 子类，额外校验格式、自动读写宽高） |
| `FilePathField(path=)` | 下拉选择服务器某目录下的文件 |
| `GenericIPAddressField()` | IPv4/IPv6 地址，自动校验格式 |
| `BinaryField()` | 原始二进制数据 |
| `NullBooleanField()` | 接受 NULL 的布尔（Django 3.1+ 用 `BooleanField(null=True)` 代替） |

一个综合示例：把 Learning Log 的 `Entry` 扩展成"带进度与阅读量的待办"，同时用到上面几档字段（UUID 主键、FK、`choices` 枚举、`property`、非负整数）：

```python
# app/models.py
# 在 Learning Log 的 Entry 上扩展，演示 UUID 主键、choices、property、FK 到 User
import uuid
from django.conf import settings

class Entry(models.Model):
    """Learning Log 的一条学习记录"""
    id = models.UUIDField(primary_key=True, default=uuid.uuid4)
    topic = models.ForeignKey('Topic', on_delete=models.CASCADE)
    text = models.TextField()
    date_added = models.DateTimeField(auto_now_add=True)
    owner = models.ForeignKey(
        settings.AUTH_USER_MODEL, on_delete=models.CASCADE, null=True)
    PROGRESS = [
        ('todo', 'To do'),
        ('doing', 'In progress'),
        ('done', 'Done'),
    ]
    progress = models.CharField(
        max_length=5, choices=PROGRESS, blank=True, default='todo')
    views = models.PositiveIntegerField(default=0, help_text='How many times viewed')

    @property
    def is_done(self):
        """这条学习记录是否已完成。"""
        return self.progress == 'done'
```

自定义字段：继承 `models.Field`，实现 `db_type()`、`from_db_value()`、`to_python()`、`get_prep_value()` 等钩子即可把 Python 类型映射到数据库列。日常业务极少需要，优先复用内置字段。

## 关系字段

### ForeignKey（一对多）

定义在"多"的一侧：一条 Topic 对应多条 Entry。

```python
class Entry(models.Model):
    """一个 topic 下可以有多个 entry。"""
    topic = models.ForeignKey('Topic', on_delete=models.CASCADE)
    ...
```

关键参数：

| 参数 | 说明 |
|---|---|
| 第一个位置参数 | 被关联的模型（类或字符串名；字符串可解决循环引用） |
| `on_delete=` | **必选**，删除被关联行时的行为，见下表 |
| `related_name=` | 反向访问名（默认 `<小写模型名>_set`） |
| `related_query_name=` | 反向查询名（默认 related_name 或模型名） |
| `limit_choices_to=` | Admin/表单下拉时的过滤条件（字典或 Q 对象） |
| `to_field=` | 关联到对方的哪个列（默认对方主键） |
| `db_constraint=True` | 是否在数据库层建外键约束；设 `False` 可对接无约束老库 |
| `null=True, blank=True` | 允许该外键为空 |

**on_delete 全部选项**：

| 值 | 行为 | 适用场景 |
|---|---|---|
| `CASCADE` | 级联删除：被关联行删了，本行也删 | 强从属关系（Entry 属于 Topic） |
| `PROTECT` | 保护：存在本行引用时**禁止删被关联行** | 业务上"不能删"的数据 |
| `RESTRICT` | 同 PROTECT，但在被 `PreDelete` 拦截时区别处理 | 多数保护场景用它 |
| `SET_NULL` | 被关联行删后，本行该列置 NULL（需 `null=True`） | 作者没了，书还在 |
| `SET_DEFAULT` | 置为字段的 `default` 值 | 有兜底默认状态 |
| `SET(callable)` | 调用一个函数返回值写入 | 复杂兜底逻辑 |
| `DO_NOTHING` | 什么都不做（数据库层会报错） | 一般不用 |


### OneToOneField（一对一）

用法同 ForeignKey，但加了唯一约束，表示"一条 A 对应一条 B"。典型场景：`User` ↔ `UserProfile`。

```python
class Profile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE, related_name='profile')
    avatar = models.ImageField(upload_to='avatars/')
```

反向访问与 FK 不同：不需要 `_set`，直接 `user.profile` 返回单个对象（不是管理器）。

### ManyToManyField（多对多）

```python
class Topic(models.Model):
    """一个 topic 可以有多个协作者（多对多到 User，todo 里的"协作"）。"""
    text = models.CharField(max_length=200)
    contributors = models.ManyToManyField(User, related_name='topics', blank=True)
```

关键参数：

| 参数 | 说明 |
|---|---|
| `through=` | 指定**自定义中间表**模型（默认 Django 自动建一个隐式中间表） |
| `symmetrical=` | 自关联时是否对称（`True`：A 关注 B 则 B 自动关注 A；默认 True） |
| `related_name=` | 反向访问名 |
| `limit_choices_to=` | 同 FK |

自定义中间表 `through` 适合需要在关系上存额外字段（如"借书记录：借出时间、归还时间"），此时不能用默认的 `.add()/.create()`，要手动 `ThroughModel.objects.create()`。

### 反向关系与跨关系查询

- **正向**：`entry.topic` → 拿到 Entry 所属的 Topic。
- **反向**：`topic.entry_set.all()` → 拿到该 Topic 下所有 Entry。命名规则：**小写模型名 + `_set`**，返回一个管理器（可用 `filter/order_by/all`）。
- 若 ForeignKey 设了 `related_name='entries'`，则反向写作 `topic.entries.all()`。
- **跨关系查询**用双下划线：`Topic.objects.filter(owner__username='bob')`、`Entry.objects.filter(topic__owner__username='bob')`，Django 自动 JOIN。

```python
entries = topic.entry_set.order_by('-date_added')
```

## Meta 选项

在模型里写一个 `class Meta` 内嵌类，配置模型级行为：

| 选项 | 说明 |
|---|---|
| `ordering = ['-date_added']` | 默认排序（字符串前加 `-` 表示倒序；可多列） |
| `verbose_name = 'topic'` | 单数人类可读名 |
| `verbose_name_plural = 'topics'` | 复数名（默认 Django 只会加 `s`） |
| `db_table = 'my_table'` | 指定数据库表名（默认 `<app>_<model>`） |
| `abstract = True` | 抽象基类：不建表，只被子模型继承字段 |
| `unique_together = [('a','b')]` | 联合唯一（旧写法，Django 4.0+ 推荐用 `constraints`） |
| `indexes = [models.Index(fields=['a','b'])]` | 联合索引 |
| `constraints = [models.UniqueConstraint(...)]` | 数据库约束（唯一、检查等） |
| `permissions = [('can_mark_done', 'Can mark an entry as done')]` | 自定义权限，配合 `permission_required` |
| `get_latest_by = 'pub_date'` | `latest()` 默认按哪列 |
| `managed = True` | 是否让 Django 管理建表（False 时完全手管） |
| `default_permissions = ('add','change','delete','view')` | 默认权限集 |

## `__str__` 与 `get_absolute_url`

两个约定俗成的模型方法：

- **`__str__`**：返回对象的人类可读字符串。Admin 列表、`repr()`、shell 调试都靠它。写法没有强制，但应包含最有辨识度的字段。
- **`get_absolute_url()`**：返回该对象详情页的 URL（配合 `reverse()`）。模板里 `{{ object.get_absolute_url }}` 可直接生成链接，Django 的 `CreateView` 也默认用它做跳转。

```python
class Topic(models.Model):
    text = models.CharField(max_length=200)
    date_added = models.DateTimeField(auto_now_add=True)

    def get_absolute_url(self):
        """返回该对象详情页的 URL，配合 reverse() 使用。"""
        return reverse('learning_logs:topic', args=[self.id])

    def __str__(self):
        """返回对象的人类可读字符串。"""
        return self.text
```

## 迁移（Migrations）

模型改动不会自动进数据库，必须走"生成迁移 → 应用迁移"两步。

### 常用命令

| 命令 | 作用 |
|---|---|
| `python manage.py makemigrations [app]` | 检测模型变更，生成迁移文件（在 app 的 `migrations/` 下） |
| `python manage.py migrate` | 把所有未应用的迁移真正执行到数据库 |
| `python manage.py showmigrations [app]` | 查看每个迁移文件是否已 `[X]` 应用 |
| `python manage.py sqlmigrate <app> <迁移名>` | 打印某条迁移对应的 SQL（**不执行**） |
| `python manage.py migrate <app> <迁移名>` | 回退/前进到指定迁移 |
| `python manage.py makemigrations --empty <app>` | 生成空迁移（手写数据迁移用） |

### 迁移文件结构

每个迁移是一个继承 `migrations.Migration` 的 Python 类，有两个关键属性：

- `dependencies`：依赖哪些迁移先跑（含 `('app', '0002_entry')`）；
- `operations`：本迁移做的操作列表（`CreateModel`、`AddField`、`RemoveField`、`RunPython` 等）。


```python
class Migration(migrations.Migration):

    dependencies = [
        migrations.swappable_dependency(settings.AUTH_USER_MODEL),
        ('learning_logs', '0002_entry'),
    ]

    operations = [
        migrations.AddField(
            model_name='topic',
            name='owner',
            field=models.ForeignKey(default=1, on_delete=django.db.models.deletion.CASCADE, to=settings.AUTH_USER_MODEL),
            preserve_default=False,
        ),
    ]
```

### 数据迁移（RunPython）

模型结构变更之外，还常需要"改数据"：写一个空迁移，在 `operations` 里加 `migrations.RunPython(forward_fn, reverse_fn)`，函数签名是 `(apps, schema_editor)`。用 `apps.get_model('app', 'Model')` 拿到历史版本的模型，不要直接 import 当前 models（迁移运行时模型可能已经变了）。

```python
def set_default_owner(apps, schema_editor):
    Topic = apps.get_model('learning_logs', 'Topic')
    for t in Topic.objects.filter(owner__isnull=True):
        t.owner_id = 1
        t.save()

class Migration(migrations.Migration):
    dependencies = [('learning_logs', '0003_topic_owner')]
    operations = [migrations.RunPython(set_default_owner, migrations.RunPython.noop)]
```

## QuerySet

`QuerySet` 是 ORM 的核心：链式、惰性、可缓存。所有方法从 `Model.objects` 出发。

### 创建与写入

| 方法 | 说明 |
|---|---|
| `Model.objects.create(**kwargs)` | 一步 `__init__()` + `save()` |
| `obj = Model(**kwargs); obj.save()` | 等价两步，可先改后存 |
| `Model.objects.get_or_create(**filters, defaults=...)` | 有则返回，无则创建；返回 `(obj, created_bool)` |
| `Model.objects.update_or_create(**filters, defaults=...)` | 有则更新，无则创建；返回 `(obj, created_bool)` |
| `Model.objects.bulk_create([obj1, obj2, ...])` | 批量插入（一条 SQL，不调用 `save()`） |
| `qs.update(field=value)` | 对整个 QuerySet 批量 UPDATE（不触发 `save()`/信号） |

```python
user, created = User.objects.get_or_create(username='bob', defaults={'email': 'b@x.com'})
Topic.objects.bulk_create([Topic(text=f't{i}', owner=user) for i in range(10)])
Topic.objects.filter(owner=user).update(date_added=timezone.now())
```

### 检索（读取）

| 方法 | 说明 |
|---|---|
| `.all()` | 全部对象 |
| `.filter(**lookups)` | 过滤（AND） |
| `.exclude(**lookups)` | 反向过滤（NOT） |
| `.get(**lookups)` | 取单条；找不到抛 `DoesNotExist`，多条抛 `MultipleObjectsReturned` |
| `.order_by('a', '-b')` | 排序；`?` 随机 |
| `.reverse()` | 反转排序 |
| `.distinct()` | DISTINCT 去重 |
| `.values('a', 'b')` | 返回字典列表（不返回模型实例） |
| `.values_list('a', flat=True)` | 返回元组列表；`flat=True` 单列时返回值列表 |
| `.dates('field', kind, order='asc')` | kind ∈ year/month/day；返回该列的日期列表 |
| `.datetimes(...)` | 同上，精确到 datetime |
| `.first()` / `.last()` | 取第一条/最后一条（不存在返回 None，不抛异常） |
| `.earliest('field')` / `.latest('field')` | 按指定列取最早/最新 |
| `.none()` | 空 QuerySet |
| `.exists()` | 是否存在匹配行（返回 bool，不加载数据） |
| `.count()` | 计数（走 SQL COUNT，比 `len(qs)` 高效） |
| `.delete()` | 删除整个 QuerySet |
| `qs[:10]` / `qs[5:10]` | 切片（LIMIT/OFFSET），不支持负索引 |

### 字段查找（Field Lookups）

写法：`字段名__lookup=值`。常用 lookup：

| Lookup | 含义 | 示例 |
|---|---|---|
| `exact` | 精确等于（默认） | `name__exact='Bob'` ≈ `name='Bob'` |
| `iexact` | 大小写不敏感等于 | `name__iexact='bob'` |
| `contains` | 包含子串（区分大小写） | `title__contains='Django'` |
| `icontains` | 包含（不区分大小写） | `title__icontains='django'` |
| `in` | 在列表中 | `id__in=[1,2,3]` |
| `gt / gte / lt / lte` | 大于/大于等于/小于/小于等于 | `views__gte=100` |
| `range` | 区间（含两端） | `date_added__range=(d1, d2)` |
| `startswith / endswith` | 以…开头/结尾 | `title__startswith='The'` |
| `istartswith / iendswith` | 同上，不区分大小写 | —— |
| `date` | 对 DateTime 按日期过滤 | `created_at__date=date(2026,1,1)` |
| `year / month / day / week_day` | 按年月日星期 | `created_at__year=2026` |
| `isnull=True/False` | 是否为 NULL | `owner__isnull=True` |
| `regex / iregex` | 正则匹配 | `name__regex=r'^A.*z$'` |

跨关系查找用双下划线贯通：`Topic.objects.filter(owner__username__icontains='bo')`、`Entry.objects.filter(topic__text__contains='django')`。

### 聚合

- **`aggregate()`**：对整个 QuerySet 做聚合，返回**字典**；
- **`annotate()`**：给每个对象附加一个聚合值（GROUP BY），返回新 QuerySet。

聚合函数：`Count`、`Sum`、`Avg`、`Max`、`Min`、`StdDev`、`Variance`、`ArrayAgg`（PG）等。

```python
# 通用示例：todo 逻辑——统计条数与阅读量
from django.db.models import Count, Avg

Entry.objects.all().aggregate(Count('id'), Avg('views'))
# => {'id__count': 120, 'views__avg': 15.5}

Topic.objects.annotate(num_entries=Count('entry')).filter(num_entries__gt=3)
# 每个主题带一个 num_entries 字段，只保留条目数>3 的
```

### F 表达式与 Q 对象

- **`F('字段名')`**：在数据库侧引用字段做运算，避免先把数据读进 Python。典型用法：`Entry.objects.update(views=F('views')+1)`（计数器自增）。
- **`Q(...)` 对象**：封装查询条件，支持 `&`（AND）、`|`（OR）、`~`（NOT），解决 `filter()` 只能 AND 的问题。

```python
# F 自增计数、Q 组合条件
from django.db.models import F, Q

Entry.objects.update(views=F('views') + 1)                          # 每条记录阅读量 +1（数据库侧自增）
Entry.objects.filter(Q(text__icontains='django') | Q(text__icontains='python'))
Topic.objects.filter(Q(owner__username='bob') & ~Q(text__startswith='hidden'))
```

### 惰性求值、缓存与性能

- **惰性**：`filter()`、`order_by()` 等只构造 SQL，不真正查库；直到**迭代、切片、`len()`、`list()`、`bool()`** 时才执行。
- **缓存**：同一个 QuerySet 第一次迭代后，结果缓存在 `.result_cache` 上；再次迭代不查库。切片后的新 QuerySet 不共享缓存。
- **性能技巧**：
  - `exists()` 只判断有没有；
  - `count()` 走 SQL COUNT；
  - `select_related('fk1','fk2')`：对**外键/一对一**做 JOIN，一次性把关联对象拉回（解决 N+1）；
  - `prefetch_related('m2m','fk_set')`：对**多对多/反向 FK** 做二次查询，再在 Python 层拼装；
  - `only('a','b')` / `defer('heavy')`：只取/不取某些列。

> 示例：把 Learning Log 的首页做成一个"待办统计面板"，组合使用 `count()`、`filter(...).count()`、`exclude(...)` 与 `request.session` 计数——todo 逻辑简单，能清晰看到各 API 的用途：

```python
def index(request):
    """The home page for Learning Log."""
    topics = Topic.objects.filter(owner=request.user)
    num_topics = topics.count()
    num_done = Entry.objects.filter(topic__in=topics, progress='done').count()
    num_todo = Entry.objects.filter(topic__in=topics).exclude(progress='done').count()

    num_visits = request.session.get('num_visits', 0) + 1
    request.session['num_visits'] = num_visits

    context = {
        'num_topics': num_topics,
        'num_done': num_done,
        'num_todo': num_todo,
        'num_visits': num_visits,
    }
    return render(request, 'learning_logs/index.html', context)
```
