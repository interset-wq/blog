
## 认证系统架构

Django 认证是一组内置应用与中间件协作的产物，默认 `startproject` 就已装好：

| 组件 | 作用 |
|---|---|
| `django.contrib.auth` | User / Group / Permission 模型、登录登出密码逻辑、视图与表单 |
| `django.contrib.contenttypes` | 权限按"模型"分类的基础（permission 关联 contenttype） |
| `django.contrib.sessions` | 会话存储（记录"已登录"状态） |
| `SessionMiddleware` | 从 cookie 读 session |
| `AuthenticationMiddleware` | 把 session 里的用户挂到 `request.user` |
| `django.contrib.auth.urls` | 内置一整套认证路由（login/logout/password_*） |

工作流程：用户 POST 账号密码 → `authenticate()` 校验 → `login()` 写 session → 后续请求经 `AuthenticationMiddleware` 自动把 `request.user` 填成当前用户（未登录时是 `AnonymousUser`）。

三个常用配置项（写在 settings.py）：

| 配置 | 作用 |
|---|---|
| `LOGIN_URL` | 未登录访问受保护页时跳转的登录页（默认 `/accounts/login/`） |
| `LOGIN_REDIRECT_URL` | 登录成功后默认跳转（默认 `/accounts/profile/`） |
| `LOGOUT_REDIRECT_URL` | 登出后跳转（不设置则渲染默认登出页） |

## User 模型

### 内置 User 字段

| 字段 | 说明 |
|---|---|
| `username` | 用户名（唯一，必填） |
| `password` | 哈希后的密码（**绝不存明文**） |
| `email` | 邮箱 |
| `first_name` / `last_name` | 名 / 姓 |
| `is_staff` | 是否能登录管理后台 |
| `is_active` | 是否激活（False 等同封号，但保留记录） |
| `is_superuser` | 是否超级用户（拥有全部权限） |
| `last_login` | 上次登录时间 |
| `date_joined` | 注册时间 |

### 创建用户

```python
from django.contrib.auth.models import User

User.objects.create_user('alice', email='alice@example.com', password='x12345')
User.objects.create_superuser('admin', email='admin@x.com', password='admin123')
```

> 必须用 `create_user()` 而不是 `User(...)`——前者会自动对密码做哈希。

在 shell 里也可以用 `python manage.py createsuperuser` 命令交互式创建。

## 登录与登出

### 函数式三步：authenticate / login / logout

```python
from django.contrib.auth import authenticate, login, logout

def my_view(request):
    user = authenticate(request, username=request.POST['username'],
                        password=request.POST['password'])
    if user is not None:
        login(request, user)          # 写 session，完成登录
        return redirect('home')
    else:
        return render(request, 'login.html', {'error': '用户名或密码错误'})

def logout_view(request):
    logout(request)                   # 清空 session 中的认证信息
    return redirect('login')
```

`authenticate()` 只校验身份、不改变状态；`login()` 才把"已登录"写进会话。模板里用 `request.user.is_authenticated`（布尔）判断当前是否登录。

### 内置登录视图：LoginView / LogoutView

Django 提供通用类视图，直接挂路由即可，无需自己写登录视图：

```python
# urls.py
from django.contrib.auth.views import LoginView, LogoutView

urlpatterns = [
    path('login/', LoginView.as_view(), name='login'),
    path('logout/', LogoutView.as_view(), name='logout'),
]
```

`LoginView` 默认渲染模板 `registration/login.html`，并把表单传成 `{{ form }}`；登录成功后跳 `LOGIN_REDIRECT_URL`。

更省事的做法是直接 include 内置全套路由：

```python
app_name = 'accounts'
urlpatterns = [
    # Include default auth urls.
    path('', include('django.contrib.auth.urls')),
    # Registration page.
    path('register/', views.register, name='register'),
]
```

`include('django.contrib.auth.urls')` 一次提供：`login/`、`logout/`、`password_change/`、`password_change/done/`、`password_reset/`、`password_reset/done/`、`reset/<uidb64>/<token>/`、`reset/done/`。

### 登录模板与 `next` 参数

`@login_required` 把未登录用户重定向到登录页时，会把原目标地址作为 `?next=/原路径/` 附加在 URL 后面。登录成功后应跳回 `next`，而不是固定首页。

```html
{% if next %}
  {% if user.is_authenticated %}
  <p>Your account doesn't have access to this page. To proceed,
  please login with an account that has access.</p>
  {% else %}
  <p>Please login to see this page.</p>
  {% endif %}
{% endif %}

<form method="post" action="{% url 'login' %}">
{% csrf_token %}
<table>
<tr>
  <td>{{ form.username.label_tag }}</td>
  <td>{{ form.username }}</td>
</tr>
<tr>
  <td>{{ form.password.label_tag }}</td>
  <td>{{ form.password }}</td>
</tr>
</table>

<input type="submit" value="login">
<input type="hidden" name="next" value="{{ next }}">
</form>

<p><a href="{% url 'password_reset' %}">Lost password?</a></p>
```

> **登出要用 POST**：Django 2.1+ 的 LogoutView 只接受 POST（GET 会 405），因为登出会销毁服务端会话，属于状态变更，不能被爬虫 / 预加载触发。模板里登出必须写成小表单。

## 限制访问：`@login_required` 与 `LoginRequiredMixin`

### 函数视图：装饰器

```python
from django.contrib.auth.decorators import login_required

@login_required
def topics(request):
    ...
```

未登录访问 → 302 重定向到 `LOGIN_URL?next=当前路径`；登录后自动跳回。

### 类视图：Mixin

```python
from django.contrib.auth.mixins import LoginRequiredMixin
from django.views import generic

class TopicListView(LoginRequiredMixin, generic.ListView):
    model = Topic
```

> **Mixin 必须写在通用视图左边**（继承顺序：`LoginRequiredMixin, generic.ListView`）。


```python
from django.contrib.auth.mixins import LoginRequiredMixin

class MyTopicsListView(LoginRequiredMixin, generic.ListView):
    """Generic class-based view listing topics owned by current user."""
    model = Topic
    template_name = 'learning_logs/my_topics.html'
    paginate_by = 10

    def get_queryset(self):
        return (
            Topic.objects.filter(owner=self.request.user)
            .order_by('-date_added')
        )
```

## 注册：`UserCreationForm`

Django 内置注册表单 `UserCreationForm`（用户名 + 两次密码，自动跑密码强度校验）。经典模式是：GET 出空白表单 → POST 校验 → `save()` 创建用户 → 立即 `login()` → 跳转。

> 示例：Learning Log 的注册视图（accounts/views.py）。

```python
from django.shortcuts import render, redirect
from django.contrib.auth import login
from django.contrib.auth.forms import UserCreationForm


def register(request):
    """Register a new user."""
    if request.method != 'POST':
        # Display blank registration form.
        form = UserCreationForm()
    else:
        # Process completed form.
        form = UserCreationForm(data=request.POST)

        if form.is_valid():
            new_user = form.save()
            # Log the user in and then redirect to home page.
            login(request, new_user)
            return redirect('learning_logs:index')

    # Display a blank or invalid form.
    context = {'form': form}
    return render(request, 'registration/register.html', context)
```

要点：

- `form.save()` 创建 User，密码自动哈希。
- 注册成功后立刻 `login(request, new_user)`，用户无需再登一次。
- 要加邮箱等字段，可继承 `UserCreationForm` 扩展，或改用自定义用户模型（见“自定义用户模型”）。

## 密码管理

### 哈希机制

Django 用 PBKDF2（默认）把密码哈希后存库，每次哈希带随机 salt。**永远不要**自己读 `user.password` 字段去比对。正确做法：

| 方法 | 作用 |
|---|---|
| `user.set_password(raw_password)` | 设置新密码（自动哈希），需 `.save()` |
| `user.check_password(raw_password)` | 校验明文密码是否正确，返回布尔 |
| `django.contrib.auth.hashers.make_password(pw)` | 仅生成哈希串 |

```python
u = User.objects.get(username='alice')
u.set_password('new-pass-123')
u.save()
u.check_password('new-pass-123')   # True
```

### 改密码：`PasswordChangeView`

和登录一样，内置类视图 + 模板三件套（`password_change.html` / `password_change_done.html`）即可，无需自己写表单。路由已由 `include('django.contrib.auth.urls')` 提供。

### 忘记密码：邮件重置四步流程

Django 提供完整的"忘记密码"邮件流程，四个视图串成一条链：

| 步骤 | 视图 | 模板 | 做什么 |
|---|---|---|---|
| 1 | `PasswordResetView` | `password_reset_form.html` | 用户填邮箱 |
| 2 | （发邮件） | `password_reset_email.html` | 生成带 token 的重置链接并发送 |
| 3 | `PasswordResetConfirmView` | `password_reset_confirm.html` | 用户点链接后设新密码 |
| 4 | `PasswordResetCompleteView` | `password_reset_done.html` / `password_reset_complete.html` | 提示完成 |

开发阶段把邮件打印到控制台而不真发：

```python
# settings.py
EMAIL_BACKEND = 'django.core.mail.backends.console.EmailBackend'
```

> 示例：重置邮件模板（templates/registration/password_reset_email.html），用 `{% url %}` 拼出带 uidb64/token 的确认链接。

```html
Someone asked for password reset for email {{ email }}. Follow the link below:
{{ protocol}}://{{ domain }}{% url 'password_reset_confirm' uidb64=uid token=token %}
```

## 权限系统：Permission / Group

登录只解决身份，权限解决"能做什么"。

### 权限模型

每个模型默认自动生成三条权限：`add_<模型>`、`change_<模型>`、`delete_<模型>`，在 admin 里可直接分配。自定义权限写在模型的 `Meta` 里：

> 示例：Learning Log 的 Entry 模型，声明了一条业务权限 `can_mark_done`。

```python
class Entry(models.Model):
    # ... 字段略 ...

    class Meta:
        ordering = ['-date_added']
        permissions = (("can_mark_done", "Can mark an entry as done"),)
```

权限在代码里的全名是 `<app_label>.<codename>`，例如 `learning_logs.can_mark_done`、`learning_logs.add_entry`。

### 视图层强制权限

**函数视图**用 `@permission_required` 装饰器：

```python
from django.contrib.auth.decorators import login_required, permission_required

@login_required
@permission_required('learning_logs.can_mark_done', raise_exception=True)
def mark_entry_done(request, pk):
    ...
```

`raise_exception=True` 时无权限直接 403；不加则先跳登录页。

**类视图**用 `PermissionRequiredMixin`：

> 示例：Learning Log 的主题创建视图，类视图要求 `learning_logs.add_topic` 权限。

```python
from django.contrib.auth.mixins import PermissionRequiredMixin

class TopicCreate(PermissionRequiredMixin, CreateView):
    model = Topic
    fields = ['text']
    permission_required = 'learning_logs.add_topic'
```

### 模板层按权限显隐

`{{ perms }}` 由 auth context processor 注入，是当前用户权限的字典式对象。模板里按权限决定是否显示入口：

```html
{% if perms.learning_logs.can_mark_done %}
  <a href="{% url 'learning_logs:mark_done' entry.id %}">Mark done</a>
{% endif %}
```

> 最佳实践：**视图层强制 + 模板层隐藏**双保险。模板隐藏只是用户体验，真正挡请求的是视图层。

### 代码里判断权限

| 方法 | 含义 |
|---|---|
| `user.has_perm('learning_logs.add_topic')` | 是否有某条权限 |
| `user.has_module_perms('learning_logs')` | 是否对某 app 拥有任意权限 |
| `user.is_superuser` | 超级用户拥有一切 |

### Group 分组

`Group` 是权限的容器：把"学习管理员"组勾上 `can_mark_done` 等权限，再把用户加进组，用户自动继承组内所有权限。组在 admin 后台的 Groups 页面管理，避免逐个用户勾选权限。

## 资源归属：用户只能看自己的数据

多用户应用的常见需求是"数据归属于创建者"。通用做法三步：

1. 创建时绑定 `owner`：
   ```python
   form = TopicForm(data=request.POST)
   if form.is_valid():
       new_topic = form.save(commit=False)
       new_topic.owner = request.user     # 归属当前登录用户
       new_topic.save()
   ```
2. 查询时只取自己的：
   ```python
   topics = Topic.objects.filter(owner=request.user).order_by('date_added')
   ```
3. 访问单条时校验归属，否则 404：
   ```python
   topic = Topic.objects.get(id=topic_id)
   if topic.owner != request.user:
       raise Http404
   ```

CBV 里等价做法是重写 `get_queryset()` 过滤 `owner=request.user`。这与 Django 权限体系正交——权限是"角色能做什么操作"，归属是"这条数据属于谁"。

## 自定义用户模型

内置 User 字段不够用时（比如想加手机号、头像），应**自定义 User 模型**。两条路线：

| 路线 | 继承 | 适用 |
|---|---|---|
| 推荐：扩展 AbstractUser | `AbstractUser` | 只想加字段，保留默认用户体系 |
| 完全自定义：AbstractBaseUser + PermissionsMixin | `AbstractBaseUser` | 想用邮箱代替用户名登录等深度定制 |

```python
# accounts/models.py
from django.contrib.auth.models import AbstractUser

class User(AbstractUser):
    bio = models.TextField(blank=True)
```

```python
# settings.py（必须在第一次 migrate 之前写好）
AUTH_USER_MODEL = 'accounts.User'
```

> **铁律**：`AUTH_USER_MODEL` 一旦执行过迁移就**几乎不能改**（所有外键都指向了旧表）。新建项目若打算自定义用户，务必在 `migrate` 之前就配置好。

## 认证后端：ModelBackend 简述

Django 的认证是**可插拔**的：`AUTHENTICATION_BACKENDS` 配置一组后端，`authenticate()` 依次询问每个后端，谁返回 User 就算谁成功。默认后端是 `ModelBackend`——查 User 表、校验密码哈希。

常见扩展：LDAP 后端、OAuth 后端（如 django-allauth）、JWT 后端（DRF 场景）。自定义后端只需写一个类，实现 `authenticate(request, **credentials)` 与 `get_user(user_id)`，注册到 settings 即可。

## 知识地图

```
认证（你是谁）
├── 注册 register（UserCreationForm + login）
├── 登录 login（authenticate → login；内置 LoginView）
├── 登出 logout（POST 请求；内置 LogoutView）
└── 密码管理（set_password / PasswordChangeView / PasswordResetView 四步）

授权（你能做什么）
├── 权限 Permission（Meta.permissions 定义 codename）
├── 函数视图 @login_required / @permission_required
├── 类视图  LoginRequiredMixin / PermissionRequiredMixin
├── 模板    {{ perms }}、{% if perms.app.codename %}
└── 分组    Group（批量分配权限）

数据归属（你的数据）
├── 创建时绑定 owner
├── 查询时 filter(owner=request.user)
└── 访问时校验归属
```
