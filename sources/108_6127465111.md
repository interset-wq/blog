
MySQL 是最流行的关系型数据库管理系统之一，与 PostgreSQL 同为 SQL 数据库，**绝大多数 SQL 语法通用**。本文以 PostgreSQL 为参照讲 MySQL，重点标注两者差异。

## 一、登录

```bash
$ mysql -u root -p          # 用户名 + 密码
$ mysql -u freecodecamp -p mydb   # 指定用户名、数据库
Enter password:
Welcome to the MySQL monitor.  Commands end with ; or \g.
mysql>
```

与 PostgreSQL 对照：`psql --username=xxx --dbname=xxx` ↔ `mysql -u xxx -p`。

## 二、mysql 命令速查

MySQL 客户端没有 `\l` 这类反斜杠命令，改用 **SQL 语句**：

| 操作 | MySQL | PostgreSQL |
|---|---|---|
| 列出数据库 | `SHOW DATABASES;` | `\l` |
| 连接数据库 | `USE <db>;` | `\c <db>` |
| 列出所有表 | `SHOW TABLES;` | `\d` |
| 查看表详情 | `DESCRIBE <table>;`（或 `DESC`） | `\d <table>` |
| 查看建表语句 | `SHOW CREATE TABLE <table>;` | `\d <table>` |

> 提示符：`mysql>` 就绪；`->` 命令未输完换行。**SQL 语句以分号 `;` 结束**，`\g` 也可作为结束符。

## 三、数据库操作

与 PostgreSQL 基本一致：

```sql
mysql> CREATE DATABASE <db>;                    -- 创建
mysql> CREATE DATABASE <db> CHARACTER SET utf8mb4;  -- 指定字符集（推荐中文场景）
mysql> DROP DATABASE <db>;                      -- 删除
mysql> ALTER DATABASE <db> CHARACTER SET utf8mb4;   -- 改字符集
```

> [!IMPORTANT]
> MySQL 建库/建表建议显式指定 `utf8mb4` 字符集，才能完整支持中文与 emoji。

## 四、表操作

### 4.1 创建表

MySQL 建表语法与 PostgreSQL 相同，差异在**自增列**写法：

```sql
CREATE TABLE students (
  student_id INT AUTO_INCREMENT PRIMARY KEY,   -- 自增：AUTO_INCREMENT
  first_name VARCHAR(50) NOT NULL,
  gpa DECIMAL(3,2)
);
```

- 自增用 `AUTO_INCREMENT`（PostgreSQL 用 `SERIAL`）
- **`AUTO_INCREMENT` 列必须是整数类型，且通常是主键**

### 4.2 常用数据类型

| 类型 | 说明 | 与 PostgreSQL 对照 |
|---|---|---|
| `INT` | 整数 | 同 `INT` |
| `VARCHAR(n)` | 字符串，n 为字符数 | 同 `VARCHAR(n)` |
| `TEXT` | 长文本 | 类似 PG 的 `TEXT` |
| `DECIMAL(p,s)` | 小数 | 同 PG `NUMERIC(p,s)` |
| `DATE` | 日期 | 同 |
| `DATETIME` | 日期时间 | PG 用 `TIMESTAMP` |
| `TIMESTAMP` | 时间戳，可自动更新 | — |
| `BOOLEAN` | 布尔 | **MySQL 无原生布尔**，实为 `TINYINT(1)`（1=TRUE、0=FALSE） |

### 4.3 约束

约束与 PostgreSQL 相同：

```sql
CREATE TABLE orders (
  order_id INT AUTO_INCREMENT PRIMARY KEY,
  customer_id INT NOT NULL,
  total DECIMAL(8,2) DEFAULT 0,
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

| 约束 | 说明 |
|---|---|
| `PRIMARY KEY` | 主键 |
| `FOREIGN KEY ... REFERENCES` | 外键 |
| `NOT NULL` | 非空 |
| `UNIQUE` | 唯一 |
| `DEFAULT` | 默认值 |

> MySQL 表默认使用 **InnoDB** 引擎才支持外键、事务。建表时可用 `ENGINE=InnoDB` 显式指定。

### 4.4 修改表结构

与 PostgreSQL 一致：

```sql
ALTER TABLE <t> ADD COLUMN <col> <DATATYPE>;            -- 加列
ALTER TABLE <t> DROP COLUMN <col>;                      -- 删列
ALTER TABLE <t> RENAME COLUMN <old> TO <new>;           -- 重命名列
ALTER TABLE <t> ADD PRIMARY KEY(<cols>);                -- 加主键
ALTER TABLE <t> ADD FOREIGN KEY(<col>) REFERENCES <t2>(<col>);  -- 加外键
ALTER TABLE <t> ADD UNIQUE(<col>);                      -- 加唯一约束
```

## 五、增删改查

CRUD 语法与 PostgreSQL **完全通用**：

```sql
-- 插入
INSERT INTO students(first_name, gpa) VALUES('Naomi', 3.9);

-- 删除
DELETE FROM students WHERE student_id = 3;

-- 更新
UPDATE students SET gpa = 4.0 WHERE student_id = 1;

-- 查询
SELECT * FROM students WHERE gpa >= 3.0 ORDER BY gpa DESC LIMIT 10;
```

## 六、查询差异点

大部分查询语法与 PostgreSQL 相同（`WHERE`、`ORDER BY`、`LIMIT`、聚合、`GROUP BY`+`HAVING`、JOIN），差异如下：

| 功能 | PostgreSQL | MySQL |
|---|---|---|
| 忽略大小写匹配 | `ILIKE` | `LIKE`（默认字符集下大小写不敏感） |
| 字符串拼接 | `a \|\| b` | `CONCAT(a, b)` |
| 取当前时间 | `NOW()` | `NOW()` / `CURDATE()` / `CURTIME()` |
| 取整/四舍五入 | `CEIL`/`FLOOR`/`ROUND` | 同 |

## 七、事务（Transaction）

事务把一组 SQL 操作打包为**要么全部成功、要么全部回滚**的原子单元，保证数据一致性。

### 7.1 事务的 ACID 特性

| 特性 | 含义 |
|---|---|
| 原子性（Atomicity） | 事务内操作要么全做、要么全不做 |
| 一致性（Consistency） | 事务前后数据始终满足约束 |
| 隔离性（Isolation） | 并发事务互不干扰 |
| 持久性（Durability） | 提交后数据永久保存 |

> [!IMPORTANT]
> MySQL 只有 **InnoDB** 引擎支持事务；MyISAM 不支持。需确认表引擎为 InnoDB。

### 7.2 事务语法

```sql
START TRANSACTION;            -- 开始事务（也可用 BEGIN）

UPDATE accounts SET balance = balance - 100 WHERE account_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE account_id = 2;

COMMIT;                       -- 提交：确认全部生效
-- ROLLBACK;                  -- 回滚：撤销本次事务所有改动
```

典型转账场景：若第二条 UPDATE 失败，执行 `ROLLBACK` 可让第一条也撤销，避免余额出错。

### 7.3 事务控制命令

| 命令 | 作用 |
|---|---|
| `START TRANSACTION` / `BEGIN` | 开启事务 |
| `COMMIT` | 提交事务，持久化所有修改 |
| `ROLLBACK` | 回滚事务，撤销所有修改 |
| `SAVEPOINT <name>` | 设置保存点，可部分回滚 |
| `ROLLBACK TO <name>` | 回滚到某保存点 |

### 7.4 隔离级别

隔离级别控制并发事务的可见性，级别越高越安全但并发越低：

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| `READ UNCOMMITTED` | 可能 | 可能 | 可能 |
| `READ COMMITTED` | 不会 | 可能 | 可能 |
| `REPEATABLE READ`（默认） | 不会 | 不会 | 可能 |
| `SERIALIZABLE` | 不会 | 不会 | 不会 |

```sql
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;   -- 设置当前事务隔离级别
SELECT @@transaction_isolation;                     -- 查看当前隔离级别
```

> [!NOTE]
> MySQL 默认隔离级别是 `REPEATABLE READ`（可重复读），PostgreSQL 默认是 `READ COMMITTED`。

## 八、索引（Index）

索引加速查询，代价是占用存储、拖慢写入（每次 INSERT/UPDATE 都要维护索引）。

### 8.1 索引类型

| 类型 | 说明 |
|---|---|
| 普通索引 `INDEX` | 加速查询，允许重复值 |
| 唯一索引 `UNIQUE INDEX` | 索引列值唯一（等效 UNIQUE 约束） |
| 主键索引 `PRIMARY KEY` | 主键自动创建 |
| 全文索引 `FULLTEXT` | 全文检索 |
| 复合索引 | 多列组合的索引，遵循最左前缀 |

### 8.2 创建索引

```sql
-- 建表时创建
CREATE TABLE students (
  student_id INT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(100),
  INDEX idx_email (email),            -- 普通索引
  UNIQUE INDEX uq_email (email)       -- 唯一索引
);

-- 表已存在时创建
CREATE INDEX idx_gpa ON students(gpa);
CREATE UNIQUE INDEX uq_email ON students(email);
ALTER TABLE students ADD INDEX idx_name (last_name, first_name);  -- 复合索引
```

### 8.3 查看与删除索引

```sql
SHOW INDEX FROM students;             -- 查看表的索引
DROP INDEX idx_gpa ON students;       -- 删除索引
```

### 8.4 用 EXPLAIN 分析查询

`EXPLAIN` 查看查询是否走索引（`key` 字段显示命中的索引，`NULL` 表示全表扫描）：

```sql
EXPLAIN SELECT * FROM students WHERE email = 'a@b.com';
```

> [!WARNING]
> 索引不是越多越好：优先给 `WHERE`、`JOIN`、`ORDER BY` 中频繁出现的列建索引；复合索引遵循**最左前缀**原则（`(a,b,c)` 索引可命中 `a`、`a,b`、`a,b,c`，但单独用 `b` 或 `c` 不会命中）。

## 九、MySQL vs PostgreSQL 差异总览

| 维度 | PostgreSQL | MySQL |
|---|---|---|
| 登录 | `psql --username=u --dbname=d` | `mysql -u u -p` |
| 列出数据库 | `\l` | `SHOW DATABASES;` |
| 连接数据库 | `\c db` | `USE db;` |
| 列出表 | `\d` | `SHOW TABLES;` |
| 表详情 | `\d table` | `DESCRIBE table;` |
| 自增列 | `SERIAL` | `AUTO_INCREMENT`（需整数） |
| 布尔类型 | `BOOLEAN` | `TINYINT(1)` |
| 忽略大小写匹配 | `ILIKE` | `LIKE`（默认不敏感） |
| 字符串拼接 | `\|\|` | `CONCAT()` |
| 时间类型 | `TIMESTAMP` | `DATETIME` / `TIMESTAMP` |
| 默认隔离级别 | `READ COMMITTED` | `REPEATABLE READ` |
| 导出备份 | `pg_dump` | `mysqldump` |
| 重建 | `psql < file.sql` | `mysql < file.sql` |

## 十、导出与重建

| 操作 | 命令 |
|---|---|
| 导出数据库 | `mysqldump -u root -p db_name > db_name.sql` |
| 用 SQL 重建 | `mysql -u root -p < db_name.sql` |

> `mysqldump` 对应 PostgreSQL 的 `pg_dump`；导入同样用重定向 `<`。

## 核心总结

1. **登录**：`mysql -u <user> -p`；客户端命令改用 SQL：`SHOW DATABASES`、`USE`、`SHOW TABLES`、`DESCRIBE`。
2. **自增列**：`AUTO_INCREMENT`（须整数且多为主键），PostgreSQL 用 `SERIAL`。
3. **数据类型**：与 PG 大体相同；`BOOLEAN` 实为 `TINYINT(1)`；中文建库建表指定 `utf8mb4`。
4. **约束与 CRUD**：`PRIMARY KEY`、`FOREIGN KEY`、`NOT NULL`、`UNIQUE`；INSERT/DELETE/UPDATE/SELECT 与 PG 通用。
5. **查询差异**：字符串拼接用 `CONCAT()`、无 `ILIKE`（`LIKE` 默认大小写不敏感）。
6. **事务**：InnoDB 才支持；`START TRANSACTION`/`COMMIT`/`ROLLBACK`，默认隔离级别 `REPEATABLE READ`。
7. **索引**：`CREATE [UNIQUE] INDEX`、`SHOW INDEX`、`DROP INDEX`；用 `EXPLAIN` 判断是否走索引，遵循最左前缀。
8. **导出重建**：`mysqldump` 导出、`mysql < file.sql` 重建。
