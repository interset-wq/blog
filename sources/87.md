

# Jinja2 学习笔记

## Jinja2 是什么，和 DTL 什么关系

Jinja2 是一个**独立于 Web 框架的通用模板引擎**：`{{ }}` 输出变量、`{% %}` 写逻辑、`{# #}` 注释。它比 DTL 更接近 Python：支持 `{% set %}` 赋值、`is` 测试、过滤器用函数调用式传参、`macro` 宏，模板继承里用 `{{ super() }}` 调用父块。

| 维度 | DTL（Django 模板语言） | Jinja2 |
|---|---|---|
| 归属 | Django 内置 | 独立第三方包（Flask / Ansible 等通用） |
| 定位 | 与 context_processors、`{% url %}`、Admin 深度耦合 | 纯渲染库，Django 能力要手动接入 |
| 表达力 | 简单但弱 | 略多但强 |
| 在 Django 里 | 默认启用 | 需额外配置后端 |

## 在 Django 里配置 Jinja2 后端

Django 的 `TEMPLATES` 是个**列表**，可以挂多个后端。默认 DTL 后端之外，再追加一个 Jinja2 后端：

```python
# 通用示例（非项目代码）
# uv add jinja2
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',  # 默认 DTL
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
    {
        'BACKEND': 'django.template.backends.jinja2.Jinja2',           # 新增 Jinja2 后端
        'DIRS': [BASE_DIR / 'jinja2'],
        'APP_DIRS': True,
        'OPTIONS': {
            'environment': 'project.jinja2.environment',            # 自定义 Environment 工厂
            'context_processors': [                                     # 注意：独立于 DTL 那份
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
            ],
        },
    },
]
```

- **模板查找目录不同**：DTL 在 `<app>/templates/` 下找；Jinja2 后端的 `app_dirname` 是 `jinja2`，即 `APP_DIRS=True` 时找 `<app>/jinja2/`。两个后端的目录不要混。
- **默认 environment 就是裸 `jinja2.Environment`**：不会自动注入 `url()` / `static()`；要在自定义工厂里加（见“自定义 Environment：把 Django 能力接进来”）。
- **`render(request, ...)` 时自动注入** `request`、`csrf_input`、`csrf_token` 三个上下文变量，并依次执行 `OPTIONS['context_processors']`——所以 `{{ user }}`、`{{ perms }}` 能用，前提是你在**这个 Jinja2 后端块里**也列了 auth processor（它不会从 DTL 那块继承）。
- `autoescape=True` 默认开启，与 DTL 一样自动转义 HTML；`DEBUG=True` 时用 `DebugUndefined`，访问未定义变量会在页面上直接报错。

### 自定义 Environment：把 Django 能力接进来

```python
# 通用示例（非项目代码）：project/jinja2.py
from django.templatetags.static import static
from django.urls import reverse
from jinja2 import Environment


def environment(**options):
    env = Environment(**options)
    env.globals.update({
        'url': reverse,        # 模板里写 {{ url('learning_logs:index') }}
        'static': static,      # 模板里写 {{ static('css/x.css') }}
    })
    return env
```

视图里显式指定用哪个后端：

```python
# 通用示例（非项目代码）
from django.shortcuts import render

def jinja_demo(request):
    return render(request, 'hello.html', {'name': 'Django'}, using='jinja2')
```

> `render()` 不带 `using` 时按后端顺序找第一个能匹配模板名的引擎。模板文件重名时，务必用 `using=` 显式指定，避免 DTL / Jinja2 互相串台。

## 语法基础

### 变量与属性访问

```jinja
{{ user.username }}
{{ topic.entry_set.all() }}     {# 可以直接调方法（带括号） #}
{{ items.0 }}                    {# 列表下标 #}
{{ topic['title'] }}             {# 字典 / 下标 #}
```

Jinja2 的 `.` 解析顺序：先属性 → 再字典键 → 再列表下标，比 DTL 宽松，且允许 `()` 调用。

### 控制流

```jinja
{% if user.is_authenticated %}
  Hello, {{ user.username }}
{% elif user %}
  访客
{% else %}
  请登录
{% endif %}

{% for topic in topics %}
  <li>{{ loop.index }}. {{ topic.title }}</li>   {# loop.index 从 1 开始 #}
{% else %}
  <p>还没有主题。</p>                               {# for 为空时走 else #}
{% endfor %}
```

### 赋值：set 与 with

```jinja
{% set total = topics|length %}        {# 全局赋值，后面都能用 #}
{{ total }}

{% with description = topic.text|truncate(30) %}
  <p>{{ description }}</p>             {# with 块内局部变量 #}
{% endwith %}
```

> DTL 没有 `{% set %}`

### 过滤器：函数调用式传参

```jinja
{{ text|truncate(20) }}
{{ d|date('Y-m-d') }}
{{ value|default('无数据') }}
{{ names|join('、') }}
{{ html|safe }}                  {# 关掉这段的自动转义 #}
{{ text|striptags|truncate(50) }} {# 链式 #}
```

> 与 DTL 的区别：DTL 用冒号 `{{ d|date:"Y-m-d" }}` 传一个参数；Jinja2 用括号 `{{ d|date('Y-m-d') }}`，可传多参、可加关键字参数。

### 测试：is

```jinja
{% if value is defined %} ... {% endif %}
{% if value is none %} ... {% endif %}
{% if items is iterable %} ... {% endif %}
{% if n is number %} ... {% endif %}
{% if loop.index is odd %} ... {% endif %}
```

### loop 变量

| 变量 | 含义 |
|---|---|
| `loop.index` | 当前序号，从 1 开始（≈ DTL `forloop.counter`） |
| `loop.index0` | 从 0 开始（≈ `forloop.counter0`） |
| `loop.revindex` | 倒数，到 1 结束（≈ `forloop.revcounter`） |
| `loop.first` / `loop.last` | 是否第一个 / 最后一个（≈ `forloop.first/last`） |
| `loop.length` | 总长 |
| `loop.cycle('odd', 'even')` | 轮流取值 |

## 模板组织：extends / block / include / macro

### 继承与 block

```jinja
{# base.html（基模板） #}
<!doctype html>
<html><body>
  {% block sidebar %}默认侧栏{% endblock %}
  {% block content %}{% endblock %}
</body></html>
```

```jinja
{# child.html（子模板） #}
{% extends "base.html" %}

{% block content %}
  <h1>{{ topic.title }}</h1>
{% endblock %}

{% block sidebar %}
  {{ super() }}          {# 调用父块内容，再追加 —— 注意是函数调用！ #}
  <li>额外链接</li>
{% endblock %}
```

> **关键差异**：Jinja2 里保留父块内容写 `{{ super() }}`（带括号、是函数）；DTL 里写 `{{ block.super }}`（属性、无括号）。语义相同，写法不同——这是迁移时最常见的手误。


```django
  <main class="container">
    <div class="pb-2 mb-2 border-bottom">
      {% block page_header %}{% endblock page_header %}
    </div>

    <div>
      {% block content %}{% endblock content %}
    </div>
  </main>
```

```django
{% extends 'learning_logs/base.html' %}

{% block page_header %}
  <div class="p-3 mb-4 bg-light border rounded-3">
    <h1 class="display-3">Track your learning.</h1>
    <a class="btn btn-primary btn-lg mt-1"
        href="{% url 'accounts:register' %}">Register &raquo;</a>
  </div>
{% endblock page_header %}
```

同一段逻辑翻成 Jinja2 就是：

```jinja
{% extends "base.html" %}
{% block page_header %}
  <h1 class="display-3">Track your learning.</h1>
  <a class="btn btn-primary" href="{{ url('accounts:register') }}">Register »</a>
{% endblock %}
```

区别一目了然：`{% url 'x' %}` 标签 → `{{ url('x') }}` 全局函数；`{% endblock page_header %}` → Jinja2 可简写 `{% endblock %}`。

### include

```jinja
{% include 'partial.html' %}                    {# 引入另一个模板 #}
{% include 'partial.html' with x=1 y=2 %}      {# 传额外变量 #}
```

### macro 宏：模板里的函数

```jinja
{# 定义宏 #}
{% macro render_topic(t) %}
  <li><a href="{{ url('topic_detail', t.id) }}">{{ t.title }}</a></li>
{% endmacro %}

{# 使用宏 #}
<ul>
  {% for t in topics %}
    {{ render_topic(t) }}
  {% endfor %}
</ul>
```

宏可以拆到独立文件里再 `import`：

```jinja
{% from 'macros.html' import render_topic, render_entry %}
{{ render_topic(t) }}
```

> DTL 没有 macro——复杂复用片段只能 `{% include %}` 拼字典；Jinja2 的 macro 是"模板级函数"，带参数、可递归，是 Jinja2 相对 DTL 的另一大优势。

## 与 Django 集成的几个接线点

| Django 能力 | 在 Jinja2 模板里怎么用 |
|---|---|
| URL 反解 | `{{ url('app:name', arg) }}`（在 2.1 的 environment 里注入 `reverse`） |
| 静态文件 | `{{ static('css/x.css') }}`（注入 `staticfiles_storage.url`） |
| CSRF | 表单里直接写 `{{ csrf_input }}`（Django 后端自动注入），输出整个 hidden input |
| 当前用户 / 权限 | `{{ user }}`、`{{ perms }}`——前提是 OPTIONS 里加了 `auth` context processor |
| 请求对象 | `{{ request.path }}`——render 带 request 时后端会自动注入 `request` 变量 |
| 消息框架 | `{{ messages }}`——加 `messages` processor |


```django
<form action="{% url 'accounts:logout' %}" method='post'>
  {% csrf_token %}
  <button name='submit'>Log out</button>
</form>
```

等价的 Jinja2 写法：

```jinja
<form action="{{ url('accounts:logout') }}" method="post">
  {{ csrf_input }}
  <button name="submit">Log out</button>
</form>
```

> Jinja2 后端没有 `{% csrf_token %}` 标签；但 `{{ csrf_input }}` 直接输出 `<input type="hidden" name="csrfmiddlewaretoken" ...>`，比手写更省事。

## 自定义过滤器 / 全局函数 / 测试

都在自定义 Environment 工厂里注册：

```python
# project/jinja2.py
from django.utils import timezone
from jinja2 import Environment


def environment(**options):
    env = Environment(**options)

    @env.filter
    def zh_date(value):                       # 自定义过滤器：{{ d|zh_date }}
        return timezone.localtime(value).strftime('%Y年%m月%d日')

    @env.global
    def site_name():                          # 全局函数：{{ site_name() }}
        return '我的站点'

    @env.test
    def rich(text):                           # 测试：{% if text is rich %}
        return len(text) > 100

    return env
```

> 对比 DTL：DTL 要写 `templatetags/*.py` 装饰 `@register.filter`，再在模板里 `{% load xxx %}`；Jinja2 直接是普通 Python 函数挂到 env 上，没有 `{% load %}` 这一步。

## DTL vs Jinja2 总对照表

| 功能 | DTL | Jinja2 |
|---|---|---|
| 输出变量 | `{{ obj.attr }}` | `{{ obj.attr }}`（也可 `obj.method()`） |
| 过滤器传参 | `{{ d\|date:"Y-m-d" }}` 冒号 | `{{ d\|date('Y-m-d') }}` 括号 |
| 默认转义 | 自动转义 | 自动转义（autoescape=True） |
| 标记安全 HTML | `{{ html\|safe }}` | `{{ html\|safe }}`（相同） |
| 赋值 | 无 | `{% set x = ... %}` |
| 局部作用域 | 无 | `{% with %}{% endwith %}` |
| 类型 / 状态判断 | 无 | `is defined` / `is none` / `is iterable` |
| 循环序号 | `forloop.counter` | `loop.index` |
| 父块内容 | `{{ block.super }}` | `{{ super() }}` |
| URL 反解 | `{% url 'x' arg %}` 标签 | `{{ url('x', arg) }}` 函数 |
| 静态文件 | `{% load static %}{% static 'x' %}` | `{{ static('x') }}` |
| CSRF | `{% csrf_token %}` | `{{ csrf_input }}` |
| 复用片段 | `{% include %}` | `{% include %}` + **`{% macro %}` + `import`** |
| 自定义标签 | `templatetags/` + `{% load %}` | env.filters / env.globals 直接注册 |
| context_processors | 自动注入 | 需在该后端 OPTIONS 里独立列出 |
| 性能 | 一般 | 预编译，通常更快 |

## 常用过滤器速查

| 过滤器 | 作用 | 示例 |
|---|---|---|
| `default('…')` | 空值默认 | `{{ x\|default('无') }}` |
| `length` | 长度 | `{{ list\|length }}` |
| `join('、')` | 拼接 | `{{ tags\|join('、') }}` |
| `truncate(n)` | 截断 n 字符 | `{{ t\|truncate(20) }}` |
| `truncatewords(n)` | 截断 n 词 | `{{ t\|truncatewords(10) }}` |
| `striptags` | 去 HTML 标签 | `{{ h\|striptags }}` |
| `upper` / `lower` / `title` | 大小写转换 | `{{ s\|upper }}` |
| `date('Y-m-d')` | 日期格式化 | `{{ d\|date('Y-m-d') }}` |
| `round(2)` | 四舍五入 | `{{ n\|round(2) }}` |
| `first` / `last` | 首 / 尾元素 | `{{ list\|last }}` |
| `escape` / `safe` | 转义 / 不转义 | `{{ html\|safe }}` |
| `replace('a', 'b')` | 字符串替换 | `{{ s\|replace(' ', '_') }}` |

常用标签 / 语句：`if / elif / else`、`for … else`、`set`、`with`、`extends`、`block`、`include`、`import`、`from … import`、`macro`、`filter`（块级过滤器）、`raw`（块内不转义）。

## Nunjucks

Jinja2 的语法不只属于 Python——**Mozilla** 把同一套模板语法移植到了 JavaScript，就是 **Nunjucks**。会 Jinja2 就能直接上手 Nunjucks，它主要用于 Node.js 服务端渲染与前端构建（Express、gulp、webpack 等）。

Nunjucks 是 Mozilla 开发的 JS 模板引擎，**语法直接继承自 Jinja2**：`{{ }}`、`{% %}`、`{# #}`、`|filter()`、`{% set %}`、`extends/block`、`is` 测试一脉相承。文档：<https://mozilla.github.io/nunjucks/>

### 安装（pnpm）与最简用法

```powershell
pnpm install nunjucks          # Node 环境；浏览器端可直接引用 nunjucks.min.js
```

```javascript
const nunjucks = require('nunjucks')
nunjucks.configure({ autoescape: true })        // 全局配置（防 XSS）
const html = nunjucks.renderString(
  'Hello {{ name }}！共 {{ list|length }} 条。',
  { name: 'Nunjucks', list: ['a', 'b'] }
)
// Hello Nunjucks！共 2 条。
```

搭配 Express：

```javascript
const express = require('express')
const nunjucks = require('nunjucks')
const app = express()
nunjucks.configure('views', { autoescape: true, express: app })  // 模板目录 views/
app.get('/', (req, res) => res.render('index.html', { user: req.user }))
```

### 语法与 Jinja2 几乎一致

```jinja
{{ user.username }}
{{ text|truncate(20) }}
{% set total = items|length %}
{% for item in items %}
  <li>{{ loop.index }}. {{ item }}</li>
{% endfor %}
{% extends 'base.html' %}
{% block content %}{{ super() }}{% endblock %}
```

### Nunjucks 相对 Jinja2 的独特点

| 特性 | 说明 |
|---|---|
| **宏 `macro`** | 定义可复用"模板函数"，前端模板里最常用 |
| 异步支持 | `{% asyncEach %}` / async 过滤器，处理异步数据 |
| 自定义扩展 | `addExtension()` / `addFilter()` / `addGlobal()` |
| 浏览器直用 | 不依赖 Node，可直接在页面引用渲染 |
| 构建集成 | 有 webpack loader（`nunjucks-loader`）、gulp 插件 |

宏示例（模板里的函数）：

```jinja
{% macro card(entry) %}
  <div class="card"><h4>{{ entry.title }}</h4><p>{{ entry.text }}</p></div>
{% endmacro %}

{% for e in entries %}
  {{ card(e) }}
{% endfor %}
```
